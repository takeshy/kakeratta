kakeratta の使い方

思いついたこと、目に留まったものを、テキスト・画像・URL・音声でひとつのタイムラインへ放り込む。担当分野ごとに別々の記憶を持つ AI（担当）が、言うことがあるときだけ反応します。このページはその使い方をひと通りまとめたものです。

1. はじめる

  1. アプリを開きます。Google ログインが有効な環境では、最初にログインします。あなたのデータはあなたのアカウントにだけ結びつきます。
  2. 右上の 設定 を開き、Nebius Token Factory の API キーを入力します。接続確認 を押して「接続できました」と出れば準備完了です。モデルは既定のまま（Lightning / Super / Ultra）で構いません。
  3. 画面の上に「担当が誰もいません」と出ていたら、「〇〇 を呼ぶ」 で 1 人以上呼びます。誰もいないと、放り込んだかけらは誰にも渡りません。
  4. 欄に一言書いて 流す。これが最初のかけらです。

API キーはサーバー側にだけ保存され、設定した接続先以外へは送られません。キーは Nebius Token Factory で発行します。

2. かけらを放り込む

思いついたことは書くのが早く、画面に出ているものは撮るのが早い。どれも同じひとつの欄から入ります。

入り口やり方
書く欄に書いて 流す。Ctrl（⌘）+Enter でも送れます。
貼る・選ぶスクリーンショットを Ctrl+V で貼る、または 📷 画像 でファイルを選びます。画像の文字は担当が読み取り、あとから検索できます。
URLURL を書いて流すと、公開ページの本文を取りに行きます。
話す🎙 話す で音声入力。設定した「送信の合図」を言うと、そのまま投稿されます。

一言とあわせて画像を付けることもできます。投稿には「今どこで何時か」だけが添えられます。目的地や時刻は文面に書けば、担当が読み取ります。位置情報は任意で、無くても成立します。

3. タイムラインと反応

  • 最新 20 件から表示し、下へスクロールすると 20 件ずつ追加されます。
  • 担当の発言や自分の返信は 返信 N件 の下に折りたたまれます。押すと開きます。表示中に担当の発言が届いたときは、そのスレッドが自動で開きます。
  • 一言足す でその投稿に続けて書けます。担当の発言には 返す で返事ができます。
  • 反応は遅れて届きます。反応が付かないこともあります。 担当は喋らずに覚えるだけのこともあるからです。
  • 必ず答えがほしいときは @tabe のように @名前 で指名します。担当の名前の並び（担当バー）を押すと、@名前 が書き込まれます。
  • 投稿・返信のあと 5 分間は、取りこぼしに備えて自動でタイムラインを読み直します。
  • 🔈 読み上げ で、溜まった反応を順に読み上げます。移動中に便利です。
  • 自分の投稿・返信の ⚖（担当の判断）で、誰が呼ばれ、誰がなぜ呼ばれなかったかを見られます。詳しくは 担当の判断を見て、条件を直す。
  • 担当の発言の 返し方を直す で、期待とどう違うかを伝えて口調と指示を直せます。詳しくは 返事がずれたところで、口調と指示を直す。
  • 投稿の ✎ で編集、× で削除できます。投稿を消すと、その下の担当の発言と自分の返信も一緒に消え、担当のメモからその投稿への出典が外れます。削除した投稿は検索にも出ません。

素早い表示とオフライン投稿

直近20件の元投稿とその返信を利用者ごとにブラウザへ保存し、次回は保存済みの会話を先に表示して裏で更新します。一度オンラインで開いた端末なら、オフラインでも文章・画像・URL・返信を「送信待ち」として保存できます。未送信の投稿は20件の上限とは別に保持します。アプリを開いている間に接続と認証が戻ると自動送信します。担当の反応やURL・画像の解析は、サーバーへ届いてから始まります。

「端末に保存済み・送信待ち」は、まだサーバーに届いていない状態です。失敗した場合は「接続して再送」でやり直せます。同じ投稿IDで再送するため、通信が途切れても二重投稿を防ぎます。送信待ちはブラウザのデータ削除で失われます。ログアウト時は送信待ちがあれば確認し、この端末の保存データを削除します。

4. 会話をBlueskyに公開する

自分の投稿と担当との会話から、公開する発言だけを選べます。すべて自分のBlueskyアカウントから投稿され、担当の発言には「🍚 tabeからの返信:」のような署名が付きます。

自分のアカウントを接続する

  1. 設定 → 上級オプション → Bluesky連携、または投稿の Blueskyに投稿 を開きます。
  2. 自分のハンドル（例: alice.bsky.social）を入力し、Blueskyと接続 を押します。
  3. Blueskyの画面で接続を許可し、同じタブでkakerattaに戻ります。パスワードはBluesky側にだけ入力します。利用者ごとの開発者登録やAPIキー発行は不要です。

公開する会話を選ぶ

  1. 元の投稿の Blueskyに投稿 を押します。最初は元投稿だけが選択され、担当の返信や自分の追加返信は未選択です。
  2. 公開する発言を選びます。返信を選ぶときは、その返信先も選んでください。選ばなかった発言や、画面を開いた後で届いた返信は自動追加されません。
  3. プレビュー で本文・添付画像・返信先・投稿アカウントを確認し、選択した会話を投稿 を押します。独立した担当の返信は、それぞれ元投稿への返信になります。

本文・リンク・出典URL・添付画像が公開対象です。位置情報や画像解析結果を本文に追加したり、担当の記憶を読み出したりしません。長文は文末・改行を優先し、署名込みで300文字相当（書記素）・3,000バイト以内に自動分割します。2つ目以降は「つづき:」と署名を付けてつなぎます。一文が長すぎる場合は読点・空白、それでも収まらなければ文字の境界で分割します。URL単体が長すぎる場合はエラーになります。投稿済みの発言は再送せず、新しく選んだ返信だけを追加投稿できます。すべて投稿済みなら投稿ボタンは無効になります。投稿中は二重操作できません。公開先のリンクは会話の親投稿への1つにまとめます。画像は最初の分割投稿だけに添付します。2 MBを超える画像は送信用に縮小・JPEG圧縮し、保存済みの元画像は変更しません。透明部分は白背景、GIFは静止画になります。返信は相手の最後の分割投稿につながります。1回に100発言まで選択でき、分割結果はプレビューで確認できます。

再操作と接続解除

同じアカウントへ投稿済みの発言は再送せず、追加分を返信として続けます。通信が途切れて結果を確認できない場合は、重複防止のため再送を止めます。Bluesky上の結果を確認してください。

設定 → 上級オプション → Bluesky連携 → 接続を解除 で解除できます。接続や再接続だけでは公開されません。接続解除やkakeratta内での削除は、Blueskyの投稿を削除しません。

「Bluesky連携は準備中です」と表示される場合は、運営側の初期設定が必要です。運営側の設定と投稿履歴の復旧を参照してください。

5. 担当

担当は分野ごとに分かれた記憶を持つ AI です。投稿がどの担当に渡るかは本体が振り分け、そのうえで覚えるか、喋るかは各担当が自分で決めます。

最初からいる 4 人

名前分野受け取るもの
@tabe食事店、料理、飲み物、食事やメニューの写真、「何食べよう」
@michi移動行き先、経路、所要時間、待ち合わせ、旅程、チケット
@shiori読書電子書籍のキャプチャ、引用、書名と著者、読んだ感想
@planaやること薬、金魚の餌、洗濯、ゴミ出しのような繰り返し。「仕事帰りに花を買おう」のような一度きりの用と、したかどうか

担当は投稿された言語で答えます。ヘッダーの 担当 から一覧を開き、有効 / 停止中 を切り替えられます。

毎日のチェックインと timer

新しいかけらを投げない日も、担当が一度だけ起き、伝えることがあれば話しかけます。何もなければ黙り、空の投稿は残りません。メモの更新だけをすることもあります。

  1. 担当 を開き、対象の担当を 有効にする にします。
  2. 1日1回のチェックイン をONにします（初期状態はOFF）。
  3. 希望時刻 を選びます。変更は自動保存されます。

時刻の横に表示される端末のタイムゾーンを保存します。JST以外と夏時間にも対応し、旅行後も保存したタイムゾーンを維持します。現在はタイムゾーンの手動選択はありません。チェックインをOFFにするか、担当を無効にすると定期起床は止まります。

これとは別に、timer を持つ担当は、自分で起きる時刻を置きます（timer）。時刻を尋ねられることはありません。担当が自分の記録から見当をつけます。

たとえば plana なら、記録から「朝の薬は7時半ごろ」と分かった項目にだけ timer を置き、その少しあとに起きて、まだ記録がないときだけ「そういえば朝の薬」と一言添えます。催促や飲み忘れの指摘はしません。決まった件数の通知を約束する機能ではありません。

ブラウザを閉じても、サーバーが動いていれば実行します。毎分確認するため、希望時刻や処理の混雑によって少し遅れることがあります。設定した時刻を過ぎてONにした場合は、その日の分を次の確認で実行します。再起動時も当日分だけを実行し、過去の日の分はまとめて送りません。

沈黙や失敗もその日の1回に数えます。時刻の変更や記憶の削除で当日分を再実行することはありません。定期起床では現在地を取得しないため、経路検索は使えず、店舗検索は名前検索だけになります。

AI と担当を作る

  1. 担当 を開き、AIと担当を作る を選びます。
  2. 「どんなことの担当を作りたい？」に自分の言葉で答えます。
    例：美味しかったワインのラベルを送るので、銘柄やブドウ品種を教えてほしい。
  3. AI が名前、話し方、記憶のルールを下書きします。内容を確認して この内容で保存。
  4. 有効にする と、以後のかけらを受け取り始めます。

使いながら育てる

担当の AIで修正 から「もっと短く返事してほしい」「銘柄だけでなく、なぜ気に入ったかも覚えてほしい」のように頼めます。組み込みの担当も同じように変えられ、これまでのメモと有効・停止の状態はそのまま残ります。

覚えていることを確かめる

担当の 覚えていること を開くと、好み・ワイン・お店・本などの種類ごとに、保存済みのメモを読めます。説明や根拠、例外も保存された内容のまま表示します。表示のために新しくAIで要約することはありません。

  • 記憶を更新した投稿 のリンクで、元の投稿と会話を新しいタブに開けます。リンクはメモ保存時に自動で付き、書き直しや、読み込んだメモの統合（統合先がそのメモへリンクする、または元のメモを捨てる）でも引き継がれます。参照のために読んだだけのメモの投稿は付きません。
  • メモのタグ（担当が付けたもの）はチップで並びます。押すとそのタグのメモだけになり、すべてのメモを表示 で戻ります。
  • タイムラインの担当の発言の下にある 📝 は、その発言と一緒に書いたメモです。押すとこの画面がそのメモで開きます。
  • 関連する記憶のリンクを押すと、そのメモへ移動します。メモの見出しの ✎ を押すと、そのメモが保存された原文のまま編集欄になり、綴りや事実の誤りをその場で直せます。画像の読み取りが銘柄を読み違えたまま覚えたときなどに使います。「記憶を更新した投稿」のリンクは残ります。
  • 以前のメモに投稿リンクが無い場合は、元の投稿を探す で検索できます。

間違った記憶を消す・覚え方を変える

このメモを忘れさせる を押し、メモの名前を確認すると、その1件だけを削除します。ほかのメモと元の投稿は残ります。すべてのメモを忘れさせる は、その担当のメモをまとめて消す操作です。どちらも元に戻せません。担当そのものの 削除 ではメモは残ります。

メモを消しても、担当が残っている投稿を検索して再び覚えることがあります。今後の覚え方や判断を変えるには、担当画面の AIで修正 を使います。

たとえば「このワインが好き」という誤ったメモは個別削除し、「一度飲んだだけで好みと決めない」というルールは AIで修正 で伝えます。担当の修正は、すでに保存されたメモを自動で訂正する操作ではありません。

担当の判断を見て、条件を直す

誰にかけらを渡すかは本体が決めています。自分の投稿・返信の ⚖（担当の判断）を押すと、呼ばれた担当と、呼ばれなかった担当ごとの一行の理由が別の画面に並びます。@名前 で指名した担当は出ません。指名で届いたのはあなたの判断だからです。判定できなかった投稿は「判断の記録がありません」と出ます。呼ばれた担当には、一手が終わったか、返事をしたか、この投稿からメモを残したかが出ます。終わる前は「返事を考えています」です。黙っていたなら 返事がほしかった から、口調と指示を直す流れに入れます。

  1. 行の 呼んでほしかった（または 呼んでほしくなかった）を押します。
  2. 理由や、どう変えてほしいかを自分の言葉で書き、条件を作る を押します。担当を作る AI が担当条件だけを書き直します。
  3. 新しい判定条件 は文章のまま表示され、手で直せます。AIに変更を依頼 を押すと別の欄が開き、直してほしい内容を新たに書いて、欄の条件を書き直させられます。
  4. OK で条件を保存し、続けて同じ投稿で振り分けを試します。担当は起こしません。狙いどおりに届けば閉じます。
  5. まだ違っていれば、届かなかった理由とともにそのことを伝え、理由の入力からやり直します。保存した条件はそのまま残ります。キャンセル は何もしません。

変わるのは担当条件だけです。口調や覚え方は変わりません。裏で何かを学習することもなく、条件は保存前にいつも目で確かめられます。

返事がずれたところで、口調と指示を直す

担当の発言の 返し方を直す を押すと、その返事が期待とどう違うかを書けます。担当を作る AI が 口調 と 指示 だけを書き直し、担当条件や名前、道具は変えません。

  1. 発言の 返し方を直す を押し、期待とどう違うかを書いて 直し方を作る を押します。
  2. 新しい口調 と 新しい指示 は文章のまま表示され、手で直せます。AIに変更を依頼 で直してほしい内容を新たに書くこともできます。
  3. OK で保存し、続けて同じ投稿に同じ担当をもう一度立たせます。メモを読むところまでは本番どおりで、発言はタイムラインに載らず、メモも予定も書かれません。
  4. いま返すならこう、という文章が出ます。これでよい で閉じ、まだ違う ならその文章を引用して、どう違うかをもう一度聞きます。

担当の一手は計画と確認を経るので、試し書きには数分かかることがあります。保存した口調と指示は、試し書きの結果がどうでもそのまま残ります。

上級者向けに、skill.json を書いて 担当を追加する ことも、この画面からできます。

6. 検索

「あのとき飲んだワイン、何だった？」 ヘッダーの 検索 を開きます。

  • 「ピノ」のような名前をそのまま入力できます。
  • 「軽くて飲みやすかった赤ワイン」のような記憶も同じ欄に入力できます。単語や短い語句はキーワード検索、「？」「教えて」「探して」などを含む質問や文章は意味検索します。
  • キーワード検索後は、0件でも「似たような単語でも探す」で範囲を広げられます。自動判定が合わない場合も、結果から検索方法を切り替えられます。

対象は、自分が書いた本文、画像から読み取った文字、担当との会話です。結果を押すと、元の投稿とその会話が開きます。

投稿・返信を保存した後と画像解析が完了した後に、意味検索用の登録をバックグラウンドで行います。画像内の文字・説明・出典も対象です。「サザエ」「さざえ」のようなひらがな・カタカナの違いは、語句一致でも吸収します。

意味検索の準備に時間がかかる場合や接続できない場合は、語句の一致だけで探した結果と、その旨を表示します。あとでもう一度検索できます。途中まで保存された準備は再利用します。

担当も、必要なときに過去のかけらを検索します。新しいラベルが届いたとき、ワイン担当が「前に気に入ったピノに近いですね」と元の投稿へのリンク付きで答えることがあります。

7. スマホから共有する

Kindle も有料記事も SNS も、画面に出ていればスクリーンショットで放り込めます。PC は貼るだけ（Ctrl+V）。スマホは次の準備で共有シートから渡せます。

Android

  1. ブラウザのメニューから ホーム画面に追加（アプリとしてインストール）します。
  2. 他のアプリでスクリーンショットを共有すると、共有先に kakeratta が並びます。選ぶだけでタイムラインに入ります。

iOS

Googleログイン環境ではブラウザから画像を添付してください。以下のショートカットは認証なしのローカル環境向けです。

共有シートからの受け取りは「ショートカット」アプリで代替します。

  1. ショートカットを新規作成し、「共有シートで表示」を有効にして、受け取る種類を「イメージ」にします。
  2. 「URL の内容を取得」を追加。URL は https://<アプリのアドレス>/api/capture、メソッド POST、本文は フォーム。
    • image … ショートカットの入力
    • text … （任意）その場で書くなら「入力を要求」の結果

読書中は無言で投げておいて、あとからまとめて一言を足す使い方もできます。

8. 音声入力と読み上げ

  • 🎙 話す を押すと、ブラウザの音声認識で聞き取ります。既定では無音が続くと自動で止まります（設定の上級オプションにある「無音で自動停止」）。
  • 送信の合図（例：「以上」）を設定しておくと、そう言った時点で投稿されます。手を使わずに放り込めます。
  • 自動送信前に AI で文章を整える を ON にすると、合図で送るときだけ、意味を変えずに句読点や言いよどみを整えます。既定は OFF で、手で送るときはそのまま投稿されます。
  • 🔈 読み上げ は、溜まった反応を順に読み上げます。声と速さは設定で変えられます。

Hermes連携

「Hermesに聞く」で送った依頼を、自分のHermesが受け取り、結果をkakerattaに返します。

1. 接続キーを発行する

  1. kakerattaの「設定」→「上級オプション」→「外部連携」を開きます。
  2. 「Hermes連携」の「接続キーを発行」を押します。
  3. 表示された設定をコピーします。キーを確認できるのは発行直後だけです。

2. Hermesに設定を追加する

Hermesを動かしている端末の ~/.hermes/config.yaml に、コピーした設定を追加します。すでに mcp_servers がある場合は、その中へ kakeratta を追加してください。

mcp_servers:
  kakeratta:
    url: "画面に表示された接続URL"
    headers:
      Authorization: "Bearer 画面に表示された接続キー"

3. 依頼して確認する

  1. Hermesを再起動します。
  2. kakerattaでHermes担当をONにし、「Hermesに聞く」から依頼を送ります。
  3. 自分のHermesに「kakerattaの依頼を確認して」と話しかけます。
  4. Hermesが依頼を処理して報告すると、kakerattaで結果を確認できます。

依頼はHermesが取りに来るまで待機します。自動で対応させたい場合は、Hermes側で依頼を確認する定期実行を設定してください。HermesのAPIを公開する必要はありません。

接続できないとき

  • 設定を変更したあと、Hermesを再起動したか確認してください。
  • 接続URLにHermesからアクセスできるか確認してください。
  • キーを再発行した場合は、config.yamlも新しい設定に置き換えてください。
  • Hermes担当がOFFの場合はONにしてください。

アクセス範囲と解除

Hermesはあなたの投稿・担当のメモ・依頼を読み、Hermesのメモと報告を書き込めます。モデル設定や他のユーザーにはアクセスできません。

Hermes担当をOFFにすると読み書きを停止します。「連携を解除」を押すと接続キーが無効になります。

9. 設定

バックアップ（zipに書き出す）

zipに書き出す を押すと、ワークスペース全体を1つのzipにして渡します。投稿・担当とその記憶（メモ）・いる担当とその順番・キャプチャ画像が入ります。手元で動かすkakerattaが読むファイル構成そのままなので、KAKERATTA_HOME に展開して起動すれば同じ見え方で開きます。中の backup.json にワークスペースの鍵（workspaceKey）があります。

APIキー、BlueskyやMCPの接続は入りません。復元先では自分のキーを入れてつなぎ直します。書き出しには少し時間がかかることがあり、ホスティング版では準備ができると「ダウンロード」のリンクが出ます。リンクは1時間有効です。

利用停止（退会）

すべて削除して利用を停止する を押すと、確認のため「削除」と入力する画面が出ます。実行すると、このアカウントの投稿・担当とメモ・キャプチャ画像・設定と鍵・BlueskyやMCPの接続・バックアップ、そしてログインのアカウント自体が消え、ログアウトした状態に戻ります。元に戻せないので、必要なものは先に上のバックアップで書き出してください。ほかの利用者のデータには触れません。

手元で一人で動かしている構成（ログインなし）にはこの項目はありません。アプリを止めて、「この端末」に出る保存先のディレクトリを削除してください。

この端末（表示言語）

日本語と英語を切り替えられます。このマニュアルも同じ設定を引き継ぎます。kakerattaの版と、手元で動かしている場合は保存先もここに出ます。

上級オプション

既定のままで困らないものは、線の下の 上級オプション にまとめてあります：OpenRouterを使う、音声入力、読み上げ、MCP連携（Hermesなど）、Bluesky連携。開いたときに初めて読み込むので、使わない人の画面には出ませんし、通信も起きません。

AI（Nebius Token Factory）

KakerattaはNebius Token Factoryを通じてNVIDIA Nemotronモデルを使用します。Token FactoryのAPIキーを入れれば動きます。

  • Nemotron 3.5 Lightning — 道具を使わない軽い担当（メモと web 検索と発言だけ）
  • Nemotron Super — 振り分け、middle の担当、workflow の確認
  • Nemotron Ultra — high の担当と担当案の作成
  • GLM-5.3-Flash — 画像の読み取り（同じ基盤）
用途既定
low（先に動く。メモと web 検索と発言だけ）Nemotron 3.5 Lightning
middleNemotron Super
high（最後に動く。下の発言を見て突っ込める）Nemotron Ultra
画像を読むモデル（vision）GLM-5.3-Flash
振り分けNemotron Super
workflow の確認Nemotron Super

OpenRouterを使うでは、APIキーを入力して接続確認すると利用可能なモデルを取得し、router/high/middle/lowごとに選べます。振り分けだけをJevへ切り替えることも、OpenRouter専用モードでhigh/middle/lowを選択モデルへ切り替えることもできます。Jevは本番20件の比較で条件差分5/5、平均0.37秒、1件約0.026円でしたが、判定理由は表示しません。

担当ごとに low / middle / high を選びます。low が先に動き、その発言を見て上の段が突っ込めます。どのモデルをどの段に置くかが、そのまま体験の差になります。

web 検索以外の道具（経路、店探し、予定など）を使う担当は middle か high です。middle 以上の担当は、まず読んだり調べたりしてから、やること（メモ・予定・発言）を workflow として出し、本体が確認してから実行します。low の担当は workflow を使わず、メモと web 検索と発言だけで軽く動きます。

道具：担当が調べたり覚えたりする方法

どこで動く？道具を実行するのはkakerattaのサーバーです。公開版ではホスト先のサーバー、手元で起動した場合は手元のGoサーバーから呼び出します。ブラウザが外部の検索APIを直接呼ぶことはありません。位置情報を許可するとブラウザからサーバーへ座標が送られ、店舗・経路検索時は検索語や座標が外部サービスへ送られます。メモ操作はサーバーの保存先を使い、担当が読むメモや検索結果は設定したAIモデルへの入力にも含まれます。

道具は、担当が返答や記憶の更新に必要だと判断したときに使います。チャットにツール名やJSONを入力する必要はありません。普段の言葉で頼んでください。@名前 は返答を求める操作で、特定のツールの実行を保証するものではありません。

Web・店舗・経路検索は、担当画面の 道具 に名前がある担当が使えます。追加したい場合は AIで修正 で「Web検索も使って調べて」のように頼み、変更案を確認して保存します。過去のかけら検索と自分の記憶の操作は、すべての担当が使えます。

道具の接続先を用意するのは運用者です。店舗・経路検索の接続先は、サーバーを動かす人が環境変数で設定し、利用者全員で共有します。利用者が自分で入れるのはWeb検索（Tavily）のAPIキーだけです。使える道具の名前は担当画面の 道具 に出ます。運用者はさらに MCP サーバーを追加でき、その道具は サーバー名.道具名（例: geo.compute_commute）として担当に宣言できます。

道具できること必要な設定
web_searchWeb上の情報を検索担当への追加、TavilyのAPIキー

route車・徒歩・自転車の道路経路と所要時間担当への追加、投稿の位置情報。接続先は運用者の設定（既定は公開サービス）
timeline_search保存したかけらをキーワード・意味で検索担当への追加や検索専用のAPIキーは不要
notes_list / notes_read / notes_write / notes_forget担当自身の記憶を一覧・読み取り・保存・削除追加設定不要

Web検索 — web_search

用途：ニュースや技術情報など、Web上の情報を検索し、検索結果のリンクを返答の出典に付けられます。

設定：設定 → Web検索 にTavilyのAPIキーを保存します。AIモデルのAPIキーとは別です。Web検索を使用しない場合は空欄のままで構いません。

依頼例：「@shiori この本の著者についてWebで調べて」

制限：検索結果の説明を使う道具で、リンク先の全文を必ず読めるわけではありません。最新情報や網羅性は保証しません。定期チェックインでも利用できます。

店舗・場所検索 — place_search

用途：投稿に位置情報があれば周辺を検索し、店舗名、距離、地図に登録された営業時間などを返します。位置情報がなければ場所の名前で検索します。

設定：周辺を探すには、投稿時にブラウザの位置情報利用を許可してください。地名検索（Nominatim）と周辺検索（Overpass）の接続先は運用者が環境変数で決めます。既定はAPIキー不要の公開サービスです。

依頼例：位置情報付きで「@tabe この近くのラーメン屋を探して」。位置が分からないときは「@michi 渋谷駅という場所を探して」。

制限：地図に載っていない店舗は見つからず、営業時間の登録がない場合もあります。現在営業中か、空席があるかは分かりません。周辺検索は一時的な障害で再試行することがありますが、混雑で取得できない場合もあります。取得失敗は「店がない」という意味ではありません。定期起床では現在地を取得しないため、名前検索だけになります。

経路検索 — route

用途：投稿の位置から目的地まで、車・徒歩・自転車の道路上の距離と所要時間の目安を調べます。

設定：投稿時に位置情報を許可します。車・徒歩・自転車ごとのOSRMの接続先は運用者が環境変数で決めます。既定は鍵不要の公開サービスです。

依頼例：「@michi ここから渋谷駅まで徒歩で何分？」

制限：電車・バスなどの公共交通、時刻表、リアルタイムの渋滞は含みません。位置情報なしでは使えず、定期チェックインでも使えません。本文に出発地を書くだけでは、投稿に位置情報を付けたことにはなりません。

過去のかけら検索 — timeline_search

用途：このユーザーが保存した投稿、画像から読み取った文字、返信を語句の一致と意味の近さを合わせて検索します。開始と終了の日時で期間を絞ることもでき、期間だけを指定すればその間の記録を語句なしでまとめて読めます。担当のメモとは別に、過去の記録を振り返る道具です。

設定：すべての担当で利用でき、Web検索サービスのAPIキーは不要です。自分で検索するときはヘッダーの 検索 を開きます。

依頼例：「@tabe 前に飲んで気に入った、軽い赤ワインを探して」

制限：保存していない出来事は検索できません。一度に返るのは最大30件の抜粋で、意味が近い結果が必ず正解とは限りません。検索結果は担当の発言に自動では添えられず、担当が根拠として申告した投稿だけが発言の下にリンクとして付きます。初回の意味検索は準備に時間がかかることがあります。定期チェックインでも利用できます。

自分の記憶を扱う — notes系

用途：notes_list で記憶の一覧を確認し、notes_read で必要なメモを読み、notes_write で1件を保存・更新し、notes_forget で1件を削除します。担当同士でメモは共有しません。

設定：全担当が使え、追加設定は不要です。

依頼例：「@tabe 辛いものは好きだけど、ごまが強い味は苦手。覚えておいて」

制限：何を記憶するかは担当が判断します。黙って記憶だけ更新する場合もあります。保存内容の確認や確実な削除は、担当画面の 覚えていること から行ってください。定期チェックインでも読み書きできます。

自分で起きる時刻を預ける — schedule

用途：担当が自分を起こす時刻を本体に預けます。カレンダーや目覚まし時計ではなく、担当が自分の担当分野の用のために使うものです。plana は、繰り返しの記録や「仕事帰りに」のような言葉から、いつごろかを読み取って預けます。声をかけるのはその時刻のあとで、済んでいれば黙ります。

設定：担当に schedule を追加します。外部サービスもAPIキーも要りません。担当ごとに20件まで、30日以内、1回きりか毎日です。

依頼例：預けるのは担当自身です。あなたから時刻を指定する道具ではありません（「毎朝8時に知らせて」のような使い方は想定していません）。

制限：発火前に実行権を保存するため、沈黙や失敗でも同じ回は繰り返しません。10分以上遅れたものは鳴らさずに捨てます。メモを消すと担当が起きて予定を見直します。記憶を全部消したとき、担当を停止・削除したときは予定も消えます（メモは残ります）。預けた予定は担当パネルのカードに一覧で出ますが、画面からは消せません（消すのは担当自身です）。

公開サービスの利用条件

APIキー不要でも、無制限に利用できるわけではありません。OpenStreetMapのデータはODbLで、著作権・ライセンスの表示が必要です。ソフトウェアのライセンスとは別に、各APIの利用条件が適用されます。

公開Nominatimの利用条件は、アプリ全体で最大1リクエスト/秒、アプリの識別、帰属表示などを要求します。定期アクセスは強く非推奨で、定期処理にはキャッシュやさらに低い頻度の条件があります。現状の地名検索にはキャッシュがないため、定期便での利用や公開運用の拡大では、条件に合う自前・契約サービスへの切り替えを検討してください。開発者・運営者自身が条件を理解し、採用を判断する必要があります。

公開経路サービスにも頻度・負荷・帰属表示の条件があります。現在の頻度制限はサーバープロセス単位で、複数プロセスを合算した制御はありません。現在の出典リンクだけで必要な帰属表示をすべて満たすかも、運用前の確認・対応が必要です。Web検索にはTavilyの契約条件が適用されます。

この端末

音声入力の方式・言語・無音停止・送信の合図、読み上げの声と速さ。これらは端末ごとの設定です。

kakeratta Manual

Put thoughts and things that catch your eye into one timeline as text, images, URLs, or speech. AIs with separate memories for their own subjects, called personas, react when they have something to say. This page walks through how to use it.

1. Getting started

  1. Open the app. Where Google sign-in is enabled, sign in first. Your data is tied to your account only.
  2. Open Settings in the header and enter your Nebius Token Factory API key. Press Check connection; “Connected” means you are ready. The default models (Lightning / Super / Ultra) are fine.
  3. If the screen says “Nobody is in the room”, call in at least one persona with Call in …. With nobody in the room, a fragment reaches no one.
  4. Write a line in the box and press Post. That is your first fragment.

The API key is stored only on the server and sent only to the configured endpoint. Keys are issued at Nebius Token Factory.

2. Tossing in a fragment

A thought is fastest written; something on screen is fastest shot. Everything goes through the same single box.

Way inHow
WriteType and press Post, or Ctrl (⌘) + Enter.
Paste or pickPaste a screenshot with Ctrl+V, or choose a file with 📷 Image. Text in the image is read and becomes searchable later.
URLPost a URL and the body of the public page is fetched.
Speak🎙 Speak starts voice input. Say your configured send phrase and the text is posted.

An image can go with a line of text. Only where you are and what time it is travel with a post. Destinations and times belong in what you write; the persona reads them from the text. Location is optional.

3. Timeline and reactions

  • The newest 20 posts show first; 20 more load as you scroll.
  • Persona remarks and your replies fold under N replies. Tap to open. A remark that arrives while the timeline is showing opens its thread by itself.
  • Add a comment continues your own post. Reply answers a persona.
  • Reactions arrive later. Some posts get no reaction. A persona can remember something without speaking.
  • For a guaranteed answer, mention a persona with @name, such as @tabe. Tapping a name in the persona bar writes the mention for you.
  • For five minutes after you post or reply, the timeline is re-read automatically in case a reaction was missed.
  • 🔈 Read aloud reads the collected reactions in order. Handy while moving.
  • ⚖ (the router's call) on your own posts and replies shows who was called and why the others were not. See See the router's call and fix a condition.
  • Change how it replies on a persona's remark lets you say how it missed and corrects its tone and instructions. See Fix the tone and instructions where a reply went wrong.
  • ✎ edits a post and × removes it. Removing a post removes the remarks and your replies under it too, and the personas' notes lose their links to it. Deleted posts never appear in search.

Fast startup and offline posts

The browser saves the latest 20 original posts and their replies per user, displays them immediately on the next visit, and refreshes in the background. After opening the app online once, you can save text, images, URLs, and replies while offline. Unsent posts are kept separately from the 20-post limit. They send automatically when connectivity and authentication return while the app is open. Persona reactions and URL/image analysis start after the server receives the post.

“Saved on this device · waiting to send” means the server has not received the post yet. Use “Reconnect and retry” after an error. Retries reuse the same post ID to prevent duplicates after a lost response. Clearing browser data removes unsent posts. Signing out clears this device’s saved data and asks for confirmation if posts are still waiting to send.

4. Share a conversation to Bluesky

Select the messages you want to publish from a conversation with your personas. They all appear on your own Bluesky account. Persona messages carry an attribution such as “🍚 tabeからの返信:” (reply from tabe).

Connect your own account

  1. Open Settings → Advanced options → Bluesky connection, or choose Share to Bluesky on a post.
  2. Enter your handle (for example, alice.bsky.social) and press Connect Bluesky.
  3. Authorize the connection on Bluesky and return to kakeratta in the same tab. Enter your password only on Bluesky. Users do not need a developer account or an API key.

Choose the messages to publish

  1. Press Share to Bluesky on the original post. Only that post is initially selected; persona replies and your follow-ups start unchecked.
  2. Select the messages to share. Include the parent of each selected reply. Unchecked messages and replies that arrive after you open the dialog are never added automatically.
  3. Press Preview to check the text, images, reply structure, and account, then Publish selected conversation. Independent persona replies stay attached to the original post.

Sharing includes the selected text, links, source URLs, and images. It does not add location or image analysis to the text or read persona notes. Long messages split at sentence endings or line breaks into posts of up to 300 graphemes and 3,000 UTF-8 bytes including attribution. Later parts begin with “つづき:” (continued) and repeat persona attribution. Oversized sentences split at commas or spaces, then at grapheme boundaries if necessary. Individually oversized URLs raise an error. Already published messages are not sent again. Newly selected replies can be added to their existing parent posts. Publishing is disabled while sending or when all selected messages are already posted. A single link opens the root post of the published conversation. Images appear only on the first part. Images over 2 MB are resized and compressed as JPEG for sharing; saved originals remain unchanged. Transparency becomes white and GIFs become still images. Replies attach to the final part of their parent message. Select up to 100 messages and review the resulting parts in the preview.

Retrying and disconnecting

Messages already published to the same account are reused as parents for new replies. If a connection breaks and the outcome is uncertain, publishing stops to avoid duplicates. Check the result on Bluesky.

Use Settings → Advanced options → Bluesky connection → Disconnect to remove the connection. Connecting or reconnecting never publishes anything. Disconnecting or deleting a post in kakeratta does not delete posts on Bluesky.

If the panel says Bluesky sharing is not available yet, the operator needs to complete setup. See operator setup and publication recovery.

5. Personas

A persona is an AI with its own memory for one subject. The app routes each post to the relevant personas; each one then decides what to remember and whether to speak.

The four that ship with the app

NameSubjectWhat it receives
@tabefoodPlaces, dishes, drinks, photos of meals and menus, “what should I eat”
@michitravelDestinations, routes, travel time, meeting times, itineraries, tickets
@shiorireadingE-book captures, quoted passages, titles and authors, thoughts on a read
@planafollow-upsMedicine, feeding the goldfish, laundry, the bins - and one-offs like buying flowers on the way home, and whether they happened

A persona answers in the language the post was written in. Open Personas in the header to see them all and switch each between Active and Paused.

Daily check-ins and timers

Even without a new fragment, a persona can wake once a day and speak when it has something worth sharing. Silence leaves no empty post. It may just update its memory.

  1. Open Personas and enable the persona.
  2. Turn on Daily check-in (off by default).
  3. Choose a Preferred time. Changes save automatically.

The browser's time zone shown beside the time is saved, with support for daylight saving and zones beyond JST. It stays saved when you travel; there is currently no manual time-zone picker. Turn off the check-in or disable the persona to stop the daily wake.

Separately, a persona that has timer sets its own wake times (timer). You are never asked for a time: the persona works it out from its own records.

plana, for example, sets a timer only for a routine its notes place at a usual time, wakes shortly after it, and adds “the morning medicine, by the way” only when nothing has been recorded yet. It does not nag or point out a missed dose. This does not promise a fixed number of notifications.

The browser can be closed, but the server must be running. It checks every minute; a busy execution queue may delay a wake. Enabling it after the preferred time runs today's check-in at the next check. After a restart, only today's due wake runs, without replaying missed days.

Silent and failed attempts count as the day's wake. Changing the time or forgetting memory does not trigger a second attempt that day. Check-ins do not acquire your current location: routes are unavailable and place search is by name only.

Create a persona with AI

  1. Open Personas and choose Create a persona with AI.
  2. Answer “What would you like your persona to help with?” in your own words.
    Example: When I send a photo of a wine label I liked, tell me the wine and its grape varieties.
  3. AI drafts a name, tone, and memory rules. Review it and select Save this persona.
  4. Enable it and it starts receiving fragments.

Make it yours as you go

Use Edit with AI on a persona to say “Give shorter replies” or “Remember why I liked a wine, as well as its name.” Built-in personas can be edited too. Their existing memories and enabled status carry over.

See what a persona remembers

Open What I remember on a persona to read its saved notes grouped into preferences, wines, shops, books, and other types. Descriptions, evidence, and exceptions stay as written. Viewing memory does not generate another AI summary.

  • Posts behind this memory opens the original post and conversation in a new tab. The app attaches these links when saving notes and retains them through rewrites and consolidation - a note that links to another, or replaces one it throws away, inherits its posts. A note read merely for context passes nothing on.
  • A note's tags (the persona's own) appear as chips; tap one to see only the notes carrying it, and Show all notes to go back.
  • The 📝 chips under a persona's remark on the timeline are the notes it wrote with that remark; tap one to open this view at that note.
  • Related-memory links take you to those notes. The ✎ on a note's heading turns that note into an editor of the text as saved, to fix a misspelling or a wrong fact in place - a wine misread off its label, say. The links under “Posts behind this memory” stay.
  • For older notes without saved post links, Find original post opens search.

Remove a mistaken memory or change how a persona remembers

Select Forget this note and confirm its name to delete only that note. Other notes and original posts remain. Forget all notes erases all notes for that persona. Neither action can be undone. Deleting the persona itself keeps its memory.

A persona may remember something again by searching the remaining posts. To change its future memory or judgment rules, use Edit with AI in the Personas panel.

For example, delete an incorrect “Likes this wine” note individually, then use Edit with AI to say “Do not infer a preference from trying a wine once.” Editing a persona does not automatically correct its existing notes.

See the router's call and fix a condition

The app decides who gets each fragment. Tap ⚖ (the router's call) on one of your posts or replies to open, apart from the timeline, which personas were called and, for each one that was not, the router's one-line reason. A persona you mentioned with @name is not listed: reaching it was your call. A post the router could not judge reads as “No record of the router's call”. For each persona that was called you see whether its turn has finished, whether it replied, and whether it kept a note from this post (“still working on it” until it finishes). A reply was wanted opens the reply dialog for a silence.

  1. Tap Should have been called (or Should not have been called) on a row.
  2. Say why, or what should change, in your own words and tap Write the condition. The AI that builds personas rewrites the condition, and only the condition.
  3. New condition is shown as text you can edit by hand. Ask the AI to change it opens another box: write a fresh request and the AI rewrites what is in the condition box.
  4. OK saves the condition and then has the router try the same post again. Nobody is woken. If the post lands as you meant, the dialog closes.
  5. If it still does not, you are told - with the router's reason - and asked again from the start. What was saved stays saved. Cancel changes nothing.

Only the condition changes; tone and memory rules stay. Nothing is learned in the background, and the condition is always in front of you before it is saved.

Fix the tone and instructions where a reply went wrong

Tap Change how it replies on a persona's remark to say how that reply missed. The AI that builds personas rewrites the tone and the instructions, and only those; the condition, name and tools stay.

  1. Tap Change how it replies on a remark, say how it missed, and tap Write the fix.
  2. New tone and New instructions are shown as text you can edit. Ask the AI to change it takes a fresh request.
  3. OK saves them and then has the persona take the same turn again on the same post. It reads its notes as it would, but no remark lands on the timeline and no note or schedule is written.
  4. The reply it would now give is shown. That's it closes; Still not it quotes that reply and asks again how it misses.

A persona's turn is planned and reviewed, so the trial can take a few minutes. What was saved stays saved whatever the trial says.

Advanced users can also add a persona from a hand-written skill.json in the same panel.

6. Search

“What was that wine I liked?” Open Search in the header.

  • Enter a name you remember, like “Pinot”.
  • Or describe it in the same field, like “a light red wine that was easy to drink”. Short terms use keyword search; questions and sentences use meaning search.
  • After keyword search, “Search similar meanings too” broadens the search, even with zero results. You can switch methods from the results if the automatic choice does not fit.

Search covers what you wrote, text read from your photos, and your conversations with personas. Tap a result to open the original post and its conversation.

Search embeddings are registered in the background after posts and replies are saved and after image analysis completes, including OCR text, descriptions, and source hints. Word matching also handles hiragana/katakana variants such as “サザエ” and “さざえ”.

If meaning search is still preparing or cannot connect, search returns word matches with a notice. You can search again later; saved indexing progress is reused.

Personas search too, when it helps. When a new label arrives, a wine persona may say “This is close to the Pinot you liked before,” with a link to that post.

  2. Share a screenshot from any app and kakeratta appears in the share sheet. Pick it and the image lands in the timeline.

8. Voice input and read-aloud

  • 🎙 Speak listens with the browser’s speech recognition. By default it stops after a stretch of silence (“Stop after silence”, under Advanced options in Settings).
  • Set a send phrase (for example “done”) and the text is posted the moment you say it. Hands free.
  • Turn on Polish text with AI before auto-send and, only when a send phrase triggers posting, punctuation and hesitations are tidied without changing the meaning. It is OFF by default; manual sends keep your text as entered.
  • 🔈 Read aloud reads the collected reactions in order. Voice and speed are in Settings.

Hermes integration

Your own Hermes picks up “Ask Hermes” requests and sends its reports back to kakeratta.

1. Create a connection key

  1. Open Settings → Advanced options → Integrations.
  2. Under Hermes integration, select “Create connection key”.
  3. Copy the configuration shown. The key is shown only immediately after it is issued.

2. Configure Hermes

Add the copied configuration to ~/.hermes/config.yaml on the machine running Hermes. If mcp_servers already exists, add the kakeratta entry under it.

mcp_servers:
  kakeratta:
    url: "Connection URL shown in Settings"
    headers:
      Authorization: "Bearer CONNECTION_KEY"

3. Send a request

  1. Restart Hermes.
  2. Enable the Hermes persona in kakeratta and send a request with “Ask Hermes”.
  3. Tell your Hermes: “Check my kakeratta requests.”
  4. After Hermes processes the request and submits its report, check the result in kakeratta.

Requests wait until Hermes retrieves them. For automatic handling, configure a recurring check on the Hermes side. You do not need to expose a Hermes API.

Troubleshooting

  • Restart Hermes after changing its configuration.
  • Check that Hermes can reach the connection URL.
  • If you replaced the key, update config.yaml with the new configuration.
  • Make sure the Hermes persona is enabled.

Access and disconnection

Hermes can read your posts, persona notes and requests, and write its notes and reports. It cannot access model settings or other users.

Disable the Hermes persona to stop reads and writes. Select “Disconnect” to invalidate the key.

9. Settings

Backup (Export as zip)

Export as zip hands you the whole workspace as one zip: posts, personas with their notes, who is in the room and in what order, and captured images. It is laid out exactly as a kakeratta running on your own machine reads it, so extracting it into KAKERATTA_HOME and starting the server shows what you were looking at. The workspace key is in the backup.json inside.

No API keys and no Bluesky or MCP connections travel with it; a restored workspace asks for its own. Preparing the file can take a moment, and on the hosted version a Download link appears once it is ready. The link lasts an hour.

Close account

Delete everything and close the account asks you to type the word "delete" to confirm. It then removes this account's posts, personas and their notes, captured images, settings and keys, the Bluesky and MCP connections, any backups, and the login account itself, and leaves you signed out. There is no way back, so export a backup above first if there is anything you want to keep. Nobody else's data is touched.

A single-user setup without login has no such item: stop the app and remove the workspace directory shown under This device.

This device (display language)

Switch between Japanese and English. This manual follows the same setting. The version is here too, and the workspace path when you run kakeratta yourself.

Advanced options

Everything the defaults already answer sits below the line, under Advanced options: Use OpenRouter, voice input, read-aloud, the MCP connection (for Hermes) and the Bluesky connection. It is built the first time it is opened, so a panel you never open asks nothing and shows nothing.

In the 20-production-item comparison, Jev scored 5/5 on disputed cases, averaged 0.37 seconds, and cost about ¥0.026 per route, but it does not display decision reasons.

Each persona chooses low, middle, or high. Low runs first, and higher tiers can build on earlier responses. Which model sits in which tier is the difference in experience.

A persona that uses any tool other than web search (routes, places, schedules) is middle or high. Those personas first read and look things up, then hand in what they will do (notes, schedules, a remark) as a workflow that the app reviews before running it. A low persona has no workflow: it works with its notes, web search and a remark only.

Tools: how personas look things up and remember

Where do tools run?On the kakeratta server: the hosted server for an online deployment, or the Go server on your computer when you run it locally. The browser does not call external search APIs directly. If you allow location access, coordinates go from the browser to the server; place and route searches send search terms or coordinates to the external services. Memory tools use the server's storage, and notes and search results read by a persona also become input to the configured AI model.

A persona uses tools when it decides they are needed for a reply or memory update. Ask in ordinary language; you do not need to type tool names or JSON. Mentioning @name asks for a reply but does not guarantee a particular tool will run.

Web, place, and route search are available to personas that list them under Tools. To add one, use Edit with AI, ask for the capability, and review and save the proposed change. Every persona can search past fragments and manage its own memory.

The operator provides the tool endpoints. The place and route endpoints are set by whoever runs the server, through environment variables, and shared by every user. The only key a user enters is their own Tavily API key for web search. Available tool names appear under Tools in the Personas panel. An operator can also add MCP servers; their tools appear as server.tool (for example geo.compute_commute) and can be declared for a persona like any other tool.

Web search — web_search

Purpose: Search news, technical information, and other Web content. Links from the results can appear as sources in the reply.

Setup: Under Settings → Web search, save your Tavily API key. This is separate from your AI model API key. Leave it blank if you do not use web search.

Try: “@shiori Search the Web for this book's author.”

Limits: This tool returns search descriptions; it does not necessarily read the full linked pages. Results may not be current or comprehensive. Available during check-ins too.

Place search — place_search

Purpose: With a location on the post, search nearby places for names, distances, and opening hours recorded in the map. Without a location, look up places by name.

Setup: Allow the browser to use your location when posting to search nearby. The Nominatim (name lookup) and Overpass (nearby search) endpoints are chosen by the operator through environment variables; the defaults are public services that need no API key.

Try: With location enabled, “@tabe Find ramen near me.” Without a location, “@michi Look up Shibuya Station.”

Limits: Places missing from the map cannot be found. Opening hours may be absent and do not confirm a shop is open now or has seats. Temporary failures may be retried, but the service can still be busy or unavailable. A failed search does not mean there are no places. Check-ins do not acquire your location, so only name lookup is available then.

Route search — route

Purpose: Estimate road distance and travel time from the post's location to a destination by car, on foot, or by bicycle.

Setup: Allow location access when posting. The OSRM endpoints for driving, walking, and cycling are chosen by the operator through environment variables; the defaults are public services that need no key.

Try: “@michi How long would it take to walk from here to Shibuya Station?”

Limits: No trains, buses, timetables, or live traffic. A location on the post is required, so the tool is unavailable during check-ins. Typing a starting place in the text does not attach location coordinates to the post.

Search past fragments — timeline_search

Purpose: Search this user's saved posts, text read from images, and replies by combining words and meaning. A start and end time narrow the search to a period, and a period alone reads everything written then without any words. This looks back at records separately from the persona's memory.

Setup: Available to every persona without a Web search API key. To search yourself, open Search in the header.

Try: “@tabe Find that light red wine I enjoyed before.”

Limits: Events that were never saved cannot be found. Each call returns at most 30 excerpts. The hits are not attached to the persona's remark; only the posts it declares as its grounds are linked under it. A similar result is not necessarily the right one, and the first semantic search may take time to prepare. Available during check-ins too.

Manage personal memory — notes tools

Purpose: notes_list lists memories, notes_read reads selected notes, notes_write saves or replaces one note, and notes_forget deletes one note. Personas do not share these notes with one another.

Setup: Every persona has these tools without additional configuration.

Try: “@tabe I like spicy food, but strong sesame flavours aren't for me. Remember that.”

Limits: Each persona decides what to remember. It may update memory without speaking. To inspect saved notes or explicitly delete them, open What I remember in the Personas panel. Memory tools are available during check-ins too.

Ask the app to wake it — schedule

Purpose: A persona asks the app for the minute it wakes. This is not a calendar or an alarm clock: it is for the persona's own subject. plana works the time out of its records, or out of words like “on the way home”, and always speaks after the moment - never as a nudge beforehand.

Setup: Add schedule to the persona. No external service or API key is needed. Up to 20 pending schedules per persona, 30 days ahead, once or every day.

Try: Nothing - the persona asks for these itself. It is not a way for you to schedule a message (“tell me every morning at 8” is not what this is for).

Limits: A schedule is claimed before the model runs, so a silent or failed wake is not repeated. One more than 10 minutes late is dropped rather than replayed. Deleting a note wakes the persona to revisit the schedules that went with it; forgetting its whole memory, pausing it, or removing it drops them. Pending schedules are listed on the persona's card, but cannot be removed from there - only the persona cancels them.

Public service usage conditions

No API key does not mean unlimited use. OpenStreetMap data is licensed under ODbL and requires attribution and license information. Each API's usage conditions apply separately from the software license.

The public Nominatim policy requires an application-wide maximum of one request per second, application identification, and attribution. Periodic requests are strongly discouraged; recurring jobs have caching and stricter frequency requirements. Name lookup currently has no cache. For check-ins or a growing public deployment, consider a self-hosted or contracted service whose conditions fit your use. Developers and operators must make an informed decision about using the service.

The public routing service also has frequency, load, and attribution requirements. Current rate limiting is per server process, not aggregated across multiple processes. Existing source links also need review and possibly changes to meet all attribution requirements before deployment. Web search is subject to Tavily's contract.

This device

Voice input mode, language, silence stop, and send phrase, plus the read-aloud voice and speed. These are per-device settings.

10. FAQ

Nothing reacts to my post.
Perhaps nobody is in the room, the post matched no persona’s subject, or the persona chose to remember without speaking. Check which personas are active under Personas, and mention @name when you need an answer. Reactions arrive late.
I cannot close Settings.
Until an AI connection is configured, Settings stays open. Enter an API key and check the connection.
Search says it only matched words.
Meaning search is preparing or unavailable. Word matches are still shown. Wait a moment and search again.
The text in my image has not been read.
Reading takes a moment. Open “Reading result” under the post a little later. Images are limited to 20 MiB per post.
Where is my data stored?
In a public deployment, in server-side storage separated per account (Firestore and Cloud Storage). When run on your own machine, on that machine’s disk. API keys are stored only on the server.
I want to change a built-in persona.
Use Edit with AI. Existing memories and enabled status carry over.
