kakeratta の使い方

日々のかけらを、ひとつのタイムラインへ放り込む。人や関心ごとに置いた、自分とは別の記憶を持つ AI（担当）が、言うことがあるときだけ反応し、必要なときに思い出させます。

このページは毎日使う機能だけをまとめています。振り分けや返し方の調整、Bluesky・外部エージェント（Hermes、Obsidian）との連携、設定の詳細は 上級編 にあります。

1. はじめる

  1. アプリを開きます。Google アカウントでログインします。認証後は「ログインを完了しています…」を表示し、完了すると自動で画面が切り替わります。データはあなたのアカウントにだけ結びつき、ほかの人からは見えません。
  2. 右上の 設定 を開き、Nebius Token Factory で発行した API キー を入力します。「接続できました」と出れば準備完了です。
  3. 新しいアカウントでは、sona・support・インフォグラフィックの 3 人が最初から有効です。
  4. 欄に一言書いて 流す。これが最初のかけらです。

API キーはサーバー側にだけ保存され、設定した接続先以外へは送られません。

2. かけらを放り込む

書く、貼る、URL、話す。どれも同じひとつの欄から入ります。

書く欄に書いて 流す。Ctrl（⌘）+Enter でも送れます。
画像PC はスクリーンショットを Ctrl+V で貼るだけ。スマホは 📷 画像 からスクリーンショットを選ぶか、その場でカメラで撮ります。画像の文字は読み取られ、あとから検索できます。
URLURL を書いて流すと、公開ページの本文を読み込みます。
話す🎙 話す で音声入力します（8. 音声入力と読み上げ）。

Kindle も有料記事も SNS も、画面に出ていればスクリーンショットで放り込めます。一言と画像を一緒に送ることもできます。投稿に自動で添えられるのは「今どこで何時か」だけです。行き先や時刻は文面に書けば担当が読み取ります。位置情報は任意です。

3. 反応を読む・返す

反応の届き方

  • 担当の反応は少し遅れて届きます。反応が付かないこともあります。 担当は喋らずに覚えるだけのこともあるからです。
  • 必ず答えてほしいときは @名前 で指名します（例：@tabe）。指名された担当は必ず返事をします。担当の名前が並んだバーを押すと、@名前 が書き込まれます。
  • 担当の発言や自分の返信は 返信 N件 の下にたたまれます。表示中に届いた発言は、そのスレッドが自動で開きます。

投稿を削除すると、その下の担当の発言と自分の返信も消え、検索にも出なくなります。その投稿だけをもとに書かれた担当のメモも一緒に消えます。 ほかの投稿ももとにしているメモは残り、担当があとで整理します。

担当の回答や返信は × で消せます。それに（間接的にも）返事している発言も一緒に消え、スレッドのほかの発言は残ります。間違った回答を消すと、それを繰り返した返事も含めて、検索やスレッドの文脈として参照されなくなります。回答と一緒に書いたメモは残るので、メモも誤っていれば担当の記憶から直してください。

予定から届いた通知には 済みにする が表示されます。押すと ✓ 済み になり、もう一度押すと印を外せます。担当も会話を読むときに済みの印を確認できます。操作にはオンライン接続が必要です。

4. 担当を選ぶ・作る

担当は、一人の人物か一つの関心ごとについて、別々の記憶を持つ AI です。人物の担当にはその人の名前が出たかけらが、関心ごとの担当には本体が振り分けたかけらが届き、そのうえで覚えるか、喋るかを各担当が決めます。担当同士でメモは共有しません。

ヘッダーの 担当 で一覧を開き、有効にする で受け取る担当を選びます。担当は投稿された言語で答えます。

AI と担当を作る

  1. 担当 を開き、関心ごと タブで AIと担当を作る を選びます。人物を覚える担当は、人物タブから作ります。
  2. 「どんなことの担当を作りたい？」に自分の言葉で答えます。「ワイン」だけでも始められます。
    例：美味しかったワインのラベルを送るので、銘柄やブドウ品種を教えてほしい。
  3. AI が名前、話し方、覚えることの下書きを作ります。確認して この内容で保存。
  4. 有効にする と、以後のかけらを受け取り始めます。

作成・修正時に 記憶する（オフにすると記憶を持たない回答専門になり、費用削減や不要なメモ防止になります）や、常に熟考する（通常の依頼も最終回答を Super VL で生成）を選べます。

人物の担当

母や友人のように、特定の一人を覚える担当も作れます。担当 の 人物 タブで AIと担当を作る を選ぶと、「誰のことを覚える担当を作りたい？名前や呼び名、あなたとの関係を教えてください。」と尋ねられます。入力欄の例を参考に、「大学時代の友人の佐藤さん。さっちゃんと呼んでいて、たまに一緒に食事をします。」のように答えると、人物の担当の下書きができます。人物を覚える担当かどうかは作成時に決まり、あとから切り替えることはできません。

  • 人物の担当は、本体の振り分けを通りません。 かけらに 呼び名 か キーワード が書かれているときだけ届きます。写真から読み取った文字も対象です。@呼び名 で指名することもできます。
  • 「サトウ」を登録すれば「サトウくん」「さとうさん」にも届きます。全角・半角、大文字・小文字、ひらがな・カタカナ、末尾の敬称（さん・くん など）の違いは区別しません。漢字の「佐藤」とかな書きは別の語として扱うので、両方使うなら両方を呼び名に入れてください。名前を出さない話も拾えるよう、キーワードには言い換えや似た言葉（例：釣り、つり、釣行、海釣り）を並べます。
  • 人物の担当はその人との出来事（会話、贈り物、約束、貸し借り）を覚えます。誕生日や会う予定が近づくと声かけしてくれます（詳しい通知時刻のルールは 上級編 を参照）。
  • 伝えた誕生日・好み・出来事などは、担当の編集画面でいつでも見直し・修正できます。

届かなかったかけらがあれば ⚖ の 呼んでほしかった からキーワードを足せ、関係のないかけらが届いたら 呼んでほしくなかった から一致した語を外せます（人物の担当のキーワードを直す）。

使いながら直す

担当の AIで修正 から「もっと短く返事してほしい」「なぜ気に入ったかも覚えてほしい」のように頼めます。組み込みの担当も同じように変えられ、それまでのメモはそのまま残ります。

担当の 削除 は、その担当のメモも一緒に消します。元に戻せません。受け取りを止めたいだけなら、有効にする をOFFにしてください。

通知予定は担当一覧と発言一覧のカードで確認できます。不要な予定は各予定の × で取り消せます。

編集画面で変更を保存せずに閉じようとすると、確認が出ます。保存して閉じる・保存せずに閉じる・編集に戻る から選べます。

アイコンを変える（絵文字・写真）

担当のアイコンは、作るとき（AIと担当を作る）や、カードの 修正・AIで修正 で変えられます。自分のアイコンは 設定のプロフィール で同じように変えられます。

  • 絵文字を選ぶ を開くと、顔・人・手・体・動物・自然・食べ物・趣味・乗り物・場所・もの・記号・旗のグループごとに絵文字が並びます。押すだけで決まります。一覧にない絵文字は その他の絵文字を入力 から入力できます。
  • 写真を選ぶ で、手元の画像をアイコンにできます。写真は端末の中で正方形に切り抜き、小さく圧縮してから保存します。元の画像はアップロードしません。
  • 写真があるときは写真が優先して表示されます。写真を外す と絵文字に戻ります。絵文字を選び直したときも写真は外れます。

担当からの声かけ

記憶を持つ担当は、伝えたいことがあるときや、出かける前の持ち物点検・雨予報の傘の助言（sona）など、必要なタイミングで話しかけます。話す量や口調は担当のキャラクターに合わせます。「記憶する」をオフにすると定期的なチェックインは止まりますが、明示的な通知予定は引き続き実行します。毎日の起床時刻や月次まとめの仕組みは 上級編 にあります。

リマインダーのPush通知

  1. iPhone・iPadでは、kakerattaをホーム画面に追加し、そこから開きます。
  2. 設定 → この端末 → リマインダーのpush通知 を開き、通知を有効にする を押してブラウザの通知を許可します。受け取りたい端末ごとに設定してください。
  3. 誕生日や予定のリマインダーを、ブラウザを閉じていても受け取れます。通知を開くと該当の投稿に移動します。同じ場所の 通知を無効にする で、その端末への配信を止められます。

通知にはリマインダー本文が最大120文字で表示されます（省略時は末尾に「…」）。ロック画面での表示は端末の設定に従います。通常の返事・チェックイン・今月のまとめは通知しません。HTTPSと対応ブラウザが必要です。配信に失敗しても投稿はタイムラインに残ります。

通知が届かないときは、この端末での有効化、ブラウザの通知許可、ログイン状態、予定ごとの通知設定を確認してください。「サーバーで設定されていません」と表示される場合は運用者の設定が必要です。

予定だけをまとめて見る・編集する

ヘッダーの「予定」（スマホではカレンダーアイコン） で、すべての担当の予定を次の実行日時順に確認できます。担当名や予定の内容で検索できます。各予定の鉛筆マークから 日時・通知を編集 モーダルを開き、次の実行日時と Push通知 を変更して保存してください。入力欄の日時は、表示されたこの端末のタイムゾーンです。

担当ごとのカードや発言一覧でも編集できます。通知OFFでも予定の実行とタイムラインへの投稿は続きます。「この予定は通知しないで」のように担当に頼むこともできます。予定自体を止める場合は × で取り消してください。

毎日の予定は、予定のタイムゾーンで変更後の時刻を引き継ぎます。年次予定も時刻は引き継ぎますが、日付変更は次回だけです。実行を始めた回には変更が間に合わないことがあります。保存に失敗した場合は入力を残して再試行できます。

5. 覚えていることを確かめる

担当の 覚えていること を開くと、その担当が覚えている内容をいつでも確認・編集・削除できます。AIが勝手に覚えたままブラックボックスになることはありません。

できること

  • 読む: 「事実と記録」に、いまの事実・かけらの記録が並びます。担当ごとに1つの記憶として持っています。
  • たどる: 各メモの 元の投稿 を押すと、そのメモのもとになった会話や写真がその場で開きます。記録の #タグ を押すと、その話題だけに絞り込めます。
  • 直す: 誤字や解釈の違いがあれば、横の ✎ でいつでも手で直せます。
  • 消す: 忘れさせたいメモは × や このメモを忘れさせる で消せます。削除前に確認が出ます。記憶を一括削除する専用ボタンはありません。元のかけらを削除すると、そのかけらだけに基づいていたメモも消えます。
  • 見直す・お別れ: その場限りのメモは自動で消え（… に消える）、古いメモはチェックインで「そろそろ忘れていい？」と担当が尋ねてきます（… に見直し）。投稿の下の はい で記録を削除、もうちょっと覚えてて で見直しを延期、忘れないで で以後の見直しを止められます。回答後は選んだ結果が表示されます。言葉で返事をすることもできます。

事実の更新ルールや、記録を事実へ取り込む流れなど、記憶システムの詳しい仕組みは 上級編：記憶の仕組みと見直し をご覧ください。

削除は元に戻せません。消したことでも、残っている投稿を担当が検索して、また覚えることがあります。

たとえば「このワインが好き」という誤ったメモは個別に消し、「一度飲んだだけで好みと決めない」というルールは AIで修正 で伝えます。AIで修正しても、すでにあるメモは書き換わりません。

6. お気に入りに残す

あとで読み返したい投稿や担当の回答の ☆ を押すと、★ に変わり、お気に入りに保存されます。自分の投稿・返信も保存できます。担当のメモに残らない回答も、ここから読み返せます。

タイムライン上の 絞り込み を開き、お気に入りのみ をオンにすると、保存した投稿・回答を会話と一緒に表示します。開始日・終了日 で投稿日時を絞れます。終了日も含みます。発言一覧でも同じ絞り込みを使えます。閉じても条件は維持され、「絞り込み中」と表示されます。

★ で解除するときは、どの画面でも確認します。キャンセルするとお気に入りも表示も残ります。解除しても投稿は消えません。

入力欄の下の担当を右クリック（スマホは長押し）し、発言一覧 を選ぶと、その担当の発言を開けます。

7. 検索する

ヘッダーの 検索 を開きます。「ピノ」のような名前も、「軽くて飲みやすかった赤ワイン」のような言い方も、同じ欄に入れられます。

  • 短い語句はキーワードで、質問や文章は意味の近さで探します。結果の画面から探し方を切り替えられます。
  • 探す対象は、自分が書いた本文、画像から読み取った文字、担当との会話です。
  • 結果を押すと、元の投稿と会話が開き、そこから返信も書けます。

絞り込み を開くと、開始日・終了日 を検索語やお気に入り条件と組み合わせられます。期間だけでの検索もできます。

お気に入りだけを検索する

お気に入りのみ をオンにすると、保存した投稿・回答だけを対象に検索します。キーワードでも意味でも探せます。検索欄を空にすると、お気に入りの投稿・回答を投稿日時の新しい順に表示します。

担当も必要なときに過去のかけらを検索し、「前に気に入ったピノに近いですね」のように元の投稿へのリンク付きで答えることがあります。

8. 音声入力と読み上げ

  • 🎙 話す を押すと、ブラウザの音声認識で聞き取ります。無音が続くと自動で止まります。
  • 送信の合図（例：「以上」）を決めておくと、文の最後にそう言った時点で投稿されます。
  • 自動送信前にAIで文章を整える をONにすると、合図で送るときだけ、句読点や言いよどみを整えます（初期状態はOFF）。
  • 🔈 読み上げ は、溜まった反応を順に読み上げます。

合図、無音での停止、声と速さは 設定 → 上級オプション → 音声 で変えられます。

9. オフラインで使う

一度オンラインで開いた端末なら、電波がなくても文章・画像・URL・返信を書けます。書いたものは「端末に保存済み・送信待ち」として残り、アプリを開いている間に接続が戻ると自動で送られます。担当の反応は、サーバーに届いてから始まります。

  • 送信に失敗したときは 接続して再送 でやり直せます。二重に投稿されることはありません。
  • 送信待ちは、ブラウザのデータを消すと失われます。ログアウトするときは確認のうえ、この端末の保存データを消します。
  • 直近20件の会話は端末にも保存され、次に開いたときすぐ表示されます。

10. 困ったとき

反応が付きません。
担当が誰も有効でないか、どの担当の分野にも当たらなかったか、担当が「覚えるだけ」にしたのかもしれません。⚖ で誰に届いたかを確認できます。必ず答えてほしいときは @名前 で指名してください。
設定画面が閉じられません。
AI の接続が済むまでは閉じられません。API キーを入力してください。
検索で「語句の一致で探しました」と出ます。
意味で探す準備が終わっていないか、接続できない状態です。語句で見つかった結果は表示されています。少し待ってから検索し直してください。
画像の文字が読めていません。
読み取りには少し時間がかかります。しばらくして投稿の「読み取り結果」を開いてください。画像は1投稿あたり 20 MiB までです。
データはどこに保存されますか。
アカウントごとに分かれたサーバー上に保存され、ほかの人からは見えません。手元に保存したいときは 設定とデータ を見てください。

kakeratta 上級編

担当の振り分けや返し方の調整、担当が起きるタイミング、Bluesky・外部エージェント（Hermes、Obsidian）との連携、設定とデータ、担当が使う道具を説明します。毎日の使い方は 基本の使い方 を見てください。

1. 振り分けを直す

かけらをどの担当に渡すかは本体が決めます。自分の投稿や返信の ⚖ を押すと、呼ばれた担当と、呼ばれなかった担当ごとの一行の理由が出ます。@名前 で指名した担当は、あなたが選んだので出ません。

指名と宛先の優先ルール： @名前 で指名した投稿や、有効な担当への返信は、宛先の担当だけに届きます。別の担当を指名した場合は指名が優先されます。それ以外の投稿は、担当条件や人物の呼び名・キーワードで届け先を選びます。

@infographic の対象ルール： 図解したい投稿や回答に @infographic これをインフォグラフィックにして と返信します。別の担当の回答に返信した場合、その回答を図解します。「元の投稿を」「スレッド全体を」と明示して対象を変えることもできます。URLは展開された記事本文、画像は読み取り済みの説明や文字を材料にします。図解は依頼時の表示言語に翻訳され、絵文字やMermaidを使ったMarkdownで画面内に表示されます。Web検索は行いません。

呼ばれた担当には、処理が終わったか、返事をしたか、メモを残したかが出ます。黙っていた担当には 返事がほしかった から 返し方を直す 流れに入れます。

担当の条件を直す

  1. 行の 呼んでほしかった（または 呼んでほしくなかった）を押します。
  2. 理由やどう変えてほしいかを書き、条件を作る を押します。AI が担当の判定条件だけを書き直します。
  3. 新しい条件は手で直せます。AIに変更を依頼 で書き直しを頼むこともできます。
  4. OK で保存すると、同じ投稿で振り分けを試します。「呼んでほしかった」で狙いどおり呼ばれたら、その担当に元の投稿を渡して返事やメモを残します。違えば理由を見てやり直します。

変わるのは判定条件だけで、口調や覚え方は変わりません。振り分けに Jev を使っている場合（設定とデータ）は理由が表示されませんが、条件は同じ手順で直せます。

人物の担当のキーワードを直す

人物の担当には判定条件がなく、呼び名かキーワードが書かれたかけらだけが届きます。⚖ には、どの語で届いたかが「「佐藤さん」に一致」のように出ます。

  1. 届かなかった人物の担当の行で 呼んでほしかった を押します。今のキーワードが出ます。
  2. どの語で呼んでほしいかを書き（空でもかまいません）、キーワードを作る を押します。AI がそのかけらに書かれている語を選び、似た言葉とあわせて足すキーワードを出します。
  3. 足すキーワードは手で直せます（読点区切り）。AIに変更を依頼 もできます。
  4. OK で今のキーワードに足して保存し、同じかけらで確かめます。足した語がかけらにあれば、その担当に元のかけらを渡します。なければそう伝えるので、やり直します。

関係のないかけらが語の一致で届いたときは、呼ばれた人物の担当の行で 呼んでほしくなかった を押します。

  1. 呼び名とキーワードのうち、そのかけらに一致した語が並びます。担当の名前そのものは表示だけで、ここでは外せません（担当の 修正 で変えます）。
  2. 外す語にチェックを入れて 外す を押します。保存して同じかけらで確かめ、ほかの語でもまだ一致するなら、その語を伝えるので続けて外せます。
  3. 外さないなら 残す で閉じます。その人と関係のないかけらなら、担当はもともと発言もメモもせずに終えます。

外した語だけを含むかけらは今後届かず、外した呼び名は @ での指名にも使えなくなります。そのかけらに担当がすでに残した発言やメモは消えません。

2. 返し方を直す

担当の発言の 返し方を直す を押し、期待とどう違うかを書きます。AI が担当の 口調 と 指示 だけを書き直します。判定条件、名前、道具は変わりません。

  1. 違いを書いて 直し方を作る を押します。
  2. 新しい口調と指示は手で直せます。AIに変更を依頼 で書き直しを頼むこともできます。
  3. OK で保存すると、同じ投稿で担当が試し書きをします。タイムラインには載らず、メモも予定も書かれません。数分かかることがあります。
  4. これでよい で試し書きの返事とメモ変更を元のスレッドに反映します。まだ違う なら、試し書きを見ながらもう一度伝えます。

保存した口調と指示は、試し書きの結果にかかわらずそのまま残ります。

3. 担当が起きるタイミング

担当が動くのは、次の3つのときです。

きっかけ決める人内容
かけらが届いたとき本体（振り分け）@名前 の指名や有効な担当への返信は宛先1人だけを起こし、指名を優先します。それ以外は担当条件や人物の呼び名・キーワードで選びます。
毎日のチェックイン本体設定したアカウント共通の時刻に、記憶がオンの有効な担当が順番に起きます。月1回振り返る人物は、今月のまとめの日に起きます。
担当が預けた予定担当schedule を持つ担当が、自分の記録から時刻を決めて起きます。

毎日のチェックイン

設定 → 毎日の振り返り で時刻を指定できます。「自動」では、アカウント共通で7時〜21時の間に決まり、日ごとに少しずつ動きます。指定した時刻は設定のタイムゾーンに従います。

  • 本体が前回からの投稿を内部用に一度まとめ、記憶がオンの有効な担当が順番に、そのまとめと自分の記憶を読みます。新しい投稿、見直す記録、近い予定がなければ発言せずに終わることがあります。
  • 混み具合で開始が遅れることがあります。指定時刻を過ぎた分は当日中、自動の場合は21時までが実行対象です。過ぎた日の分をまとめて実行することはありません。
  • 自動の時刻が夜から朝へ回り込む日は休みますが、月次まとめの日は実行します。時刻を指定した場合はこの休みはありません。
  • 一度実行した担当は、黙った場合や失敗した場合もその日の1回に数えます。最近の記録は前回のチェックインから読みます。
  • チェックインでは現在地を使わないので、店舗検索は名前での検索だけになります。

「外部エージェントを優先する」をONにした担当では、チェックインで何を話すか（聞くことや伝えること）を外部エージェントが書きます。記憶をどう整えるかは、ふだんどおり kakeratta が決めます。時間内に外部エージェントが応じなければ、内蔵モデルが代わりに書きます。

今月のまとめと、月1回振り返る人物

月に1回、本体がその月のタイムラインを読み、今月のまとめ をタイムラインに投稿します。あなたの発言・行動・決定・変化を話題ごとにまとめます。担当の提案だけでは、あなたが実行したことや予定として扱いません。各項目の → から元のかけらを開けます。日付は本体がアカウントごとに決めます（毎月1〜28日のどこか）。まとめはあなたのものとして ✎ で直せます。

人物の担当は、カードで 頻繁に振り返る か ときどき振り返る を選べます。月1回にした人物は、まとめが書かれた日に起き、まとめと、その人の名前やキーワードが出たかけらを読んで振り返ります。人物が増えても、タイムラインを読むのは月に1回で済みます。AI と担当を作ると、家族や親しい人は毎日、たまに会う人は月1回のように、関係性から選ばれます。関心ごとの担当は毎日です。

人物の担当の予定通知ルール

基本情報の保存・編集や、その人物に届いたかけらから、日付の分かる誕生日・記念日・会う予定を自動で登録します。

  • 誕生日・記念日： 毎年、1週間前と当日の午前9時に知らせます。
  • 会う予定： 指定された通知時刻を優先し、指定がなければ当日午前9時（午前9時より早い予定は1時間前）に知らせます。
  • 通知は担当の投稿として届きます。未来の予定に日数の上限はなく、日付の分からない情報は推測で登録しません。予定の変更や中止も反映します。

担当が預けた予定（schedule）

sona は、投稿や習慣から出発の時刻が分かると、少し前に起きて持ち物を点検します。以前「鍵を忘れた」と話していれば、その経験も手がかりになります。外出先と日時が分かれば最新の天気予報を調べ、今晴れていても帰りが雨なら傘を一言勧めます。地域や時刻、取得できない予報は作りません。用事をしたかの確認は少しあとに置き、済んでいたり同じことを伝えていたりすれば黙ります。催促や毎日の一般的な読み上げはしません。

人物の担当は、「来週土曜、佐藤さんと飲む」のような会う予定が書かれると、その日の朝に予定を置きます。起きたら前回の出来事や済んでいないこと（貸し借り、約束）を一言添えて知らせます。

  • 担当ごとに20件まで。未来の時刻に日数の上限はありません。道具の予定は1回きりか毎日、誕生日・記念日は毎年繰り返します。
  • 予定は担当のカードに並びます。不要な予定は × で消せます。
  • 起きた回は、担当が黙っても失敗しても消費されます。予定より10分以上遅れた回は実行しません。
  • かけらを消すと、担当がそのかけらのために置いた予定を見直します。担当を停止・削除したときは、その担当の予定も消えます。

記憶の仕組みと見直し

担当の記憶は、以下の構造で管理されます。

  • かけらの記録: 受け取ったかけらごとに、日時・元の投稿・要約・タグを1行残します。会話のたびに行うのはこれだけです。
  • 今の事実: 分かっていることを1件1行で持ちます。チェックイン（通常は毎日、月1回振り返る人物は月1回）で、新しい記録を事実に取り込み（足す・書き換える・消す・まとめる）、取り込んだ記録は消えます。当てはまらなくなった事実も消えます。
  • 新しい担当の提案: 記憶は話題ごとに分けません。別の話題がたまってきたら、担当が「新しく担当を作って分けませんか？」と提案します。投稿の下の 作る を押すと、名前や担当条件を整え、関係する事実と記録を移した新しい担当がすぐに追加されます。元の担当の担当条件からその話題は外れるので、以後はその話題が新しい担当にだけ届きます。作らない で見送れます。
  • 期限とお別れ: 「今日のランチ」のような一時的な記録は … に消える として自動削除され、長く使われていない記録は … に見直し としてチェックイン時に担当から「忘れていい？」と尋ねられます。

4. Blueskyに公開する

自分の投稿と担当との会話から、見せたい発言だけを選んで、自分の Bluesky アカウントから投稿できます。担当の発言には「🍚 tabeからの返信:」のような署名が付きます。

アカウントをつなぐ

  1. 設定 → 上級オプション → 外部連携 → Bluesky連携、または投稿の Blueskyに投稿 を開きます。
  2. 自分のハンドル（例：alice.bsky.social）を入れて Blueskyと接続 を押します。
  3. Bluesky の画面で許可すると、同じタブで kakeratta に戻ります。パスワードは Bluesky 側にだけ入力します。

会話を選んで公開する

  1. 元の投稿の Blueskyに投稿 を押します。最初は元の投稿だけが選ばれています。
  2. 元の投稿のチェックを外して、回答だけ公開することもできます。1件以上選んでください。返信先を選ばなかった発言は、選択した最初の発言への返信として公開します。
  3. 発言ごとに テキスト か 画像 を選びます。公開内容が同じ画面に自動で表示されるので、確認して 投稿 を押します。切り替え中や画像の変換中は投稿できません。

公開されるもの・されないもの

  • 公開されるのは、選んだ発言の本文・リンク・出典URL・画像です。位置情報、画像の読み取り結果、担当のメモは公開されません。
  • 長い発言は、文の切れ目で300文字程度ずつに分け、2つ目以降に「つづき:」を付けます。画像は最初の1つにだけ付きます。
  • 担当の回答の見出し・箇条書き・表は、Blueskyで読みやすい文章に直して公開します（Blueskyには太字や見出しがないため）。[文字](URL) のリンクは文字がそのままリンクになり、本文中のURLもリンクになります。
  • 担当のHTML回答とインフォグラフィックの図解は、最初は画像が選ばれています。テキストに切り替えることも、通常の文章を画像にすることもできます。縦長の回答は複数枚に分けるので、プレビューですべて確認してください。変換できない場合は投稿を止めます。元の回答はそのまま残ります。
  • 2 MB を超える画像は送信用に縮小されます（元の画像はそのまま）。透明部分は白に、GIF は静止画になります。
  • 一度に選べるのは100発言までです。

あとから足す・やめる

  • 公開済みの発言は再送されません。あとで選んだ返信だけを追加で投稿できます。
  • 通信が切れて結果が分からないときは、二重投稿を防ぐために止まります。Bluesky 側で確かめてください。
  • 接続を解除 でつながりを外せます。解除しても、kakeratta で投稿を消しても、Bluesky の投稿は消えません。

5. 担当の考える役を外部エージェントに任せる

接続先を設定し、設定の「外部エージェントを使う」をONにすると、担当ごとに「外部エージェントを優先する」を選べます。ONにした担当は、投稿やチェックインで起きたとき、文脈を読んで調べ、回答を書く部分を、自分で動かしている外部エージェントに任せます。標準で対応しているのは Hermes Agent と、Obsidian のプラグイン LLM Connect Hub です。ほかのエージェントも、MCP Streamable HTTP で接続し、依頼の定期取得・調査・回答の提出を実装すれば使えます。回答を受け取ったあと、kakeratta が記録の追加と予定を扱い、予定変更があれば回答と食い違わないか確認してから公開します。担当が使える外部MCPの道具は読み取り専用です。Hermes をまだ入れていない場合は、先に Hermes連携の手引き を見てください。

外部エージェントに直接頼む

@agent・@外部エージェント・@エージェント で、担当を介さず接続先に直接依頼できます。回答への返信はそのまま次の依頼になります。担当の記憶や予定は更新しません。

依頼には待機中・作業中の状態が表示され、🔔 で回答のプッシュ通知を切り替えられます。取得まで、取得後の回答まで、それぞれ2時間を過ぎるとお知らせします。遅れて届いた回答も表示されます。作業開始後の編集は届かないため、追加事項は返信してください。利用できる道具や実行できる作業は、接続先の設定に従います。

接続先を管理する

同時に使える接続先は1つです。外部エージェントを優先する担当は、すべて「使用する接続先」で選んだ接続先を使います。

  • 「＋ 接続先を追加」で名前を付けると、その接続先のキーが発行され、そのまま使用中になります。キーが表示されるのは発行した直後だけです。
  • 一覧で別の接続先を選ぶと切り替わります。ほかの接続先のキーは残りますが、使用中でないキーでは接続できません。切り替えたときに取りに来るのを待っていた依頼は、内蔵モデルが答えます。
  • キーの再発行と削除は、接続先ごとの行で行います。

Hermes とつなぐ

  1. 設定 → 上級オプション → 外部連携 → 外部エージェント接続 で 追加してキーを発行 を押し、表示された設定をコピーします。
  2. Hermes を動かす端末の ~/.hermes/config.yaml に追加し、Hermes を再起動します。すでに mcp_servers があれば、その中に kakeratta を足します。
  3. Hermes に kakeratta の Skill と Wake Gate を入れ、毎分確認するよう設定します（手順は手引きにあります）。
mcp_servers:
  kakeratta:
    url: "画面に表示された接続URL"
    headers:
      Authorization: "Bearer 画面に表示された接続キー"

Obsidian（LLM Connect Hub）とつなぐ

LLM Connect Hub を使うと、担当の回答を Obsidian の LLM Hub が答えます。モデルは LLM Hub で選んだものを使い、Vault のノート・RAG・スキルを調べて回答します。回答の出典には、参照した Vault のファイルが [[ファイル名]] で示されます。

  1. Obsidian のコミュニティプラグインから LLM Hub と LLM Connect Hub を入れて有効にします（デスクトップ版のみ）。
  2. kakeratta の 設定 → 上級オプション → 外部連携 → 外部エージェント接続 で接続名（例: Obsidian）を付けて 追加してキーを発行 を押します。
  3. LLM Connect Hub の設定の Kakeratta に、接続情報と待ち時間 に表示された MCPエンドポイントを入れます。Add header で名前 Authorization、値 Bearer 接続キー を追加します。
  4. 回答に使うモデル、読んでよい Vault のフォルダ、RAG、スキルを決めます。担当ごとに変えることもできます。
  5. Check periodically をONにして Enabled をONにし、Save and reconnect を押します。

LLM Connect Hub は Obsidian を開いている間、1分ごとに依頼を確認します。依頼がないときにモデルのトークンは使いません。確認の間隔が1分なので、取得を待つ時間（外部エージェントが依頼を受け取るまで kakeratta が待つ時間）は1分より長くしておいてください。Obsidian を閉じて取得を待つ時間が過ぎると不在とみなされ（下の「担当を任せる」を参照）、それ以降の依頼は待たずに内蔵モデルが答えます。閉じた直後に届いた依頼は、待ち時間が過ぎてから内蔵モデルが答えます。詳しい設定は LLM Connect Hub の説明 を見てください。

担当を任せる

  1. 担当 画面で、任せたい担当の 外部エージェントを優先する をONにします。このチェックは、接続先を設定し、設定の「外部エージェントを使う」がONのときだけ表示されます。
  2. いつもどおり投稿します。その担当に届いた投稿は、外部エージェントが調べて回答を書きます。記憶・予定は kakeratta が決めます。返事は担当の名前で「外部エージェント」の印付きで届きます。

外部エージェントが3分以内に依頼を取りに来ない、または取ってから15分以内に回答を返さないときは、内蔵モデルが代わりに答えます。

最後の接続から 取得を待つ時間（既定は3分）が過ぎても接続がなければ、外部エージェントは不在とみなされます。不在のあいだは、以後の依頼を待たずに内蔵モデルが答えます。再び接続されると、次の依頼から外部エージェントに戻ります。依頼に取り組んでいる最中は不在になりません。

待ち時間は 外部連携 の接続先ごとの 接続情報と待ち時間 で、エージェントごとに変えられます。同じ画面の 外部エージェントを使う をOFFにすると、外部エージェントからの接続を受け付けず、担当ごとの設定を残したまま内蔵モデルで考えます。返し方を直す ときの試し書きは、常に内蔵モデルで行います。

外部エージェントが読めるもの

外部エージェントは、あなたの投稿と すべての担当のメモ を読めます。担当への依頼では回答を提出し、記憶と予定は kakeratta が管理します。また、外部エージェントを優先する有効な担当として、自発的にタイムラインへ投稿できます（担当ごとに1日5件まで）。この投稿だけで担当の記憶が更新されたり、通知が送られたりすることはありません。モデル設定や他の利用者のデータには触れません。接続先を削除すると接続キーが無効になります。

外部エージェントが読んだ投稿やメモは、そのエージェントが使うモデルにも渡ります。Hermes や LLM Hub で外部の API のモデルを選んでいれば、その提供元に送られます。端末の外に出したくない場合は、ローカルのモデルを使ってください。ただし LLM Connect Hub で Vault・RAG・スキルを使って答えるには、API のモデルが必要です。

つながらないとき

  • 設定を変えたあと Hermes を再起動したか確認してください。
  • Hermes から接続URLに届くか確認してください。
  • キーを再発行したら、config.yaml も置き換えてください。
  • LLM Connect Hub では、設定画面の接続状態（例: Kakeratta: connected; 1 ask failed）を見てください。回答が失敗した依頼は内蔵モデルが答えます。

Gmail・Google Calendarをつなぐ

Google Bridgeは、自分の端末・サーバーで動かす個人用Webアプリ兼MCPサーバーです。Googleの資格情報はBridgeへ暗号化保存し、HermesはMCPで読み取ります。Hermes側workerが候補を取得し、LLMで選別・要約した結果をコードでTimelineの取り込み待ちへ届け、本人が「取り込む」を選んだ内容だけを通常投稿・担当・記憶の処理へ渡します。

1. Google Bridgeを起動する

Go 1.26以降と、このリポジトリが必要です。Hermesは上の手順でkakerattaへ接続しておきます。リポジトリのルートで次を実行します。Bridgeの画面はGoに埋め込まれているのでnpmは不要です。

mise exec -- go run ./tools/google-bridge/cmd/google-bridge -init
mise exec -- go run ./tools/google-bridge/cmd/google-bridge

http://127.0.0.1:8094 を開き、初期化時に表示されたパスの設定ファイルを自分のエディターで開いて、adminTokenをログイン欄へ入力します。管理キーをHermesやチャットへ貼り付けないでください。

2. 自分のGoogleアカウントを接続する

  1. BridgeのGoogleを接続でセットアップ案内を開き、自分のGoogle Cloudプロジェクトを指定します。表示されたCLI手順またはConsoleリンクでGmail APIとGoogle Calendar APIを有効にします。案内はコマンドを自動実行しません。
  2. Google Auth Platformで同意画面を設定し、Testingなら自分をテストユーザーへ追加します。Web applicationのOAuthクライアントを作り、Bridgeに表示されたリダイレクトURIを完全一致で登録します。既定はhttp://127.0.0.1:8094/api/google/callbackです。
  3. Web用OAuth JSONをBridgeの専用フォームで読み込むか、project ID・client ID・client secretを入力します。読み取りだけなら送信・下書き・予定変更の追加権限を外します。
  4. GoogleデータがHermesと設定したモデルへ渡ることを確認し、同意してGoogleに接続を押します。同じタブで認可を完了し、Gmail・Calendarの接続状態と接続テストを確認します。

3. HermesとTimelineを接続する

BridgeのHermesとつなぐから設定例を~/.hermes/config.yamlのmcp_serversへ追加し、Hermesを再起動します。同じ端末のローカル接続モードではキーなしの設定例が使えます。個別MCPキーを発行した場合は表示されたAuthorization設定も追加します。管理キーとは別のキーです。

mcp_servers:
  google_bridge:
    url: http://127.0.0.1:8094/mcp
    tools:
      prompts: false
      resources: false

kakerattaの外部エージェント接続で発行した本人のMCP URL・キーは、上のHermes連携手順でmcp_servers.kakerattaへ設定します。取り込みworkerは下のgoogle_bridge.jsonと親Hermesのkakeratta接続を使います。上のgoogle_bridge設定は対話読み取り・直接依頼用です。Bridgeへkakerattaの接続先やキーを入力する手順はありません。以前のBridgeに保存していた投稿先の資格情報は更新後の起動時に削除します。Hermesが別端末・コンテナの場合、127.0.0.1はHermes自身を指すので、到達できる同一originの転送やHTTPS構成が必要です。

@agentの直接依頼workerでも使う場合は、同じ設定ファイルの既存のkakeratta_worker.mcp_serversへgoogle_bridgeを追加します。他の設定・接続先を残して追記してください。

kakeratta_worker:
  mcp_servers: [google_bridge]

4. 同期して取り込むものを選ぶ

  1. 重要メールの確認で取り込みが有効か確認します。停止中ならおすすめ設定で有効にするを押し、今すぐ差分を取得します。フィルターでは対象・優先ラベル、送信元、除外、任意のLLM判定を調整できます。
  2. 今日・明日の予定を取り込むも有効か確認し、詳細設定で対象カレンダーとタイムゾーンを確認して、今日・明日の予定を今すぐ確認を押します。既定はprimary・Asia/Tokyoです。
  3. LLM判定が有効な場合はHermesによる判定完了を待ちます。Timelineの待機カードから内容を開き、取り込む／取り込まないを選びます。破棄時にはメールの種類・From、単発予定・定期予定全体の除外も選べ、Hermes側workerのコードが実際のレシートを取得しBridgeへ戻すと反映されます。

5. 定期実行と直接依頼

定期同期は既存のHermes cronを使います。リポジトリのtools/google-bridge/hermes/にあるcheck_google_bridge.py・check_calendar_bridge.py・google_bridge_worker.pyを自分のHermesのscriptsへ置きます。先にkakeratta連携を導入し、既存のdirect_request_worker.pyも配置されていることを確認します。BridgeのMCPキー発行時に表示されるJSONを同じ場所のgoogle_bridge.jsonへ保存して権限を0600にします。メールは30分ごと、予定は日次などで登録します。cronは--no-agent付きでgateを実行します。gateは必要なときだけworkerを起動します。配送・レシート返却はコードで行い、LLMは選別・要約が必要なときだけ隔離セッションで動きます。具体的な登録コマンドは設定・運用・復旧ガイドを参照してください。

送信・返信・下書き保存・予定の作成／変更／削除は、追加権限を付け、@agentで自分のHermesへ明示的に直接依頼する別の機能です。google_action_runはWebでの再確認なしに実行します。本人の依頼であることはサーバーで検証できないため、判定ジョブから書き込みツールを除外してください。結果が不明なら再送せずGoogle上で確認します。

Google側の予定変更は既存カード・投稿へ自動反映されません。再認証が必要なら同じGoogleアカウントで接続し直し、URI不一致ならGoogle側の登録値を確認してください。実Google OAuth・実Hermesの接続は未検証です。自分の環境でまずメール検索と予定読み取りを確認してください。

担当は、返事やメモに必要な道具を自分で選んで使います。ふだんの言葉で頼めばよく、道具の名前を書く必要はありません。@名前 で指名された担当は必ず返事をしますが、どの道具を使うかは担当が決めます。

道具できること使える担当・必要な設定
timeline_search過去のかけらを検索すべての担当
records前のかけらの記録を探す（記憶の保存は本体が行う）記憶がオンの担当
web_searchWeb 検索道具に追加した担当。Tavily の API キー
place_search店や場所を探す道具に追加した担当

担当が使える道具は、担当パネルの 道具 に出ます。増やしたいときは AIで修正 で「Web検索も使えるようにして」のように頼み、変更案を確かめて保存します。

道具は kakeratta のサーバーで動きます。位置情報を許可すると、座標がサーバーへ送られ、店や場所を探すときに外部の地図サービスへ渡ります。担当が読んだメモや検索結果は、AI モデルへの入力にも含まれます。

過去のかけら検索 — timeline_search

保存した投稿、画像から読み取った文字、返信を、語句と意味の両方で探します。期間を指定して、その間の記録をまとめて読むこともできます。一度に返るのは30件までです。検索で見つかった投稿のうち、担当が根拠にしたものだけが発言の下にリンクされます。

例：「@tabe 前に飲んで気に入った、軽い赤ワインを探して」

かけらの記録を探す — records

担当は毎回、今の事実と最近の記録を読んでから考えます。それより前のかけらの記録は、タグ・語句・意味で探し、記録の投稿そのもの（返事なら元のかけらも）を読めます。返事のあとには本体が記録を追加し、チェックインで新しい記録を事実に取り込みます。中身の確認や削除は 覚えていること から行います。

例：「@tabe 前に行きたいって言ってたラーメン屋、どこだっけ」

Web検索 — web_search

ニュースや技術情報などを検索し、結果のリンクを出典として付けます。設定 → Web検索 に Tavily の API キーを入れて使います（AI の API キーとは別）。検索結果の要約を使うので、リンク先の全文を読むとは限りません。

例：「@shiori この本の著者についてWebで調べて」

店舗・場所検索 — place_search

投稿に位置情報があれば周りの店や場所を、なければ名前で場所を探します。地図に載っていない店は見つからず、営業中かどうかや空席は分かりません。見つからなくても「店がない」とは限りません。

例：位置情報付きで「@tabe この近くのラーメン屋を探して」

天気予報 — weather_forecast

WeatherAPI.comから現在の天気と日別予報を調べます。地域名を指定するか、投稿の位置情報を使います。日付や現地時刻の時間帯を指定して確認することもできます。取得できる予報の期間は接続先の契約によって異なり、取得していない日の天気は分かりません。担当の道具に「天気予報を調べる」を追加して使います。

例：「@sona 東京の明日の18時ごろ、雨は降りそう？」

Using kakeratta

Toss fragments of your day into one timeline. AI personas, one for each person or interest you choose and each with its own memory, speak up only when they have something to say and bring things back when they matter.

This page covers what you use every day. Fixing routing and replies, Bluesky and external agents (Hermes, Obsidian), and settings in detail are in the advanced guide.

1. Getting started

  1. Open the app. Sign in with your Google account. After approval, “Completing sign-in…” stays visible until the app opens automatically. Your data is tied to your account and nobody else can see it.
  2. Open Settings at the top right and enter an API key from Nebius Token Factory. “Connected” means you are ready.
  3. New accounts start with three personas active: sona, support and the infographic persona.
  4. Write a line in the box and press Post. That is your first fragment.

The API key is stored only on the server and sent only to the configured endpoint.

2. Tossing in a fragment

Write, paste, post a URL, or speak. Everything goes through the same box.

Way inHow
WriteType and press Post, or Ctrl (⌘) + Enter.
ImageOn a PC, paste a screenshot with Ctrl+V. On a phone, pick a screenshot with 📷 Image or take a photo there and then. Text in the image is read and becomes searchable.

Speak🎙 Speak starts voice input (8. Voice input and read-aloud).

Kindle, a paywalled article, a social feed: if it is on screen, a screenshot brings it in. An image can go with a line of text. Only where you are and what time it is travel with a post automatically; destinations and times belong in what you write. Location is optional.

3. Reading and replying

How reactions arrive

  • Reactions arrive a little later. Some posts get no reaction: a persona can remember something without speaking.
  • For a guaranteed answer, mention a persona with @name (for example @tabe). A persona you mention always replies. Tapping a name in the persona bar (the personas listed below the text box) writes the mention for you.
  • Persona remarks and your replies fold under N replies. A remark that arrives while you are looking opens its thread by itself.

Deleting a post removes the remarks and your replies under it, and it no longer appears in search. Persona notes that rest only on that post are deleted too. Notes that also rest on other posts stay, and the persona tidies them later.

A persona's answer or a reply can be deleted with its ×. It takes the lines answering it, directly or further down, and nothing else in the thread: a wrong answer, and the replies that repeated it, then no longer turn up in searches or as context in the thread. The notes written with it stay; correct them in the persona's memory if they are wrong too.

Scheduled reminders offer Mark done. Tap it to show ✓ Done, or tap again to remove the mark. Personas can see the mark when reading the conversation. This requires an online connection.

4. Choosing and creating personas

A persona is an AI with its own memory for one person or one interest. A person's persona gets the fragments that mention them; an interest's gets the ones the app routes to it. Each then decides whether to remember and whether to speak. Personas do not share notes with one another.

Open Personas in the header and turn on Enable for the ones you want. A persona answers in the language you wrote in.

Create a persona with AI

  1. Open Personas, select the Interests tab, and choose Create a persona with AI. To remember a person, start from the People tab.
  2. Answer “What would you like your persona to help with?” in your own words. Even “wine” is enough.
    Example: When I send a photo of a wine label I liked, tell me the wine and its grape varieties.
  3. The AI drafts a name, a way of talking, and what to remember. Review it and select Save this persona.
  4. Enable it and it starts receiving fragments.

Creation and editing offer Remember (turning it off creates an answer-only persona, saving token costs and avoiding unwanted notes) and Always think deeply (uses Super VL for final answers to ordinary requests).

People

A persona can also keep one person in mind - your mother, a friend. In Personas, select the People tab and choose Create a persona with AI. You will be asked, “Who would you like a persona to remember? Tell me their name or nickname and how you know them.” Follow the example in the input box, such as “My friend Sato from university. I call her Sacchan, and we sometimes have meals together,” to get a draft for that person. Whether it keeps a person is fixed when you create it and cannot be switched later.

  • A person is never routed by the app. A fragment reaches it only when one of its names or keywords is written in it, text read from a photo included. You can also call it with @name.

1. Fix who gets a post

The app decides which personas get each fragment. Tap ⚖ on one of your posts or replies to see who was called and, for each one that was not, a one-line reason. A persona you mentioned with @name is not listed: that was your call.

Mention and recipient precedence: A post that mentions a persona with @name, or a reply to an active persona, reaches that recipient alone; mentions take precedence. Other posts reach personas whose subject conditions or person names/keywords match.

@infographic targeting rules: Reply to a post or answer with @infographic Turn this into an infographic. When replying to another persona's answer, it visualizes that answer. You can also specify “the original post” or “the whole thread” to change the target. URLs use expanded article bodies, and images use extracted captions and text. The infographic is translated to your current display language and shown in the timeline as Markdown with emoji and Mermaid diagrams. It does not use Web search.

For each persona that was called you see whether it has finished, replied, or kept a note. For one that stayed silent, A reply was wanted leads to fixing how it replies.

Fix a persona's condition

  1. Tap Should have been called (or Should not have been called) on a row.
  2. Say why or what should change and tap Write the condition. The AI rewrites the persona's condition, and only that.
  3. Edit the new condition by hand, or use Ask the AI to change it.
  4. OK saves it and tests routing on the same post. If "Should have been called" succeeds as intended, the persona is woken with the original post to reply and keep notes. If not, you see why and can try again.

Only the condition changes; tone and memory rules stay. When routing uses Jev (Settings and data), no reasons are shown, but conditions are fixed the same way.

Fix a person's keywords

A person's persona has no condition: only fragments with one of its names or keywords reach it. In ⚖ the word it was reached by is shown, as in Matched “Sato”.

  1. Tap Should have been called on the person's row. The current keywords are shown.
  2. Say which words should call them (or leave it empty) and tap Make keywords. The AI picks words written in the fragment and proposes them with their near words.
  3. Edit the keywords to add by hand (comma-separated), or use Ask the AI to change it.
  4. OK adds them to the saved keywords and checks the same fragment. If one of them is in it, the persona gets the fragment; if not, you are told and can try again.

When an unrelated fragment reached a person by a word, tap Should not have been called on its row.

  1. The names and keywords that match the fragment are listed. The persona's own name is shown but cannot be removed here (change it with Edit).
  2. Check the words to remove and tap Remove. They are saved and the same fragment is checked; if it still matches another word, you are told which and can remove that too.
  3. To leave them, tap Keep. A fragment that is not about the person already ends with no reply and no note.

A removed word no longer brings fragments that have only it, and a removed name no longer answers an @. What the persona already said or noted on the fragment stays.

2. Fix how a persona replies

Tap Change how it replies on a persona's remark and say how it missed. The AI rewrites the persona's tone and instructions only; its condition, name and tools stay.

  1. Describe the miss and tap Write the fix.
  2. Edit the new tone and instructions by hand, or use Ask the AI to change it.
  3. OK saves them, and the persona drafts a trial reply to the same post. Nothing lands on the timeline and no note or schedule is written. This can take a few minutes.
  4. That's it applies the trial reply and its memory edits to the original thread. Still not it lets you say again, with the trial reply in view.

What you saved stays saved, whatever the trial says.

3. When personas wake

A persona acts at three kinds of moment.

Daily check-in

Choose a time under Settings → Daily check-in. Automatic picks one account-wide time between 7:00 and 21:00, moving a little each day. A time you set uses your configured time zone.

  • The app summarizes posts since the previous run once for internal use. Active personas with memory then read it and their own memory in turn. With no new posts, records due for review, or approaching plans, a persona may stay quiet.
  • Busy periods can delay the start. A missed set time can run until midnight; automatic runs close at 21:00. Missed days are not replayed.
  • An automatic time wrapping from evening to morning skips that day, except on the monthly summary day. A time you set does not have this skip.
  • A silent or failed run still counts as that persona's run for the day. Recent records are read from the previous check-in onward.
  • Check-ins do not use your location, so place search works by name only.

For a persona that prefers the external agent, the external agent writes what to say at check-in (what to ask or tell you). How the memory is tidied is still decided by kakeratta, as always. If the agent does not respond in time, the built-in model writes it instead.

This month's summary, and people looked back on monthly

Once a month, the app reads that month's timeline and posts This month's summary to the timeline. It groups your statements, actions, decisions, and changes by topic. A persona’s suggestion alone is not treated as something you did or planned. Each bullet's → opens the original fragment. The app picks the date per account (somewhere between the 1st and the 28th of each month). The summary is yours to edit with ✎.

On a person's card you can choose Look back frequently or Look back occasionally. A person set to monthly wakes on the day the summary is posted, reading the summary and the fragments where their name or keywords appeared. Even as you add more people, the timeline is read only once a month. When you create personas with the AI, the frequency is chosen from the relationship: daily for family and close friends, monthly for people you meet once in a while. An interest persona is always daily.

Person persona notification rules

From saved or edited basic info and from fragments that reach that person, birthdays, anniversaries, and meetings with clear dates are registered automatically.

  • Birthdays and anniversaries: Reminded every year, 1 week before and on the day at 9:00 AM.
  • Meetings: Any specified reminder time takes precedence; otherwise reminded on the day at 9:00 AM (or 1 hour before if the meeting is earlier than 9:00 AM).
  • Reminders arrive as remarks posted by the persona. There is no day limit on future schedules, and unclear dates are never guessed. Schedule edits and cancellations are reflected too.

A persona's own schedule (schedule)

A persona can wake shortly before an outing whose timing is grounded in your posts or habits, checking belongings and past omissions. When the region and date are known, it reads a fresh forecast: sunshine now can still mean taking an umbrella for rain on the way home. Unknown locations, times and unavailable forecasts are not invented. Chore follow-ups happen shortly afterwards; completed or already-mentioned items stay quiet. It does not nag or recite a generic checklist every day.

A person's persona sets one for the morning of a meeting you mention, such as “drinks with Sato next Saturday.” On waking it brings up what happened last time and anything still open, like a loan or a promise.

  • Up to 20 per persona, at any future date. Tool-created schedules run once or daily; birthdays and anniversaries recur annually.
  • Schedules are listed on the persona's card. Remove one you do not want with ×.
  • A wake is used up even if the persona stays silent or fails. One more than 10 minutes late is skipped.
  • Deleting a fragment makes the persona revisit the schedules it set for it. Pausing or deleting the persona removes its schedules.

Memory architecture and review

A persona's memory is structured as follows:

  • Fragment records: For each fragment received, one line with the date and time, original post, summary, and tags. That is all a conversation adds.
  • Current facts: One line per fact known, including grounded tendencies, conditions, exceptions and changes over time. At check-in (daily, or monthly for people set to monthly), new records are folded into facts (added, rewritten, deleted or merged) and the folded records go; facts that no longer hold are deleted.
  • New persona suggestions: Memory is not split by subject. When a subject of its own builds up, the persona suggests making a new persona for it. Press Create it under the post to add one right away, with its name and scope drafted and the related facts and records moved over; the subject is left out of the original persona's condition, so such posts reach the new persona alone. Press Not now to pass.
  • Lifespan and review: Ephemeral notes such as “today's lunch” expire automatically under Gone on …, while long-unused notes are scheduled for Review on …, where the persona asks “Can I forget this now?” during check-in.

4. Share to Bluesky

Pick the messages you want from a post and its conversation and publish them from your own Bluesky account. Persona messages carry an attribution such as “🍚 tabeからの返信:” (reply from tabe).

Connect your account

  1. Open Settings → Advanced options → Integrations → Bluesky connection, or Share to Bluesky on a post.
  2. Enter your handle (for example alice.bsky.social) and press Connect Bluesky.
  3. Authorize on Bluesky and you return to kakeratta in the same tab. Your password is entered only on Bluesky.

Choose and publish

  1. Press Share to Bluesky on the original post. At first only that post is selected.
  2. You can deselect the original post and publish only an answer. Select at least one message. A reply whose parent is omitted will reply to the first selected message.
  3. Choose Text or Image for each message. The content updates inline automatically. Review it and press Post. Posting is disabled while the preview or images are being prepared.

What is and is not published

  • The selected messages' text, links, source URLs and images are published. Location, image reading results and persona notes are not.
  • Long messages split at sentence breaks into posts of about 300 characters; later parts start with “つづき:” (continued). Images go on the first part only.
  • Headings, lists and tables in persona answers are rewritten as text that reads well on Bluesky, which has no bold or headings. A [text](URL) link keeps its text as the link, and URLs in the text become links too.
  • HTML persona answers and infographic diagrams default to images. You can switch them to text, or share ordinary text as an image. Long answers split into multiple image posts; review every page in the preview. If conversion fails, publishing stops. The original answer stays unchanged.
  • Images over 2 MB are shrunk for sending (the original stays as it is). Transparency becomes white and GIFs become still.
  • Up to 100 messages at a time.

Adding later and disconnecting

  • Published messages are not sent again. Replies you select later are added to the same thread.
  • If the connection drops and the outcome is unknown, publishing stops to avoid duplicates. Check on Bluesky.
  • Disconnect removes the connection. Neither disconnecting nor deleting in kakeratta deletes anything on Bluesky.

5. Hand a persona to an external agent

Once a connection is configured and Use the external agent is enabled in settings, each persona can prefer the external agent. A persona with Prefer the external agent on hands the research and the answer of its turn to an external agent you run yourself, whether it woke for a post or a check-in. Hermes Agent and the Obsidian plugin LLM Connect Hub are supported out of the box; any other agent can connect over MCP Streamable HTTP if it polls for asks, does the research and submits the answer. After receiving the answer, kakeratta handles records and schedules and reviews schedule changes against the answer before publishing. External MCP tools available to personas are read-only. If you have not installed Hermes yet, start with the Hermes integration guide.

Ask the external agent directly

Address @agent, @外部エージェント, or @エージェント to ask the connected agent directly. Replying to its answer starts the next request. This does not update persona memory or schedules.

The request shows waiting or working status; 🔔 controls push notification for its answer. You are notified if it remains unclaimed for two hours or unanswered for two hours after being claimed. Late answers still appear. Edits after work starts are not delivered, so send additions as replies. Available tools and actions depend on the connected agent’s configuration.

Manage connections

One connection is in use at a time. Every persona that prefers the external agent uses the one chosen under Active connection.

  • + Add connection names a connection, issues its key and puts it in use. The key is shown only right after it is issued.
  • Choose another connection in the list to switch. Other connections keep their keys, but a key not in use cannot connect. Asks still waiting to be picked up when you switch are answered by the built-in model.
  • Replace or delete a key on each connection's row.

Connect Hermes

  2. Add it to ~/.hermes/config.yaml on the machine running Hermes and restart Hermes. If mcp_servers already exists, add kakeratta inside it.

Connect Obsidian (LLM Connect Hub)

With LLM Connect Hub, a persona's answer comes from LLM Hub in your Obsidian. It uses the model you choose in LLM Hub and researches your Vault notes, RAG and skills; the vault files it read are cited as [[file name]].

  1. Install and enable LLM Hub and LLM Connect Hub from Obsidian's community plugins (desktop only).
  2. In kakeratta, under Settings → Advanced options → Integrations → External agent connections, name the connection (for example, Obsidian) and press Add and create key.
  3. In LLM Connect Hub's Kakeratta settings, enter the MCP endpoint shown under Connection details and waits. Use Add header to add the name Authorization with the value Bearer CONNECTION_KEY.
  4. Choose the answer model, the Vault folders it may read, the RAG index and the skills. Each persona can override them.
  5. Turn on Check periodically and Enabled, then press Save and reconnect.

LLM Connect Hub checks for asks once a minute while Obsidian is open, and uses no model tokens when there are none. Because it checks once a minute, keep Wait for a claim (how long kakeratta waits for the agent to pick up an ask) longer than a minute. Once Obsidian has been closed for longer than that wait, the agent is taken to be away (see Hand a persona over below) and later asks go to the built-in model without waiting. An ask that arrives just after Obsidian closes is answered by the built-in model when its wait runs out. For the full settings, see the LLM Connect Hub README.

Hand a persona over

  1. In Personas, turn on Prefer the external agent for the persona. The checkbox appears only while a connection is configured and Use the external agent is enabled in settings.
  2. Post as usual. For posts that reach that persona, the external agent researches and writes the answer; kakeratta decides memory and schedules. The reply arrives under the persona's name, marked External agent.

If the external agent does not pick an ask up within 3 minutes, or does not return an answer within 15 minutes of picking it up, the built-in model answers instead.

If the agent has not connected for longer than Wait for a claim (3 minutes by default), it is taken to be away. While it is away, later asks go straight to the built-in model instead of waiting. As soon as it connects again, the next ask goes to it. An agent is never away while it is working on an ask.

Change the waits per agent under each connection's Connection details and waits in Integrations. Turning off Use the external agent there refuses its connections and plans with the built-in model while keeping each persona's choice. The trial reply when you fix how a persona replies always uses the built-in model.

What an external agent can read

An external agent can read your posts and the notes of every persona. For persona asks it submits an answer, while kakeratta manages memory and schedules. It can also post proactively as an active persona that prefers the external agent, up to five posts per persona per day. Those posts do not update persona memory or send notifications. It cannot reach model settings or other users. Deleting the connection invalidates the key.

What the agent reads also goes to the model it uses. If you chose an API model in Hermes or LLM Hub, your posts and notes are sent to that provider. To keep them on your machine, use a local model; note that LLM Connect Hub needs an API model to answer with Vault notes, RAG or skills.

If it cannot connect

  • Restart Hermes after changing its configuration.
  • Check that Hermes can reach the connection URL.
  • If you replaced the key, replace it in config.yaml too.
  • In LLM Connect Hub, look at the connection status in its settings (for example, Kakeratta: connected; 1 ask failed). An ask it failed to answer is answered by the built-in model.

Monthly AI usage

Open Settings → AI usage to see the month's total cost and Web search count. Choose a month and press Refresh for the latest records. The breakdown shows Routing, All personas, and Other. Other includes shared work such as meaning-search embeddings and daily/monthly summaries.

For an individual breakdown, open Personas → AI usage on a persona's card. It separates Replies, Scheduled runs, and Other, including related research, memory updates, and retries. Scheduled runs cover check-ins and reminders. Shared costs such as routing are not allocated to personas.

Costs are estimates in USD. OpenRouter uses API-reported costs; Nebius uses public rates at recording time, excluding discounts and free allowances. Calls without known pricing appear as Unpriced. Web searches count actual API requests, including failures; search charges and the external agent's own AI costs are excluded. Only usage since recording began is included, without importing historical logs. Months without records display an empty-state message.

Profile (display name and icon)

Profile at the top of Settings changes the Display name and Icon shown for you on the timeline and elsewhere. Pick an emoji from the groups or choose a photo, the same way as for persona icons. It is saved with your account, so other devices show the same. An empty name shows as “You” and an empty icon as 🙂. Your sign-in account name does not change.

Backup

Export as zip puts your posts, personas and their notes, persona order, and images into one zip. The download starts when it is ready, and a Download link also appears. The link is valid for an hour. The zip holds personal content, so keep it to yourself.

API keys and the Bluesky and external agent connections are not included.

Close account

Press Delete everything and close the account and type “delete” to confirm. This removes the account's posts, personas and notes, images, settings, connections, backups, and the login account itself. It cannot be undone, so export a backup first.

AI models

With Nebius Token Factory these models are used for each job; there is nothing to choose in Settings.

JobModel
Routing, built-in research (except for “in detail” requests and Always think deeply), ordinary replies, the note keeperNemotron 3 Super
Research for “in detail” requests and Always think deeply, schedule planning and review, final answers for Always think deeply, daily and monthly check-ins, memory tidying, the day's and month's summariesNemotron 3.5 Super VL
Final answers for deep requestsNemotron Ultra
Optional dictation polishingNemotron 3.5 Lightning

Personas with Always think deeply on use Super VL for final answers to ordinary requests too. A request containing words such as “in detail” or “deep dive” gets an Ultra final answer. Thanks and ordinary follow-ups use the normal model unless Always think deeply is on.

Research uses Super, or Super VL for deep requests such as “in detail” and for Always think deeply; schedule planning uses Super VL. Each answer can only look things up (read or search the Web) a limited number of times; deep requests and personas with Always think deeply get a higher limit. Tools that are not set up, and memory searches for personas without memory, are not used.

Using OpenRouter

Under Advanced options → Models → Use OpenRouter, enter an API key and check the connection.

  • Check Use OpenRouter to use OpenRouter for Router, High, Middle, Low, and image analysis. Unchecking retains the API key and model choices, so you can switch providers for comparison.
  • After checking the connection, use Image analysis model to search for and select a model that supports image input. Unset selections use GLM-5.3-Flash, as before. Turning OpenRouter off retains your selection.
  • For Jev routing, select ~typesafe/jev-latest as the Router model. Jev does not show decision reasons.

7. Tools personas use

A persona picks the tools it needs for a reply or a note. Ask in ordinary words; you never type tool names. A persona you mention with @name always replies, but which tools it uses is its own choice.

ToolPurposeWho / setup
timeline_searchSearch past fragmentsEvery persona
recordsFind older fragment records (the app keeps the memory)Memory-enabled personas
web_searchSearch the WebPersonas it is added to; Tavily API key
place_searchFind shops and placesPersonas it is added to
weather_forecastCurrent weather and forecastsPersonas it is added to; a place name or location on the post
schedulePick its own wake timePersonas it is added to

A persona's tools are listed under Tools in the Personas panel. To add one, use Edit with AI (“let it search the Web too”), review the change and save.

Tools run on the kakeratta server. If you allow location, coordinates go to the server and, for place search, to an external map service. Notes and search results a persona reads also go to the AI model as input.

Search past fragments — timeline_search

Searches your saved posts, text read from images, and replies by words and meaning together. A period can narrow it, or alone read everything written in it. Each call returns up to 30 results. Only the posts a persona uses as its grounds are linked under its remark.

Try: “@tabe Find that light red wine I enjoyed before.”

Finding fragment records — records

Every turn, a persona reads the facts that hold now, and its latest records before it thinks. Older records it finds by tag, words, or meaning, and it can read the post a record points to (with the fragment it answered, for a reply). The app adds a record after a reply, then folds new records into facts at check-in. To inspect or delete memory, use What I remember.

Try: “@tabe Which ramen place did I say I wanted to try?”

Web search — web_search

Searches news, technical information and more, and cites result links as sources. Save a Tavily API key under Settings → Web search (separate from the AI key). It works from result summaries and does not necessarily read whole pages.

Try: “@shiori Search the Web for this book's author.”

Place search — place_search

With a location on the post it searches nearby shops and places; without one, it looks places up by name. Places missing from the map cannot be found, and it cannot tell whether a shop is open now or has seats. Finding nothing does not mean there is nothing.

Try: with location on, “@tabe Find ramen near me.”

Weather forecast — weather_forecast

Looks up current weather and daily forecasts from WeatherAPI.com using a place name or the location on the post. A date and local hour can be selected. The available forecast period depends on the provider's subscription; dates outside the returned forecast are unknown. Add “Check the weather forecast” to the persona's tools to use it.

Try: “@sona Is rain likely in Tokyo around 6 pm tomorrow?”
