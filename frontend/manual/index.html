kakeratta の使い方

日々のかけらを、ひとつのタイムラインへ放り込む。人や関心ごとに置いた、自分とは別の記憶を持つ AI（担当）が、言うことがあるときだけ反応し、必要なときに思い出させます。

このページは毎日使う機能だけをまとめています。振り分けや返し方の調整、Bluesky・Hermes との連携、設定の詳細は 上級編 にあります。

1. はじめる

  1. アプリを開きます。Google アカウントでログインします。データはあなたのアカウントにだけ結びつき、ほかの人からは見えません。
  2. 右上の 設定 を開き、Nebius Token Factory で発行した API キー を入力します。「接続できました」と出れば準備完了です。
  3. 画面の上に「担当が誰もいません」と出ていたら、「〇〇 を呼ぶ」 で 1 人以上呼びます。誰もいないと、かけらは誰にも届きません。
  4. 欄に一言書いて 流す。これが最初のかけらです。

API キーはサーバー側にだけ保存され、設定した接続先以外へは送られません。

2. かけらを放り込む

書く、貼る、URL、話す。どれも同じひとつの欄から入ります。

入れ方やり方
書く欄に書いて 流す。Ctrl（⌘）+Enter でも送れます。
画像PC はスクリーンショットを Ctrl+V で貼るだけ。スマホは 📷 画像 からスクリーンショットを選ぶか、その場でカメラで撮ります。画像の文字は読み取られ、あとから検索できます。
URLURL を書いて流すと、公開ページの本文を読み込みます。
話す🎙 話す で音声入力します（7. 音声入力と読み上げ）。

Kindle も有料記事も SNS も、画面に出ていればスクリーンショットで放り込めます。一言と画像を一緒に送ることもできます。投稿に自動で添えられるのは「今どこで何時か」だけです。行き先や時刻は文面に書けば担当が読み取ります。位置情報は任意です。

3. 反応を読む・返す

反応の届き方

  • 担当の反応は少し遅れて届きます。反応が付かないこともあります。 担当は喋らずに覚えるだけのこともあるからです。
  • 必ず答えてほしいときは @名前 で指名します（例：@tabe）。指名された担当は必ず返事をします。担当の名前が並んだバーを押すと、@名前 が書き込まれます。
  • 担当の発言や自分の返信は 返信 N件 の下にたたまれます。表示中に届いた発言は、そのスレッドが自動で開きます。

返す・直す・消す

ボタンできること
一言足す自分の投稿に続けて書く
返す担当の発言に返事をする
✎ / ×投稿を編集する / 削除する
⚖誰に届き、誰になぜ届かなかったかを見る（振り分けを直す）
返し方を直す担当の口調や指示を直す（返し方を直す）
🔈 読み上げ溜まった反応を順に読み上げる

投稿を削除すると、その下の担当の発言と自分の返信も消え、検索にも出なくなります。その投稿だけをもとに書かれた担当のメモも一緒に消えます。 ほかの投稿ももとにしているメモは残り、担当があとで整理します。

4. 担当を選ぶ・作る

担当は、一人の人物か一つの関心ごとについて、別々の記憶を持つ AI です。人物の担当にはその人の名前が出たかけらが、関心ごとの担当には本体が振り分けたかけらが届き、そのうえで覚えるか、喋るかを各担当が決めます。担当同士でメモは共有しません。

最初からいる 4 人

名前分野受け取るもの
@tabe食事店、料理、飲み物、食事やメニューの写真、「何食べよう」
@michi移動行き先、経路、所要時間、待ち合わせ、旅程、チケット
@shiori読書電子書籍のキャプチャ、引用、書名と著者、読んだ感想
@planaやること薬、金魚の餌、洗濯のような繰り返し。「仕事帰りに花を買おう」のような一度きりの用と、したかどうか

ヘッダーの 担当 で一覧を開き、有効にする で受け取る担当を選びます。担当は投稿された言語で答えます。

AI と担当を作る

  1. 担当 を開き、AIと担当を作る を選びます。
  2. 「どんなことの担当を作りたい？」に自分の言葉で答えます。「ワイン」だけでも始められます。
    例：美味しかったワインのラベルを送るので、銘柄やブドウ品種を教えてほしい。
  3. AI が名前、話し方、覚えることの下書きを作ります。確認して この内容で保存。
  4. 有効にする と、以後のかけらを受け取り始めます。

人物の担当

母や友人のように、特定の一人を覚える担当も作れます。AIと担当を作る で「友人の佐藤さんのことを覚えてほしい」のように頼むと、人物の担当の下書きができます。今ある担当を 修正 で 人物の担当 にすることもできます。

  • 人物の担当は、本体の振り分けを通りません。 かけらに 呼び名 か キーワード がそのまま書かれているときだけ届きます。写真から読み取った文字も対象です。@呼び名 で指名することもできます。
  • 全角・半角、ひらがな・カタカナ、末尾の「さん」「くん」などは区別しません。「佐藤」を登録すれば「佐藤くん」「さとうさん」にも届きます。
  • 名前を出さない話も拾えるよう、キーワードには言い換えや似た言葉を並べます（例：釣り、つり、釣行、海釣り）。AI で作ると、呼び名の書き方の違いとキーワードの似た言葉をまとめて入れます。
  • 「母」で「母校」の話が届くように、文字が合っただけで届くことがあります。担当はその人の話かを確かめ、関係なければ何もしません。
  • 人物の担当はその人について分かったこと（好み、誕生日など）と、その人との出来事（会話、贈り物、約束、貸し借り）を覚えます。貸し借りや約束は、済んだと分かるまで忘れません。
  • 作るときに伝えたことも覚えます。「恋人の nagomi。11/10生まれで、辛いタイ料理が好き」のように書くと、その人についての事実は担当の設定ではなく かけらとして残すこと に分けて出ます。保存すると、それが @呼び名 付きのかけらとして投稿され、担当はそこからメモを作ります。メモからは元のかけらに戻れます。AIで修正で伝えたことも同じです。
  • 会う予定を書くと、担当はその日の朝に起きて、前回の出来事や済んでいないことを一言添えて知らせます。人物の担当は、この予定を置く道具のほか、Web 検索、お店や場所の検索、行き方の検索も最初から使えます。贈り物や会う場所を調べるためです。
  • 誕生日や記念日が分かると、その1週間前に知らせます。 これまでの贈り物やその人の好みから思いつくことも添えます。
  • 話し方、覚え方、約束や予定の扱いはすべての人物の担当で共通で、本体が決めます。担当ごとに書くのは 関係性（恋人、母、大学時代の友人など）と、必要なら この人についての指示（「健康の話は控えめに」など）だけです。

担当 の一覧は 人物 と 関心ごと のタブに分かれ、どちらも名前や担当条件、呼び名、キーワードで検索できます。ひらがな・カタカナや全角・半角は区別しません。人物のタブは 名前順 にも並べられ、漢字の名前はかなの呼び名（「青木」なら「あおき」）の読みで並びます。

届かなかったかけらがあれば ⚖ の 呼んでほしかった からキーワードを足せ、関係のないかけらが届いたら 呼んでほしくなかった から一致した語を外せます（人物の担当のキーワードを直す）。

使いながら直す

担当の AIで修正 から「もっと短く返事してほしい」「なぜ気に入ったかも覚えてほしい」のように頼めます。組み込みの担当も同じように変えられ、それまでのメモはそのまま残ります。

担当の 削除 は、その担当のメモも一緒に消します。元に戻せません。受け取りを止めたいだけなら、有効にする をOFFにしてください。

毎日のチェックイン

有効な担当は、毎日1回、7時〜21時のどこかで起きてメモを整えます。時刻は担当ごとに本体が決め、日ごとに1時間以内で少しずつずれていくので、設定はいりません。初期状態では、最近の記録と古いメモを見直して、伝える価値があることを見つけたときに話します。チェックインでは最低限のことだけ話す をONにすると、話しかけるのは見直しの日が来たメモを忘れてよいかの確認など、あなたの判断が必要なときだけになります。何もなければ黙ります。

話す量を変えるには、担当 を開き、対象の担当の チェックインでは最低限のことだけ話す を切り替えます。変更は自動で保存されます。

時刻は、この端末のタイムゾーンで数えます。ブラウザを閉じていても、サーバーが動いていれば実行されます。

チェックインとは別に、plana のように担当が自分で起きる時刻を決めることもあります。詳しくは 担当が起きるタイミング を見てください。

今月のまとめと、月1回振り返る人物

月に1回、本体がその月のタイムラインを読み、今月のまとめ をタイムラインに投稿します。話題ごとの箇条書きで、各項目の → から元のかけらを開けます。日付は本体がアカウントごとに決めます（毎月1〜28日のどこか）。まとめはあなたのものとして ✎ で直せます。

人物の担当は、カードで 毎日振り返る か 月1回振り返る を選べます。月1回にした人物は、まとめが書かれた日に起き、まとめと、その人の名前やキーワードが出たかけらを読んで振り返ります。人物が増えても、タイムラインを読むのは月に1回で済みます。AI と担当を作ると、家族や親しい人は毎日、たまに会う人は月1回のように、関係性から選ばれます。関心ごとの担当は毎日です。

5. 覚えていることを確かめる

担当の 覚えていること を開くと、保存されたメモを種類ごとに読めます。表示のためにAIで要約し直すことはなく、担当が書いたままの内容です。

メモの見方

  • 記憶を更新した投稿 のリンクで、そのメモのもとになった投稿と会話を開けます。
  • タグを押すと、そのタグのメモだけに絞り込めます。すべてのメモを表示 で戻ります。
  • タイムラインの担当の発言の下にある 📝 は、その発言と一緒に書いたメモです。押すとそのメモが開きます。
  • 投稿へのリンクがない古いメモは、元の投稿を探す で検索できます。

間違いを直す・消す

したいこと操作
メモの誤字や事実の誤りを直すメモの見出しの ✎ で原文を編集し、メモを保存
メモを1件だけ消すこのメモを忘れさせる
その担当のメモを全部消すすべてのメモを忘れさせる
今後の覚え方を変える担当の AIで修正 で頼む

削除は元に戻せません。消したことでも、残っている投稿を担当が検索して、また覚えることがあります。

たとえば「このワインが好き」という誤ったメモは個別に消し、「一度飲んだだけで好みと決めない」というルールは AIで修正 で伝えます。AIで修正しても、すでにあるメモは書き換わりません。

6. 検索する

ヘッダーの 検索 を開きます。「ピノ」のような名前も、「軽くて飲みやすかった赤ワイン」のような言い方も、同じ欄に入れられます。

  • 短い語句はキーワードで、質問や文章は意味の近さで探します。結果の画面から探し方を切り替えられます。
  • 探す対象は、自分が書いた本文、画像から読み取った文字、担当との会話です。
  • 結果を押すと、元の投稿と会話が開き、そこから返信も書けます。

担当も必要なときに過去のかけらを検索し、「前に気に入ったピノに近いですね」のように元の投稿へのリンク付きで答えることがあります。

7. 音声入力と読み上げ

  • 🎙 話す を押すと、ブラウザの音声認識で聞き取ります。無音が続くと自動で止まります。
  • 送信の合図（例：「以上」）を決めておくと、文の最後にそう言った時点で投稿されます。
  • 自動送信前にAIで文章を整える をONにすると、合図で送るときだけ、句読点や言いよどみを整えます（初期状態はOFF）。
  • 🔈 読み上げ は、溜まった反応を順に読み上げます。

合図、無音での停止、声と速さは 設定 → 上級オプション → 音声 で変えられます。

8. オフラインで使う

一度オンラインで開いた端末なら、電波がなくても文章・画像・URL・返信を書けます。書いたものは「端末に保存済み・送信待ち」として残り、アプリを開いている間に接続が戻ると自動で送られます。担当の反応は、サーバーに届いてから始まります。

  • 送信に失敗したときは 接続して再送 でやり直せます。二重に投稿されることはありません。
  • 送信待ちは、ブラウザのデータを消すと失われます。ログアウトするときは確認のうえ、この端末の保存データを消します。
  • 直近20件の会話は端末にも保存され、次に開いたときすぐ表示されます。

9. 困ったとき

反応が付きません。
担当が誰も有効でないか、どの担当の分野にも当たらなかったか、担当が「覚えるだけ」にしたのかもしれません。⚖ で誰に届いたかを確認できます。必ず答えてほしいときは @名前 で指名してください。
設定画面が閉じられません。
AI の接続が済むまでは閉じられません。API キーを入力してください。
検索で「語句の一致で探しました」と出ます。
意味で探す準備が終わっていないか、接続できない状態です。語句で見つかった結果は表示されています。少し待ってから検索し直してください。
画像の文字が読めていません。
読み取りには少し時間がかかります。しばらくして投稿の「読み取り結果」を開いてください。画像は1投稿あたり 20 MiB までです。
データはどこに保存されますか。
アカウントごとに分かれたサーバー上に保存され、ほかの人からは見えません。手元に保存したいときは 設定とデータ を見てください。

kakeratta 上級編

担当の振り分けや返し方の調整、担当が起きるタイミング、Bluesky・Hermes との連携、設定とデータ、担当が使う道具を説明します。毎日の使い方は 基本の使い方 を見てください。

1. 振り分けを直す

かけらをどの担当に渡すかは本体が決めます。自分の投稿や返信の ⚖ を押すと、呼ばれた担当と、呼ばれなかった担当ごとの一行の理由が出ます。@名前 で指名した担当は、あなたが選んだので出ません。

呼ばれた担当には、処理が終わったか、返事をしたか、メモを残したかが出ます。黙っていた担当には 返事がほしかった から 返し方を直す 流れに入れます。

担当の条件を直す

  1. 行の 呼んでほしかった（または 呼んでほしくなかった）を押します。
  2. 理由やどう変えてほしいかを書き、条件を作る を押します。AI が担当の判定条件だけを書き直します。
  3. 新しい条件は手で直せます。AIに変更を依頼 で書き直しを頼むこともできます。
  4. OK で保存すると、同じ投稿で振り分けを試します。「呼んでほしかった」で狙いどおり呼ばれたら、その担当に元の投稿を渡して返事やメモを残します。違えば理由を見てやり直します。

変わるのは判定条件だけで、口調や覚え方は変わりません。振り分けに Jev を使っている場合（設定とデータ）は理由が表示されませんが、条件は同じ手順で直せます。

人物の担当のキーワードを直す

人物の担当には判定条件がなく、呼び名かキーワードが書かれたかけらだけが届きます。⚖ には、どの語で届いたかが「「佐藤さん」に一致」のように出ます。

  1. 届かなかった人物の担当の行で 呼んでほしかった を押します。今のキーワードが出ます。
  2. どの語で呼んでほしいかを書き（空でもかまいません）、キーワードを作る を押します。AI がそのかけらに書かれている語を選び、似た言葉とあわせて足すキーワードを出します。
  3. 足すキーワードは手で直せます（読点区切り）。AIに変更を依頼 もできます。
  4. OK で今のキーワードに足して保存し、同じかけらで確かめます。足した語がかけらにあれば、その担当に元のかけらを渡します。なければそう伝えるので、やり直します。

関係のないかけらが語の一致で届いたときは、呼ばれた人物の担当の行で 呼んでほしくなかった を押します。

  1. 呼び名とキーワードのうち、そのかけらに一致した語が並びます。担当の名前そのものは表示だけで、ここでは外せません（担当の 修正 で変えます）。
  2. 外す語にチェックを入れて 外す を押します。保存して同じかけらで確かめ、ほかの語でもまだ一致するなら、その語を伝えるので続けて外せます。
  3. 外さないなら 残す で閉じます。その人と関係のないかけらなら、担当はもともと発言もメモもせずに終えます。

外した語だけを含むかけらは今後届かず、外した呼び名は @ での指名にも使えなくなります。そのかけらに担当がすでに残した発言やメモは消えません。

2. 返し方を直す

担当の発言の 返し方を直す を押し、期待とどう違うかを書きます。AI が担当の 口調 と 指示 だけを書き直します。判定条件、名前、道具は変わりません。

  1. 違いを書いて 直し方を作る を押します。
  2. 新しい口調と指示は手で直せます。AIに変更を依頼 で書き直しを頼むこともできます。
  3. OK で保存すると、同じ投稿で担当が試し書きをします。タイムラインには載らず、メモも予定も書かれません。数分かかることがあります。
  4. これでよい で試し書きの返事とメモ変更を元のスレッドに反映します。まだ違う なら、試し書きを見ながらもう一度伝えます。

保存した口調と指示は、試し書きの結果にかかわらずそのまま残ります。

3. 担当が起きるタイミング

担当が動くのは、次の3つのときです。

きっかけ決める人内容
かけらが届いたとき本体（振り分け）分野に当たる担当と、@名前 で指名された担当が動きます。人物の担当は、呼び名かキーワードが書かれているときに動きます。
毎日のチェックイン本体有効な担当が、7時〜21時のどこかで1日1回起きます。月1回振り返る人物は、今月のまとめの日に起きます。
担当が預けた予定担当schedule を持つ担当が、自分の記録から時刻を決めて起きます。

チェックインの細かい動き

  • サーバーは毎分確認するので、混み具合によって少し遅れることがあります。
  • その日の時刻を過ぎてから担当を有効にした場合は、その日の分をすぐ実行します。21時を過ぎたら、その日の分は見送ります。サーバーの再起動後も当日分だけを実行し、過ぎた日の分はまとめて実行しません。
  • 担当が黙った場合や失敗した場合も、その日の1回に数えます。メモを消しても、同じ日にもう一度は起きません。
  • 時刻が夜から朝へ回り込む日（前の日 20時台 → その日 7時台など）は、数時間おきに2回起きないよう、その日を休みにします。
  • 最近の記録は、前回のチェックインから今までの分を読みます。休んだ日や見送った日があっても、その間の記録を取りこぼしません。
  • チェックインでは現在地を使わないので、経路検索はできず、店舗検索は名前での検索だけになります。

「外部エージェントを優先する」をONにした担当では、チェックインで何を整え、何を聞くかを Hermes が考えます。時間内に Hermes が応じなければ、内蔵モデルが代わりに考えます。

担当が預けた予定（schedule）

たとえば plana は、記録から「朝の薬は7時半ごろ」と分かったものにだけ予定を置き、その少しあとに起きます。まだ記録がなければ「そういえば朝の薬」と一言添え、済んでいれば黙ります。時刻の前に知らせるリマインダーではなく、催促もしません。あなたから「毎朝8時に知らせて」と頼む機能でもありません。

人物の担当は、「来週土曜、佐藤さんと飲む」のような会う予定が書かれると、その日の朝に予定を置きます。起きたら前回の出来事や済んでいないこと（貸し借り、約束）を一言添えて知らせます。

  • 担当ごとに20件まで、30日先まで、1回きりか毎日です。
  • 予定は担当のカードに並びます。不要な予定は × で消せます。
  • 起きた回は、担当が黙っても失敗しても消費されます。予定より10分以上遅れた回は実行しません。
  • メモを消すと、担当が予定を見直します。担当を停止・削除したとき、メモを全部消したときは、その担当の予定も消えます。

4. Blueskyに公開する

自分の投稿と担当との会話から、見せたい発言だけを選んで、自分の Bluesky アカウントから投稿できます。担当の発言には「🍚 tabeからの返信:」のような署名が付きます。

アカウントをつなぐ

  1. 設定 → 上級オプション → 外部連携 → Bluesky連携、または投稿の Blueskyに投稿 を開きます。
  2. 自分のハンドル（例：alice.bsky.social）を入れて Blueskyと接続 を押します。
  3. Bluesky の画面で許可すると、同じタブで kakeratta に戻ります。パスワードは Bluesky 側にだけ入力します。

会話を選んで公開する

  1. 元の投稿の Blueskyに投稿 を押します。最初は元の投稿だけが選ばれています。
  2. 公開する発言を選びます。返信を選ぶときは、その返信先も選んでください。
  3. プレビュー で分割のされ方や返信のつながりを確かめ、選択した会話を投稿 を押します。

公開されるもの・されないもの

  • 公開されるのは、選んだ発言の本文・リンク・出典URL・画像です。位置情報、画像の読み取り結果、担当のメモは公開されません。
  • 長い発言は、文の切れ目で300文字程度ずつに分け、2つ目以降に「つづき:」を付けます。画像は最初の1つにだけ付きます。
  • 2 MB を超える画像は送信用に縮小されます（元の画像はそのまま）。透明部分は白に、GIF は静止画になります。
  • 一度に選べるのは100発言までです。

あとから足す・やめる

  • 公開済みの発言は再送されません。あとで選んだ返信だけを追加で投稿できます。
  • 通信が切れて結果が分からないときは、二重投稿を防ぐために止まります。Bluesky 側で確かめてください。
  • 接続を解除 でつながりを外せます。解除しても、kakeratta で投稿を消しても、Bluesky の投稿は消えません。

5. 担当の考える役をHermesにする

担当ごとに「外部エージェントを優先する」を選べます。ONにした担当は、投稿やチェックインで起きたとき、文脈を読んで次に何をするか（workflow）を考える部分を自分の Hermes に任せます。kakeratta はその workflow を確認してから、担当として実行します（メモ・予定・発言）。Hermes をまだ入れていない場合は、先に Hermes連携の手引き を見てください。

つなぐ

  1. 設定 → 上級オプション → 外部連携 → 外部エージェント連携（Hermes） で 接続キーを発行 し、表示された設定をコピーします。キーを確認できるのは発行直後だけです。
  2. Hermes を動かす端末の ~/.hermes/config.yaml に追加し、Hermes を再起動します。すでに mcp_servers があれば、その中に kakeratta を足します。
  3. Hermes に kakeratta の Skill と Wake Gate を入れ、毎分確認するよう設定します（手順は手引きにあります）。
mcp_servers:
  kakeratta:
    url: "画面に表示された接続URL"
    headers:
      Authorization: "Bearer 画面に表示された接続キー"

担当を任せる

  1. 担当 画面で、任せたい担当の 外部エージェントを優先する をONにします。このチェックは接続キーを発行したあとにだけ表示されます。
  2. いつもどおり投稿します。その担当に届いた投稿は Hermes が考え、返事は担当の名前で「外部エージェント」の印付きで届きます。

Hermes が3分以内に取りに来ない、または15分以内に workflow を返さないときは、内蔵モデルが代わりに考えます。取得を待つ時間のあいだ Hermes から一度も接続がなければ応答なしとみなし、次に接続があるまで待たずに内蔵モデルが考えます。時間は 外部連携 で変えられます。同じ場所の 外部エージェントを使う をOFFにすると、担当ごとの設定を残したまま一時的に内蔵モデルで考えます。試し直しは常に内蔵モデルで行います。

Hermes が読めるもの

Hermes は、あなたの投稿と すべての担当のメモ を読めます。自分で投稿したりメモを書いたりはできず、書き込みはすべて kakeratta が確認した workflow を通ります。モデル設定や他の利用者のデータには触れません。連携を解除 で接続キーが無効になります。

つながらないとき

  • 設定を変えたあと Hermes を再起動したか確認してください。
  • Hermes から接続URLに届くか確認してください。
  • キーを再発行したら、config.yaml も置き換えてください。

バックアップ

zipに書き出す で、投稿、担当とメモ、担当の並び、画像をひとつの zip にまとめます。準備ができるとダウンロードが始まり、ダウンロード のリンクも表示されます。リンクは1時間有効です。個人的な内容を含むので、他人に渡さないでください。

API キーや Bluesky・Hermes の接続は入りません。

利用停止（退会）

すべて削除して利用を停止する を押し、確認のため「削除」と入力すると、このアカウントの投稿・担当とメモ・画像・設定・接続・バックアップ、ログインのアカウント自体が消えます。元に戻せないので、先にバックアップを取ってください。

AI のモデル

Nebius Token Factory では、用途ごとに次のモデルを使います。設定画面で選ぶ必要はありません。

用途モデル
振り分け、担当のふだんの返事、担当が出した操作の確認Nemotron Super
「違う」「もっと詳しく」と返されたときの返事Nemotron Ultra
返信が「考え直して」という依頼かの判定Nemotron 3.5 Lightning
画像の読み取りGLM-5.3-Flash

担当の発言に「違う」「もう少し詳しく」などと返すと、考え直しの依頼かどうかを判定し、そうであれば返信先の担当が Ultra で答え直します。お礼やふつうの追加質問はそのままです。

OpenRouter を使う

上級オプション → モデル → OpenRouterを使う で API キーを入れて接続確認します。

  • Jevを有効にする：振り分けだけを Jev に切り替えます。担当の返事は Token Factory のままです。Jev は振り分けの理由を表示しませんが、条件の直し方 は同じです。
  • OpenRouter専用モード：担当の返事に使うモデルも OpenRouter に切り替えます。

7. 担当が使う道具

担当は、返事やメモに必要な道具を自分で選んで使います。ふだんの言葉で頼めばよく、道具の名前を書く必要はありません。@名前 で指名された担当は必ず返事をしますが、どの道具を使うかは担当が決めます。

道具できること使える担当・必要な設定
timeline_search過去のかけらを検索すべての担当
notes_*自分のメモの一覧・読み取り・保存・削除すべての担当
web_searchWeb 検索道具に追加した担当。Tavily の API キー
place_search店や場所を探す道具に追加した担当
route道のりと所要時間道具に追加した担当。投稿の位置情報
schedule自分が起きる時刻を預ける道具に追加した担当

担当が使える道具は、担当パネルの 道具 に出ます。増やしたいときは AIで修正 で「Web検索も使えるようにして」のように頼み、変更案を確かめて保存します。

道具は kakeratta のサーバーで動きます。位置情報を許可すると、座標がサーバーへ送られ、店や経路を探すときに外部の地図サービスへ渡ります。担当が読んだメモや検索結果は、AI モデルへの入力にも含まれます。

過去のかけら検索 — timeline_search

保存した投稿、画像から読み取った文字、返信を、語句と意味の両方で探します。期間を指定して、その間の記録をまとめて読むこともできます。一度に返るのは30件までです。検索で見つかった投稿のうち、担当が根拠にしたものだけが発言の下にリンクされます。

例：「@tabe 前に飲んで気に入った、軽い赤ワインを探して」

メモの読み書き — notes_list / notes_read / notes_write / notes_forget

担当が自分のメモを一覧し、読み、1件ずつ保存・削除します。何を覚えるかは担当が決め、黙ってメモだけ更新することもあります。中身の確認や確実な削除は 覚えていること から行います。

例：「@tabe 辛いものは好きだけど、ごまが強い味は苦手。覚えておいて」

Web検索 — web_search

ニュースや技術情報などを検索し、結果のリンクを出典として付けます。設定 → Web検索 に Tavily の API キーを入れて使います（AI の API キーとは別）。検索結果の要約を使うので、リンク先の全文を読むとは限りません。

例：「@shiori この本の著者についてWebで調べて」

店舗・場所検索 — place_search

投稿に位置情報があれば周りの店や場所を、なければ名前で場所を探します。地図に載っていない店は見つからず、営業中かどうかや空席は分かりません。見つからなくても「店がない」とは限りません。

例：位置情報付きで「@tabe この近くのラーメン屋を探して」

経路検索 — route

投稿の位置から目的地までの、車・徒歩・自転車での道のりと所要時間の目安を調べます。電車やバス、時刻表、渋滞は含みません。位置情報のない投稿やチェックインでは使えません。本文に出発地を書いても、位置情報の代わりにはなりません。

例：「@michi ここから渋谷駅まで徒歩で何分？」

Using kakeratta

Toss fragments of your day into one timeline. AIs you keep for the people and interests in your life, each with a memory separate from yours, called personas, react only when they have something to say and bring things back when they matter.

This page covers what you use every day. Fixing routing and replies, Bluesky and Hermes, and settings in detail are in the advanced guide.

1. Getting started

  1. Open the app. Sign in with your Google account. Your data is tied to your account and nobody else can see it.
  2. Open Settings at the top right and enter an API key from Nebius Token Factory. “Connected” means you are ready.
  3. If the screen says “Nobody is in the room”, call in at least one persona with Call in …. With nobody in the room, a fragment reaches no one.
  4. Write a line in the box and press Post. That is your first fragment.

The API key is stored only on the server and sent only to the configured endpoint.

2. Tossing in a fragment

Write, paste, post a URL, or speak. Everything goes through the same box.

Way inHow
WriteType and press Post, or Ctrl (⌘) + Enter.
ImageOn a PC, paste a screenshot with Ctrl+V. On a phone, pick a screenshot with 📷 Image or take a photo there and then. Text in the image is read and becomes searchable.
URLPost a URL and the body of the public page is read.
Speak🎙 Speak starts voice input (7. Voice input and read-aloud).

Kindle, a paywalled article, a social feed: if it is on screen, a screenshot brings it in. An image can go with a line of text. Only where you are and what time it is travel with a post automatically; destinations and times belong in what you write. Location is optional.

3. Reading and replying

How reactions arrive

  • Reactions arrive a little later. Some posts get no reaction: a persona can remember something without speaking.
  • For a guaranteed answer, mention a persona with @name (for example @tabe). A persona you mention always replies. Tapping a name in the persona bar writes the mention for you.
  • Persona remarks and your replies fold under N replies. A remark that arrives while you are looking opens its thread by itself.

Reply, fix, delete

ButtonWhat it does
Add a commentContinue your own post
ReplyAnswer a persona
✎ / ×Edit / delete a post
⚖See who got the post and why the others did not (Fix who gets a post)
Change how it repliesCorrect a persona's tone and instructions (Fix how a persona replies)
🔈 Read aloudRead the collected reactions in order

Deleting a post removes the remarks and your replies under it, and it no longer appears in search. Persona notes that rest only on that post are deleted too. Notes that also rest on other posts stay, and the persona tidies them later.

4. Choosing and creating personas

A persona is an AI with its own memory for one person or one interest. A person's persona gets the fragments that mention them; an interest's gets the ones the app routes to it. Each then decides whether to remember and whether to speak. Personas do not share notes with one another.

The four that ship with the app

NameSubjectWhat it receives
@tabefoodPlaces, dishes, drinks, photos of meals and menus, “what should I eat”
@michitravelDestinations, routes, travel time, meeting times, itineraries, tickets
@shiorireadingE-book captures, quoted passages, titles and authors, thoughts on a read
@planafollow-upsMedicine, feeding the goldfish, laundry - and one-offs like buying flowers on the way home, and whether they happened

Open Personas in the header and turn on Enable for the ones you want. A persona answers in the language you wrote in.

Create a persona with AI

  1. Open Personas and choose Create a persona with AI.
  2. Answer “What would you like your persona to help with?” in your own words. Even “wine” is enough.
    Example: When I send a photo of a wine label I liked, tell me the wine and its grape varieties.
  3. The AI drafts a name, a way of talking, and what to remember. Review it and select Save this persona.
  4. Enable it and it starts receiving fragments.

People

A persona can also keep one person in mind - your mother, a friend. Ask Create a persona with AI something like “Remember things about my friend Sato” and the draft is a person's persona. An existing persona can be turned into one with Edit and Keeps a person.

  • A person is never routed by the app. A fragment reaches it only when one of its names or keywords is written in it, text read from a photo included. You can also call it with @name.
  • Width, case, hiragana against katakana and a trailing さん or くん do not matter: 佐藤 also reaches 佐藤くん and さとうさん.
  • To catch posts that do not name them, list rewordings and near words as keywords (fishing, angling, sea fishing). The AI fills in the other spellings of the names and the near words of the keywords.
  • A word can match by accident, as 母 (mother) does in 母校 (alma mater). The persona checks whether the post is about the person and does nothing if it is not.
  • A person's persona remembers what it learns about them (tastes, birthday) and what happens with them (talks, gifts, promises, loans). Loans and promises are kept until you say they are settled.
  • What you tell it when making it is remembered too. Write something like “My partner nagomi. Born on 10 November, loves spicy Thai food” and the facts about them come out apart from the settings, under Keep as a fragment. Saving posts them as a fragment with @name, and the persona makes its notes from it, each leading back to that fragment. The same goes for what you tell Edit with AI.
  • Mention meeting them and the persona wakes that morning to bring up what happened last time and anything still open. Besides placing wakes, a person's persona starts with web search, place search and routes, to look up presents and places to meet.
  • Once it knows a birthday or an anniversary, it tells you a week before, with an idea drawn from past gifts and what they like.
  • How a person's persona speaks, what it keeps and how it handles promises and meetings are the same for every person, set by the app. Each one has only a relationship (partner, mother, a friend from university) and, if you like, instructions for this person (“go easy on health topics”).

The Personas panel has a People tab and an Interests tab, and each can be searched by name, condition, names or keywords; kana and width do not matter. People can also be put By name, a name in kanji going by the kana among its names.

If a fragment did not reach them, add keywords from Should have been called in ⚖; if an unrelated one did, remove the matched word from Should not have been called (Fix a person's keywords).

Adjust as you go

Use Edit with AI on a persona to say “Give shorter replies” or “Remember why I liked a wine, too.” Built-in personas can be edited the same way, and their notes carry over.

Delete removes the persona together with its notes, and cannot be undone. To stop it receiving posts, just turn off Enable.

Daily check-ins

Every active persona wakes once a day, somewhere between 7:00 and 21:00, to tidy its notes. The app picks each persona's time, drifting by an hour a day at most, so there is nothing to set. By default it looks over recent records and older notes and speaks when it finds something worth sharing. With At check-in, speak only when needed on, it speaks only when your decision is needed, such as whether a note that has reached its review date can be forgotten. Otherwise it stays quiet.

To change how much it says, open Personas and toggle the persona's At check-in, speak only when needed. Changes save automatically.

The hours are counted in this device's time zone. The browser can be closed; the server runs the check-in.

Some personas, such as plana, also pick their own wake times. See When personas wake.

This month's summary, and people looked back on monthly

Once a month the app reads the month's timeline and posts This month: a list by topic, each line with a → to the fragment it came from. The app picks the day for your account (somewhere from the 1st to the 28th). The summary is yours to set right with ✎.

On a person's card you choose Look back daily or Look back monthly. A person looked back on monthly wakes on the summary's day and reads the summary and the fragments that mention its names or keywords, so however many people there are, the timeline is read once a month. Create a persona with AI chooses from the relationship: family and close friends daily, people you see now and then monthly. Interests check in daily.

5. What a persona remembers

Open What I remember on a persona to read its saved notes by kind. They are shown as the persona wrote them; no new AI summary is made for display.

Reading notes

  • Posts behind this memory opens the posts and conversations a note came from.
  • Tap a tag to see only notes carrying it; Show all notes goes back.
  • The 📝 chips under a persona's remark are the notes it wrote with that remark. Tap one to open it.
  • For older notes without post links, Find original post opens search.

Fixing and removing

ToDo
Fix a typo or a wrong fact in a note✎ on the note's heading, then Save note
Remove one noteForget this note
Remove all of a persona's notesForget all notes
Change how it remembers from now onEdit with AI on the persona

Deletion cannot be undone. A persona may learn something again by searching the posts that remain.

For example, forget a wrong “Likes this wine” note on its own, then use Edit with AI to say “Do not infer a preference from trying a wine once.” Editing a persona does not rewrite notes it already has.

6. Search

Open Search in the header. A name like “Pinot” and a description like “a light red wine that was easy to drink” go in the same box.

  • Short terms search by words; questions and sentences search by meaning. You can switch from the results.
  • Search covers what you wrote, text read from your images, and your conversations with personas.
  • Tap a result to open the post and its conversation; you can reply from there.

Personas search too, when it helps: a wine persona may say “This is close to the Pinot you liked before,” with a link to that post.

7. Voice input and read-aloud

  • 🎙 Speak listens with the browser's speech recognition and stops after a stretch of silence.
  • Set a send phrase (for example “done”) and the text is posted when you end with it.
  • Turn on Polish text with AI before auto-send to tidy punctuation and hesitations, only when a send phrase posts (off by default).
  • 🔈 Read aloud reads the collected reactions in order.

The send phrase, silence stop, voice and speed are under Settings → Advanced options → Voice.

8. Using it offline

On a device that has opened the app online once, you can write text, images, URLs and replies without a connection. They wait as “Saved on this device · waiting to send” and go out automatically when the connection returns while the app is open. Personas react once the server has them.

  • After an error, Reconnect and retry sends again. Nothing is posted twice.
  • Clearing browser data loses posts still waiting. Signing out asks first, then clears this device's saved data.
  • The latest 20 conversations are also kept on the device, so the app opens with them straight away.

9. Troubleshooting

Nothing reacts to my post.
Perhaps no persona is enabled, the post matched no persona's subject, or a persona chose to remember without speaking. ⚖ shows who got the post. Mention @name when you need an answer.
I cannot close Settings.
Settings stays open until the AI connection works. Enter an API key.
Search says it only matched words.
Meaning search is still preparing or cannot connect. Word matches are still shown. Try again in a moment.
The text in my image has not been read.
Reading takes a moment. Open “Reading result” under the post a little later. Images are limited to 20 MiB per post.
Where is my data stored?
On the server, separated per account; nobody else can see it. To keep a copy yourself, see Settings and data.

kakeratta advanced guide

Fixing routing and replies, when personas wake, Bluesky and Hermes, settings and data, and the tools personas use. For everyday use, see the basics.

1. Fix who gets a post

The app decides which personas get each fragment. Tap ⚖ on one of your posts or replies to see who was called and, for each one that was not, a one-line reason. A persona you mentioned with @name is not listed: that was your call.

For each persona that was called you see whether it has finished, replied, or kept a note. For one that stayed silent, A reply was wanted leads to fixing how it replies.

Fix a persona's condition

  1. Tap Should have been called (or Should not have been called) on a row.
  2. Say why or what should change and tap Write the condition. The AI rewrites the persona's condition, and only that.
  3. Edit the new condition by hand, or use Ask the AI to change it.
  4. OK saves it and tries the same post again (nobody is woken). If it lands as you meant, the dialog closes; if not, you see why and can try again.

Only the condition changes; tone and memory rules stay. When routing uses Jev (Settings and data), no reasons are shown, but conditions are fixed the same way.

Fix a person's keywords

A person's persona has no condition: only fragments with one of its names or keywords reach it. In ⚖ the word it was reached by is shown, as in Matched “Sato”.

  1. Tap Should have been called on the person's row. The current keywords are shown.
  2. Say which words should call them (or leave it empty) and tap Make keywords. The AI picks words written in the fragment and proposes them with their near words.
  3. Edit the keywords to add by hand (comma-separated), or use Ask the AI to change it.
  4. OK adds them to the saved keywords and checks the same fragment. If one of them is in it, the persona gets the fragment; if not, you are told and can try again.

When an unrelated fragment reached a person by a word, tap Should not have been called on its row.

  1. The names and keywords that match the fragment are listed. The persona's own name is shown but cannot be removed here (change it with Edit).
  2. Check the words to remove and tap Remove. They are saved and the same fragment is checked; if it still matches another word, you are told which and can remove that too.
  3. To leave them, tap Keep. A fragment that is not about the person already ends with no reply and no note.

A removed word no longer brings fragments that have only it, and a removed name no longer answers an @. What the persona already said or noted on the fragment stays.

2. Fix how a persona replies

Tap Change how it replies on a persona's remark and say how it missed. The AI rewrites the persona's tone and instructions only; its condition, name and tools stay.

  1. Describe the miss and tap Write the fix.
  2. Edit the new tone and instructions by hand, or use Ask the AI to change it.
  3. OK saves them, and the persona drafts a trial reply to the same post. Nothing lands on the timeline and no note or schedule is written. This can take a few minutes.
  4. That's it closes. Still not it lets you say again, with the trial reply in view.

What you saved stays saved, whatever the trial says.

3. When personas wake

A persona acts at three kinds of moment.

TriggerDecided byWhat happens
A fragment arrivesThe app (routing)Personas whose subject matches, and any you mentioned with @name, act. A person's persona acts when one of its names or keywords is written.
Daily check-inThe appEach active persona wakes once a day, somewhere between 7:00 and 21:00. A person looked back on monthly wakes on the day of this month's summary.
A persona's own scheduleThe personaA persona with schedule picks a time from its own records.

Check-in details

  • The server checks every minute, so a busy moment can delay a wake a little.
  • Enabling a persona after that day's time runs today's check-in right away. After 21:00 the day's check-in is skipped. After a server restart only today's is run; missed days are not replayed.
  • A silent or failed wake still counts as the day's. Deleting notes does not cause a second wake that day.
  • On a day the time would wrap from the evening round to the morning (the 20s one day, the 7s the next), that day is skipped, so a persona does not wake twice within hours.
  • Recent records are read from the previous check-in onward, so a skipped or missed day leaves nothing unread.
  • Check-ins do not use your location, so route search is unavailable and place search works by name only.

For a persona that prefers the external agent, Hermes decides what to tidy and what to ask at check-in. If Hermes does not respond in time, the built-in model plans instead.

A persona's own schedule (schedule)

plana, for example, sets one only for something its records place at a usual time - “morning medicine around 7:30” - and wakes shortly after. If nothing has been recorded yet it adds “the morning medicine, by the way”; if it has, it stays quiet. This is not an advance reminder and it does not nag. It is also not a way for you to ask “tell me every morning at 8.”

A person's persona sets one for the morning of a meeting you mention, such as “drinks with Sato next Saturday.” On waking it brings up what happened last time and anything still open, like a loan or a promise.

  • Up to 20 per persona, up to 30 days ahead, once or daily.
  • Schedules are listed on the persona's card. Remove one you do not want with ×.
  • A wake is used up even if the persona stays silent or fails. One more than 10 minutes late is skipped.
  • Deleting a note makes the persona revisit its schedules. Pausing or deleting the persona, or forgetting all its notes, removes its schedules.

4. Share to Bluesky

Pick the messages you want from a post and its conversation and publish them from your own Bluesky account. Persona messages carry an attribution such as “🍚 tabeからの返信:” (reply from tabe).

Connect your account

  1. Open Settings → Advanced options → Integrations → Bluesky connection, or Share to Bluesky on a post.
  2. Enter your handle (for example alice.bsky.social) and press Connect Bluesky.
  3. Authorize on Bluesky and you return to kakeratta in the same tab. Your password is entered only on Bluesky.

Choose and publish

  1. Press Share to Bluesky on the original post. At first only that post is selected.
  2. Select the messages to share. When you select a reply, select what it replies to as well.
  3. Check how it splits and connects with Preview, then press Publish selected conversation.

What is and is not published

  • The selected messages' text, links, source URLs and images are published. Location, image reading results and persona notes are not.
  • Long messages split at sentence breaks into posts of about 300 characters; later parts start with “つづき:” (continued). Images go on the first part only.
  • Images over 2 MB are shrunk for sending (the original stays as it is). Transparency becomes white and GIFs become still.
  • Up to 100 messages at a time.

Adding later and disconnecting

  • Published messages are not sent again. Replies you select later are added to the same thread.
  • If the connection drops and the outcome is unknown, publishing stops to avoid duplicates. Check on Bluesky.
  • Disconnect removes the connection. Neither disconnecting nor deleting in kakeratta deletes anything on Bluesky.

5. Let Hermes plan for a persona

Each persona can prefer the external agent. A persona with Prefer the external agent on hands the thinking part of its turn — reading the context and deciding what to do next (the workflow) — to your own Hermes, whether it woke for a post or a check-in. kakeratta checks that workflow and then runs it as the persona (notes, schedules, remarks). If you have not installed Hermes yet, start with the Hermes integration guide.

Connect

  1. Under Settings → Advanced options → Integrations → External agent (Hermes), press Create connection key and copy the configuration. The key is shown only then.
  2. Add it to ~/.hermes/config.yaml on the machine running Hermes and restart Hermes. If mcp_servers already exists, add kakeratta inside it.
  3. Install the kakeratta skill and Wake Gate in Hermes and have it check every minute (the guide has the steps).
mcp_servers:
  kakeratta:
    url: "Connection URL shown in Settings"
    headers:
      Authorization: "Bearer CONNECTION_KEY"

Hand a persona over

  1. In Personas, turn on Prefer the external agent for the persona. The checkbox appears only after a connection key has been issued.
  2. Post as usual. Hermes plans what that persona does with it; the reply arrives under the persona's name, marked External agent.

If Hermes does not pick it up within 3 minutes, or does not return a workflow within 15 minutes, the built-in model plans instead. If Hermes has not connected at all for the claim wait, it is taken to be away and the built-in model plans without waiting until it connects again. Change the waits under Integrations; turning off Use the external agent there pauses it while keeping each persona's choice. Try again always uses the built-in model.

What Hermes can read

Hermes can read your posts and the notes of every persona. It cannot post or write notes itself: every write goes through a workflow kakeratta has checked. It cannot reach model settings or other users. Disconnect invalidates the key.

If it cannot connect

  • Restart Hermes after changing its configuration.
  • Check that Hermes can reach the connection URL.
  • If you replaced the key, replace it in config.yaml too.

Backup

Export as zip puts your posts, personas and their notes, persona order, and images into one zip. The download starts when it is ready, and a Download link also appears. The link is valid for an hour. The zip holds personal content, so keep it to yourself.

API keys and the Bluesky and Hermes connections are not included.

Close account

Press Delete everything and close the account and type “delete” to confirm. This removes the account's posts, personas and notes, images, settings, connections, backups, and the login account itself. It cannot be undone, so export a backup first.

With Nebius Token Factory these models are used for each job; there is nothing to choose in Settings.

Reply to a persona with “that's wrong” or “tell me more” and the app checks whether you are asking for a rethink; if so, the persona answers again on Ultra. Thanks and ordinary follow-ups stay as they are.

Under Advanced options → Models → Use OpenRouter, enter an API key and check the connection.

  • Enable Jev: moves routing only to Jev; persona replies stay on Token Factory. Jev shows no routing reasons, but fixing conditions works the same.

7. Tools personas use

A persona picks the tools it needs for a reply or a note. Ask in ordinary words; you never type tool names. A persona you mention with @name always replies, but which tools it uses is its own choice.

ToolPurposeWho / setup
timeline_searchSearch past fragmentsEvery persona
notes_*List, read, save and delete its own notesEvery persona
web_searchSearch the WebPersonas it is added to; Tavily API key
place_searchFind shops and placesPersonas it is added to
routeRoad distance and travel timePersonas it is added to; location on the post
schedulePick its own wake timePersonas it is added to

A persona's tools are listed under Tools in the Personas panel. To add one, use Edit with AI (“let it search the Web too”), review the change and save.

Tools run on the kakeratta server. If you allow location, coordinates go to the server and, for place and route search, to an external map service. Notes and search results a persona reads also go to the AI model as input.

Search past fragments — timeline_search

Searches your saved posts, text read from images, and replies by words and meaning together. A period can narrow it, or alone read everything written in it. Each call returns up to 30 results. Only the posts a persona uses as its grounds are linked under its remark.

Try: “@tabe Find that light red wine I enjoyed before.”

Notes — notes_list / notes_read / notes_write / notes_forget

A persona lists, reads, saves and deletes its own notes one at a time. It decides what to remember and may update notes without speaking. To inspect or reliably delete notes, use What I remember.

Try: “@tabe I like spicy food, but strong sesame isn't for me. Remember that.”

Web search — web_search

Searches news, technical information and more, and cites result links as sources. Save a Tavily API key under Settings → Web search (separate from the AI key). It works from result summaries and does not necessarily read whole pages.

Try: “@shiori Search the Web for this book's author.”

Place search — place_search

With a location on the post it searches nearby shops and places; without one, it looks places up by name. Places missing from the map cannot be found, and it cannot tell whether a shop is open now or has seats. Finding nothing does not mean there is nothing.

Try: with location on, “@tabe Find ramen near me.”

Route search — route

Estimates road distance and time from the post's location to a destination by car, on foot, or by bicycle. No trains, buses, timetables or live traffic. It needs a location on the post, so it is unavailable in check-ins; typing a starting place in the text is not the same as a location.

Try: “@michi How long to walk from here to Shibuya Station?”
