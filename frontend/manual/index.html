kakeratta の使い方

kakeratta は、記憶して、必要なときに思い出させてくれる Personal AI 付きのメモ帳です。

テキスト、写真、URL、音声をひとつのタイムラインに放り込みます。AI から返事がないのも普通です。投稿はそのまま残り、あとから検索したり、読み返したりできます。

人や関心ごとに置いた「担当」は、それぞれ別の記憶を持ち、関係することがあれば反応します。覚えている内容や振り分けの判断は、自分で確認・修正できます。

このマニュアルでは、日常の操作から、担当の調整、外部エージェントとの連携まで説明します。

1. はじめる

  1. アプリを開きます。Google アカウントでログインします。認証後は「ログインを完了しています…」を表示し、完了すると自動で画面が切り替わります。データはあなたのアカウントにだけ結びつき、ほかの人からは見えません。
  2. 右上の 設定 を開き、Nebius Token Factory で発行した API キー を入力します。「接続できました」と出れば準備完了です。
  3. 新しいアカウントでは、sona・インフォグラフィックの 2 人が最初から有効です。
  4. 欄に一言書いて 流す。これが最初のかけらです。

API キーはサーバー側にだけ保存され、設定した接続先以外へは送られません。

2. メモ・写真・音声を残す

書く、貼る、URL、話す。どれも同じひとつの欄から入ります。

入れ方やり方
書く欄に書いて 流す。Ctrl（⌘）+Enter でも送れます。
画像PC はスクリーンショットを Ctrl+V で貼るだけ。スマホは 📷 画像 からスクリーンショットを選ぶか、その場でカメラで撮ります。画像の文字は読み取られ、あとから検索できます。
URLURL を書いて流すと、公開ページの本文を読み込みます。
話す🎙 話す で音声入力します（音声入力と読み上げ）。

Kindle も有料記事も SNS も、画面に出ていればスクリーンショットで放り込めます。一言と画像を一緒に送ることもできます。投稿に自動で添えられるのは「今どこで何時か」だけです。行き先や時刻は文面に書けば担当が読み取ります。位置情報は任意です。

音声入力と読み上げ

  • 🎙 話す を押すと、ブラウザの音声認識で聞き取ります。無音が続くと自動で止まります。
  • 送信の合図（例：「以上」）を決めておくと、文の最後にそう言った時点で投稿されます。
  • 自動送信前にAIで文章を整える をONにすると、合図で送るときだけ、句読点や言いよどみを整えます（初期状態はOFF）。
  • 🔈 読み上げ は、溜まった反応を順に読み上げます。

合図、無音での停止、声と速さは 設定 → 音声 で変えられます。

オフラインで使う

一度オンラインで開いた端末なら、電波がなくても文章・画像・URL・返信を書けます。書いたものは「端末に保存済み・送信待ち」として残り、アプリを開いている間に接続が戻ると自動で送られます。担当の反応は、サーバーに届いてから始まります。

  • 送信に失敗したときは 接続して再送 でやり直せます。二重に投稿されることはありません。
  • 送信待ちは、ブラウザのデータを消すと失われます。ログアウトするときは確認のうえ、この端末の保存データを消します。
  • 直近20件の会話は端末にも保存され、次に開いたときすぐ表示されます。

3. AIに質問する

反応の届き方

  • 担当の反応は少し遅れて届きます。反応が付かないこともあります。 担当は喋らずに覚えるだけのこともあるからです。
  • 必ず答えてほしいときは @名前 で指名します（例：@tabe）。指名された担当は必ず返事をします。入力欄の下の 担当を表示 を開いて担当の名前を押すか、入力欄で @ を打つと、@名前 が書き込まれます。
  • 担当の発言や自分の返信は 返信 N件 の下にたたまれます。表示中に届いた発言は、そのスレッドが自動で開きます。

宛先の使い分け

同じ入力欄から、誰に向けて書くかを選べます。入力欄で @ を打つと候補が出ます。

書き方届く先と動き例
普通の投稿担当条件や人物の呼び名に合う担当が、必要なときだけ反応します。無反応も正常で、投稿はそのまま残ります。静岡で気になっていた店
@担当名指名した担当から必ず返事が届きます。その担当の記憶と道具を使います。@tabe 静岡で前に話した店は？

@ai に質問する

@ai 最近いつ横浜から離れたっけ？ のように内蔵AIへ質問できます。過去の投稿・位置情報・日時を検索し、根拠の投稿を添えて答えます。担当メモ・予定・会話全体も参照でき、検索用APIキーがあればWeb検索も使えます。kakerattaの使い方や困りごとも @ai に聞けます。アプリの質問のときだけ関連する仕様を読みます。通常は Super VL、「詳しく」と頼むと Ultra を使います。スケジュール登録・メモ保存・メール送信などの外部操作はせず、会話はタイムラインに残ります。回答への返信で会話を続けられます。

@ai は内蔵、@agent は外部です。入力欄の @ 候補では「内蔵AI」をいつでも選べ、外部連携が有効で接続先がある場合は「外部エージェント」も選べます。外部が無効・未接続なら @agent の候補は出ません。ai・agent は予約名で、担当のID・名前・呼び名には使えません。

投稿を削除すると、その下の担当の発言と自分の返信も消え、検索にも出なくなります。その投稿だけをもとに書かれた担当のメモも一緒に消えます。 ほかの投稿ももとにしているメモは残り、担当があとで整理します。

担当の回答や返信は × で消せます。それに（間接的にも）返事している発言も一緒に消え、スレッドのほかの発言は残ります。間違った回答を消すと、それを繰り返した返事も含めて、検索やスレッドの文脈として参照されなくなります。回答と一緒に書いたメモは残るので、メモも誤っていれば担当の記憶から直してください。

詳細 担当が使う道具

担当は、返事やメモに必要な道具を自分で選んで使います。ふだんの言葉で頼めばよく、道具の名前を書く必要はありません。@名前 で指名された担当は必ず返事をしますが、どの道具を使うかは担当が決めます。

道具できること使える担当・必要な設定
timeline_search過去のかけらを検索すべての担当
records前のかけらの記録を探す（記憶の保存は本体が行う）記憶がオンの担当
web_searchWeb 検索道具に追加した担当。Tavily の API キー
place_search店や場所を探す道具に追加した担当
weather_forecast現在の天気と天気予報道具に追加した担当。地域名または投稿の位置情報
schedule自分が起きる時刻を預ける道具に追加した担当

担当が使える道具は、担当パネルの 道具 に出ます。増やしたいときは AIで修正 で「Web検索も使えるようにして」のように頼み、変更案を確かめて保存します。

道具は kakeratta のサーバーで動きます。位置情報を許可すると、座標がサーバーへ送られ、店や場所を探すときに外部の地図サービスへ渡ります。担当が読んだメモや検索結果は、AI モデルへの入力にも含まれます。

過去のかけら検索 — timeline_search

保存した投稿、画像から読み取った文字、返信を、語句と意味の両方で探します。期間を指定して、その間の記録をまとめて読むこともできます。一度に返るのは30件までです。検索で見つかった投稿のうち、担当が根拠にしたものだけが発言の下にリンクされます。

例：「@tabe 前に飲んで気に入った、軽い赤ワインを探して」

かけらの記録を探す — records

担当は毎回、今の事実と最近の記録を読んでから考えます。それより前のかけらの記録は、タグ・語句・意味で探し、記録の投稿そのもの（返事なら元のかけらも）を読めます。返事のあとには本体が記録を追加し、チェックインで新しい記録を事実に取り込みます。中身の確認や削除は 覚えていること から行います。

例：「@tabe 前に行きたいって言ってたラーメン屋、どこだっけ」

Web検索 — web_search

ニュースや技術情報などを検索し、結果のリンクを出典として付けます。設定 → Web検索 に Tavily の API キーを入れて使います（AI の API キーとは別）。検索結果の要約を使うので、リンク先の全文を読むとは限りません。

例：「@shiori この本の著者についてWebで調べて」

店舗・場所検索 — place_search

投稿に位置情報があれば周りの店や場所を、なければ名前で場所を探します。地図に載っていない店は見つからず、営業中かどうかや空席は分かりません。見つからなくても「店がない」とは限りません。

例：位置情報付きで「@tabe この近くのラーメン屋を探して」

天気予報 — weather_forecast

WeatherAPI.comから現在の天気と日別予報を調べます。地域名を指定するか、投稿の位置情報を使います。日付や現地時刻の時間帯を指定して確認することもできます。取得できる予報の期間は接続先の契約によって異なり、取得していない日の天気は分かりません。担当の道具に「天気予報を調べる」を追加して使います。

例：「@sona 東京の明日の18時ごろ、雨は降りそう？」

4. 担当を作る・育てる

担当は、一人の人物か一つの関心ごとについて、別々の記憶を持つ AI です。人物の担当にはその人の名前が出たかけらが、関心ごとの担当には本体が振り分けたかけらが届き、そのうえで覚えるか、喋るかを各担当が決めます。担当同士でメモは共有しません。

最初からいる担当

名前分野受け取るもの
@tabe食事店、料理、飲み物、食事やメニューの写真、「何食べよう」
@infographic図解投稿・記事・画像・会話を図解にしてほしいという依頼。表示言語の図解（見出し・表・Mermaid の図）で返します。Web検索なし・記憶なし・最終回答はふだん Super VL、「詳しく」を付けると Ultra（新規利用時は有効）
@shiori読書電子書籍のキャプチャ、引用、書名と著者、読んだ感想
@sona備え外出前の持ち物、忘れ物、予定と天気を合わせた声かけ。繰り返す用事や一度きりの用の確認。新規利用時は有効

ヘッダーの 担当 で一覧を開き、各カードのスイッチ（有効／無効）で受け取る担当を選びます。担当は投稿された言語で答えます。

AI と担当を作る

  1. 担当 を開き、関心ごと タブで AIと担当を作る を選びます。人物を覚える担当は、人物タブから作ります。
  2. 「どんなことの担当を作りたい？」に自分の言葉で答えます。「ワイン」だけでも始められます。
    例：美味しかったワインのラベルを送るので、銘柄やブドウ品種を教えてほしい。
  3. AI が名前、話し方、覚え方、覚えること・返事をするタイミングの下書きを作ります。確認して この担当を追加 を押します（既存の担当を直したときは この内容で保存）。
  4. 追加するとすぐに 有効 になり、以後のかけらを受け取り始めます。

作成・修正時に 記憶する（オフにすると記憶を持たない回答専門になり、費用削減や不要なメモ防止になります）や、常に熟考する（通常の依頼も最終回答を Super VL で生成）を選べます。

人物担当を作る

母や友人のように、特定の一人を覚える担当も作れます。担当 の 人物 タブで AIと担当を作る を選ぶと、「誰のことを覚える担当を作りたい？名前や呼び名、あなたとの関係を教えてください。」と尋ねられます。入力欄の例を参考に、「大学時代の友人の佐藤さん。さっちゃんと呼んでいて、たまに一緒に食事をします。」のように答えると、人物の担当の下書きができます。人物を覚える担当かどうかは作成時に決まり、あとから切り替えることはできません。

  • 人物の担当は、本体の振り分けを通りません。 かけらに 呼び名 か キーワード が書かれているときだけ届きます。写真から読み取った文字も対象です。@呼び名 で指名することもできます。
  • 「サトウ」を登録すれば「サトウくん」「さとうさん」にも届きます。全角・半角、大文字・小文字、ひらがな・カタカナ、末尾の敬称（さん・くん など）の違いは区別しません。漢字の「佐藤」とかな書きは別の語として扱うので、両方使うなら両方を呼び名に入れてください。名前を出さない話も拾えるよう、キーワードには言い換えや似た言葉（例：釣り、つり、釣行、海釣り）を並べます。
  • 人物の担当はその人との出来事（会話、贈り物、約束、貸し借り）を覚えます。誕生日や会う予定が近づくと声かけしてくれます（詳しい通知時刻のルールは 詳しい説明 を参照）。
  • 伝えた誕生日・好み・出来事などは、担当の編集画面でいつでも見直し・修正できます。

届かなかったかけらがあれば ⚖ の 呼んでほしかった からキーワードを足せ、関係のないかけらが届いたら 呼んでほしくなかった から一致した語を外せます（人物の担当のキーワードを直す）。キーワードは多ければよいわけではありません。曖昧な語を増やすと関係のないかけらが届きやすくなるので、実際の振り分けを見ながら調整してください。

担当を編集する

担当の AIで修正 から「もっと短く返事してほしい」「なぜ気に入ったかも覚えてほしい」のように頼めます。組み込みの担当も同じように変えられ、それまでのメモはそのまま残ります。

担当の 削除 は、その担当のメモも一緒に消します。元に戻せません。受け取りを止めたいだけなら、カードのスイッチを 無効 にしてください。

編集画面で変更を保存せずに閉じようとすると、確認が出ます。保存して閉じる・保存せずに閉じる・編集に戻る から選べます。

記憶から担当を増やす

使い続けるうちに担当の記憶に別の話題が増えてくると、毎日のチェックインで担当が「〇〇の担当を新しく作って分けませんか？」と提案することがあります。

  • 投稿の下の 作る を押すと、新しい担当の作成、関係する記憶の移動、元の担当の担当条件の調整までまとめて行います。以後、その話題は新しい担当にだけ届きます。
  • 作らない で見送れます。担当も記憶もそのままです。
  • 途中で失敗したときは元の状態に戻り、もう一度 作る を押せます。

提案するのは記憶がオンの関心ごとの担当だけで、同じ担当からは30日に1回までです。作られた担当は、ほかの担当と同じように 編集 できます。詳しくは 詳細：記憶の整理と担当の提案 を見てください。

アイコンを変える（絵文字・写真）

担当のアイコンは、作るとき（AIと担当を作る）や、カードの 修正・AIで修正 で変えられます。自分のアイコンは 設定のプロフィール で同じように変えられます。

  • 絵文字を選ぶ を開くと、顔・人・手・体・動物・自然・食べ物・趣味・乗り物・場所・もの・記号・旗のグループごとに絵文字が並びます。押すだけで決まります。一覧にない絵文字は その他の絵文字を入力 から入力できます。
  • 写真を選ぶ で、手元の画像をアイコンにできます。写真は端末の中で正方形に切り抜き、小さく圧縮してから保存します。元の画像はアップロードしません。
  • 写真があるときは写真が優先して表示されます。写真を外す と絵文字に戻ります。絵文字を選び直したときも写真は外れます。

5. 記憶を確認・修正する

担当の 覚えていること を開くと、その担当が覚えている内容をいつでも確認・編集・削除できます。AIが勝手に覚えたままブラックボックスになることはありません。

できること

  • 読む: 「事実と記録」に、いまの事実・かけらの記録が並びます。担当ごとに1つの記憶として持っています。
  • たどる: 各メモの 元の投稿 を押すと、そのメモのもとになった会話や写真がその場で開きます。記録の #タグ を押すと、その話題だけに絞り込めます。
  • 直す: 誤字や解釈の違いがあれば、横の ✎ でいつでも手で直せます。
  • 消す: 忘れさせたいメモは × や このメモを忘れさせる で消せます。削除前に確認が出ます。記憶を一括削除する専用ボタンはありません。元のかけらを削除すると、そのかけらだけに基づいていたメモも消えます。
  • 見直す・お別れ: その場限りのメモは自動で消え（… に消える）、古いメモはチェックインで「そろそろ忘れていい？」と担当が尋ねてきます（… に見直し）。投稿の下の はい で記録を削除、もうちょっと覚えてて で見直しを延期、忘れないで で以後の見直しを止められます。回答後は選んだ結果が表示されます。言葉で返事をすることもできます。

変わるのはこれから覚える内容です。すでにある記憶は書き換わらないので、誤ったメモは 覚えていること から直すか消してください。

詳細 記憶の整理と担当の提案

担当の記憶は会話のたびに少しずつ足され、チェックインでまとめ直されます。画面で確かめたり直したりする方法は 覚えていること にあります。この章では、記憶がどう整理されるかと、記憶から新しい担当が提案される仕組みを説明します。

かけらの記録と今の事実

  • かけらの記録：受け取ったかけらごとに、日時・元の投稿・要約・タグを1行残します。挨拶や一般的な質問だけのかけらは記録しません。会話のたびに行うのはこれだけです。
  • 今の事実：分かっていることを1件1行で持ちます。根拠のある傾向・条件・例外・役立つ変化も残します。チェックイン（通常は毎日、月1回振り返る人物は月1回）で、新しい記録を事実に取り込み（足す・書き換える・消す・まとめる）、取り込んだ記録は消えます。当てはまらなくなった事実や、日付が過ぎた予約などの予定も消えます。

事実は1件200字、合計4,000字までです。担当は毎回、今の事実と最近の記録を読んでから考え、それより前の記録はタグ・語句・意味で探します（records）。

期限と見直し

  • … に消える：「今日のランチ」のようなその場限りの記録に付き、その日に自動で消えます。
  • … に見直し：あなたが言ったことの記録に、内容から日付が付きます。日付を過ぎると、毎日のチェックインで担当が「そろそろ忘れていい？」と尋ねます。
  • 尋ねられたら、投稿の下の はい で記録を削除、もうちょっと覚えてて で見直しを延期、忘れないで で以後の見直しを止めます。言葉で返事をしても同じように扱います。
  • 担当が返事のために記録を読み返すと、期限はその日から延びます。
  • 記録が消えると、その記録だけを根拠にしていた事実も一緒に消えます。

新しい担当の提案

何が起きるか： 記憶は話題ごとに分けません。担当の領域から外れる話題や、はっきり別の話題がたまってくると、毎日のチェックインで担当が「〇〇の担当を新しく作って分けませんか？」と一言提案します。担当が黙った場合も、アプリが同じ提案を投稿します。

使い方： 提案の投稿の下で 作る か 作らない を選びます。

  • 作る：その話題に合わせて名前・アイコン・担当条件・口調を整えた担当が、記憶オン・有効の状態ですぐ追加されます。関係する事実と記録は、書かれたままの文で新しい担当の記憶へ移ります。新しい担当は、移った記録を次のチェックインで新しい記録として読みます。
  • 元の担当の担当条件には、その話題を除く一文（「ただし、…は除く。」）が加わります。以後、その話題の投稿は新しい担当だけに届きます。
  • 作らない：見送りとして記録され、担当も記憶もそのままです。

注意点：

  • 提案するのは記憶がオンの関心ごとの担当だけで、同じ担当からは30日に1回までです。人物担当は提案しません。
  • 担当の追加、担当条件の変更、記憶の移動、有効化は、すべて成功したときだけ確定します。途中で失敗すると、それまでの手順を取り消して元に戻し、提案の投稿は 作る を押せる状態のままです。記憶の移動中に失敗しても、記憶がどちらの担当からも消えることはありません。
  • 続けて押しても、担当が2人できることはありません。

作られた担当や元の担当の条件は、ほかの担当と同じく 編集 や 担当の条件を直す で調整できます。

6. 振り分け・返し方を直す

かけらをどの担当に渡すかは本体が決めます。自分の投稿や返信の ⚖ を押すと、呼ばれた担当と、呼ばれなかった担当ごとの一行の理由が出ます。@名前 で指名した担当は、あなたが選んだので出ません。

指名と宛先の優先ルール： @名前 で指名した投稿や、有効な担当への返信は、宛先の担当だけに届きます。別の担当を指名した場合は指名が優先されます。それ以外の投稿は、担当条件や人物の呼び名・キーワードで届け先を選びます。

@infographic の対象ルール： 図解したい投稿や回答に @infographic これをインフォグラフィックにして と返信します。別の担当の回答に返信した場合、その回答を図解します。「元の投稿を」「スレッド全体を」と明示して対象を変えることもできます。URLは展開された記事本文、画像は読み取り済みの説明や文字を材料にします。図解は依頼時の表示言語に翻訳され、絵文字やMermaidを使ったMarkdownで画面内に表示されます。Web検索は行いません。

振り分けの決まり方

宛先決まり方直し方
関心ごとの担当本体の AI（Router）が、投稿と各担当の担当条件を読んで選びます。担当の条件を直す
人物担当AI を通さず、呼び名かキーワードが投稿に書かれているかの文字の一致で届きます。キーワードを直す
@名前 の指名・担当への返信指名した担当、または返信先の担当だけに届きます。返信先と違う担当を指名すると指名が優先です。自分で選んだ宛先なので、⚖ に理由は出ません
Jev で振り分ける場合OpenRouter の Router を Jev に切り替えると、判定理由は表示されません。担当条件は同じ手順で直せます

呼ばれた担当には、処理が終わったか、返事をしたか、メモを残したかが出ます。黙っていた担当には 返事がほしかった から 返し方を直す 流れに入れます。

担当の条件を直す

  1. 行の 呼んでほしかった（または 呼んでほしくなかった）を押します。
  2. 理由やどう変えてほしいかを書き、条件を作る を押します。AI が担当の判定条件だけを書き直します。
  3. 新しい条件は手で直せます。AIに変更を依頼 で書き直しを頼むこともできます。
  4. OK で保存すると、同じ投稿で振り分けを試します。「呼んでほしかった」で狙いどおり呼ばれたら、その担当に元の投稿を渡して返事やメモを残します。違えば理由を見てやり直します。

変わるのは判定条件だけで、口調や覚え方は変わりません。振り分けに Jev を使っている場合（OpenRouter を使う）は理由が表示されませんが、条件は同じ手順で直せます。

人物の担当のキーワードを直す

人物の担当には判定条件がなく、呼び名かキーワードが書かれたかけらだけが届きます。⚖ には、どの語で届いたかが「「佐藤さん」に一致」のように出ます。

キーワードは多ければよいわけではありません。 短い語や意味の広い語を増やすと、「母」で「母校」が届くように、関係のないかけらまで届きやすくなります。足したあとは ⚖ で実際の振り分けを確かめ、余計に届くなら下の 呼んでほしくなかった で外してください。

  1. 届かなかった人物の担当の行で 呼んでほしかった を押します。今のキーワードが出ます。
  2. どの語で呼んでほしいかを書き（空でもかまいません）、キーワードを作る を押します。AI がそのかけらに書かれている語を選び、似た言葉とあわせて足すキーワードを出します。
  3. 足すキーワードは手で直せます（読点区切り）。AIに変更を依頼 もできます。
  4. OK で今のキーワードに足して保存し、同じかけらで確かめます。足した語がかけらにあれば、その担当に元のかけらを渡します。なければそう伝えるので、やり直します。

関係のないかけらが語の一致で届いたときは、呼ばれた人物の担当の行で 呼んでほしくなかった を押します。

  1. 呼び名とキーワードのうち、そのかけらに一致した語が並びます。担当の名前そのものは表示だけで、ここでは外せません（担当の 修正 で変えます）。
  2. 外す語にチェックを入れて 外す を押します。保存して同じかけらで確かめ、ほかの語でもまだ一致するなら、その語を伝えるので続けて外せます。
  3. 外さないなら 残す で閉じます。その人と関係のないかけらなら、担当はもともと発言もメモもせずに終えます。

外した語だけを含むかけらは今後届かず、外した呼び名は @ での指名にも使えなくなります。そのかけらに担当がすでに残した発言やメモは消えません。

返し方を直す

担当の発言の 返し方を直す を押し、期待とどう違うかを書きます。AI が担当の 口調 と 指示 だけを書き直します。判定条件、名前、道具は変わりません。

  1. 違いを書いて 直し方を作る を押します。
  2. 新しい口調と指示は手で直せます。AIに変更を依頼 で書き直しを頼むこともできます。
  3. OK で保存すると、同じ投稿で担当が試し書きをします。タイムラインには載らず、メモも予定も書かれません。数分かかることがあります。
  4. これでよい で試し書きの返事とメモ変更を元のスレッドに反映します。まだ違う なら、試し書きを見ながらもう一度伝えます。

保存した口調と指示は、試し書きの結果にかかわらずそのまま残ります。

7. 予定・通知を管理する

担当は、誕生日や会う予定、出かける前の点検などを予定として預かり、その時刻にタイムラインへ知らせます。予定は一覧で確認・編集・取り消しができます。

通知をOFFにしても、予定そのものは実行されます。 OFFで止まるのはPush通知だけで、担当はその時刻に起きてタイムラインへ投稿します。予定を止めたいときは × で取り消してください。

予定ができるとき

  • 人物担当：基本情報やかけらから、日付の分かる誕生日・記念日・会う予定を自動で登録します。
  • 道具に「予定」を持つ担当（sona など）：投稿や習慣から時刻が分かると、自分が起きる時刻を預けます。
  • 予定は担当ごとに20件までです。担当を停止・削除すると、その担当の予定も消えます。

担当からの声かけ

記憶を持つ担当は、伝えたいことがあるときや、出かける前の持ち物点検・雨予報の傘の助言（sona）など、必要なタイミングで話しかけます。話す量や口調は担当のキャラクターに合わせます。「記憶する」をオフにすると定期的なチェックインは止まりますが、明示的な通知予定は引き続き実行します。毎日の起床時刻や月次まとめの仕組みは 詳しい説明 にあります。

予定だけをまとめて見る・編集する

ヘッダーの「予定」（スマホではカレンダーアイコン） で、すべての担当の予定を次の実行日時順に確認できます。担当名や予定の内容で検索できます。各予定の鉛筆マークから 日時・通知を編集 モーダルを開き、次の実行日時と Push通知 を変更して保存してください。入力欄の日時は、表示されたこの端末のタイムゾーンです。

担当ごとのカードや発言一覧でも編集できます。通知OFFでも予定の実行とタイムラインへの投稿は続きます。「この予定は通知しないで」のように担当に頼むこともできます。予定自体を止める場合は × で取り消してください。

毎日の予定は、予定のタイムゾーンで変更後の時刻を引き継ぎます。年次予定も時刻は引き継ぎますが、日付変更は次回だけです。実行を始めた回には変更が間に合わないことがあります。保存に失敗した場合は入力を残して再試行できます。

リマインダーのPush通知

  1. iPhone・iPadでは、kakerattaをホーム画面に追加し、そこから開きます。スマホで上部の案内を「あとで」で閉じた場合も、設定 → この端末 から手順をいつでも確認できます。
  2. 設定 → この端末 → リマインダーのpush通知 を開き、Push通知 のスイッチをONにしてブラウザの通知を許可します。受け取りたい端末ごとに設定してください。
  3. 誕生日や予定のリマインダー、および @agent への直接依頼の回答（依頼の 🔔 がONのとき）を、ブラウザを閉じていても受け取れます。通知を開くと該当の投稿に移動します。同じ場所の Push通知 のスイッチをOFFにすると、その端末への配信を止められます。

通知には本文が最大300文字で表示されます（省略時は末尾に「…」）。ロック画面での表示は端末の設定に従います。通常の返事・チェックイン・今月のまとめは通知しません。HTTPSと対応ブラウザが必要です。配信に失敗しても投稿はタイムラインに残ります。

通知が届かないときは、この端末での有効化、ブラウザの通知許可、ログイン状態、予定ごとの通知設定を確認してください。「サーバーで設定されていません」と表示される場合は運用者の設定が必要です。

済みにする

予定から届いた通知には 済みにする が表示されます。押すと ✓ 済み になり、もう一度押すと印を外せます。担当も会話を読むときに済みの印を確認できます。操作にはオンライン接続が必要です。

通知の時刻や予定が実行される条件は詳しい説明の 人物担当の予定通知ルール、担当が預けた予定、毎日のチェックイン にあります。

詳細 担当が起きるタイミング

担当が動くのは、次の3つのときです。

きっかけ決める人内容
かけらが届いたとき本体（振り分け）@名前 の指名や有効な担当への返信は宛先1人だけを起こし、指名を優先します。それ以外は担当条件や人物の呼び名・キーワードで選びます。
毎日のチェックイン本体設定したアカウント共通の時刻に、記憶がオンの有効な担当が順番に起きます。月1回振り返る人物は、今月のまとめの日に起きます。
担当が預けた予定担当schedule を持つ担当が、自分の記録から時刻を決めて起きます。

毎日のチェックイン

設定 → 毎日の振り返り で時刻を指定できます。「自動」では、アカウント共通で7時〜21時の間に決まり、日ごとに少しずつ動きます。指定した時刻は設定のタイムゾーンに従います。

  • 本体が前回からの投稿を内部用に一度まとめ、記憶がオンの有効な担当が順番に、そのまとめと自分の記憶を読みます。新しい投稿、見直す記録、近い予定がなければ発言せずに終わることがあります。
  • 混み具合で開始が遅れることがあります。指定時刻を過ぎた分は当日中、自動の場合は21時までが実行対象です。過ぎた日の分をまとめて実行することはありません。
  • 自動の時刻が夜から朝へ回り込む日は休みますが、月次まとめの日は実行します。時刻を指定した場合はこの休みはありません。
  • 一度実行した担当は、黙った場合や失敗した場合もその日の1回に数えます。最近の記録は前回のチェックインから読みます。
  • チェックインでは現在地を使わないので、店舗検索は名前での検索だけになります。

「外部エージェントを優先する」をONにした担当では、チェックインで何を話すか（聞くことや伝えること）を外部エージェントが書きます。記憶をどう整えるかは、ふだんどおり kakeratta が決めます。時間内に外部エージェントが応じなければ、内蔵モデルが代わりに書きます。

今月のまとめと、月1回振り返る人物

月に1回、本体がその月のタイムラインを読み、今月のまとめ をタイムラインに投稿します。あなたの発言・行動・決定・変化を話題ごとにまとめます。担当の提案だけでは、あなたが実行したことや予定として扱いません。各項目の → から元のかけらを開けます。日付は本体がアカウントごとに決めます（毎月1〜28日のどこか）。まとめはあなたのものとして ✎ で直せます。

人物の担当は、カードで 頻繁に振り返る か ときどき振り返る を選べます。月1回にした人物は、まとめが書かれた日に起き、まとめと、その人の名前やキーワードが出たかけらを読んで振り返ります。人物が増えても、タイムラインを読むのは月に1回で済みます。AI と担当を作ると、家族や親しい人は毎日、たまに会う人は月1回のように、関係性から選ばれます。関心ごとの担当は毎日です。

人物の担当の予定通知ルール

基本情報の保存・編集や、その人物に届いたかけらから、日付の分かる誕生日・記念日・会う予定を自動で登録します。

  • 誕生日・記念日： 毎年、1週間前と当日の午前9時に知らせます。
  • 会う予定： 指定された通知時刻を優先し、指定がなければ当日午前9時（午前9時より早い予定は1時間前）に知らせます。
  • 通知は担当の投稿として届きます。未来の予定に日数の上限はなく、日付の分からない情報は推測で登録しません。予定の変更や中止も反映します。

担当が預けた予定（schedule）

sona は、投稿や習慣から出発の時刻が分かると、少し前に起きて持ち物を点検します。以前「鍵を忘れた」と話していれば、その経験も手がかりになります。外出先と日時が分かれば最新の天気予報を調べ、今晴れていても帰りが雨なら傘を一言勧めます。地域や時刻、取得できない予報は作りません。用事をしたかの確認は少しあとに置き、済んでいたり同じことを伝えていたりすれば黙ります。催促や毎日の一般的な読み上げはしません。

人物の担当は、「来週土曜、佐藤さんと飲む」のような会う予定が書かれると、その日の朝に予定を置きます。起きたら前回の出来事や済んでいないこと（貸し借り、約束）を一言添えて知らせます。

  • 担当ごとに20件まで。未来の時刻に日数の上限はありません。道具の予定は1回きりか毎日、誕生日・記念日は毎年繰り返します。
  • 予定は担当のカードに並びます。不要な予定は × で消せます。
  • 起きた回は、担当が黙っても失敗しても消費されます。予定より10分以上遅れた回は実行しません。
  • かけらを消すと、担当がそのかけらのために置いた予定を見直します。担当を停止・削除したときは、その担当の予定も消えます。

8. 過去の投稿・お気に入りを探す

ヘッダーの 検索 を開きます。「ピノ」のような名前も、「軽くて飲みやすかった赤ワイン」のような言い方も、同じ欄に入れられます。

  • 短い語句はキーワードで、質問や文章は意味の近さで探します。結果の画面から探し方を切り替えられます。
  • 探す対象は、自分が書いた本文、画像から読み取った文字、担当との会話です。
  • 結果を押すと、元の投稿と会話が開き、そこから返信も書けます。

絞り込み を開くと、開始日・終了日 を検索語やお気に入り条件と組み合わせられます。期間だけでの検索もできます。

お気に入りだけを検索する

お気に入りのみ をオンにすると、保存した投稿・回答だけを対象に検索します。キーワードでも意味でも探せます。検索欄を空にすると、お気に入りの投稿・回答を投稿日時の新しい順に表示します。

あとで読み返したい投稿や担当の回答の ☆ を押すと、★ に変わり、お気に入りに保存されます。自分の投稿・返信も保存できます。担当のメモに残らない回答も、ここから読み返せます。

タイムライン上の 絞り込み を開き、お気に入りのみ をオンにすると、保存した投稿・回答を会話と一緒に表示します。開始日・終了日 で投稿日時を絞れます。終了日も含みます。発言一覧でも同じ絞り込みを使えます。閉じても条件は維持され、「絞り込み中」と表示されます。

外部エージェントに直接頼む

@agent・@外部エージェント・@エージェント で、担当を介さず接続先に直接依頼できます。回答への返信はそのまま次の依頼になります。担当の記憶や予定は更新しません。

依頼には待機中・作業中の状態が表示され、🔔 で回答のプッシュ通知を切り替えられます。取得まで、取得後の回答まで、それぞれ2時間を過ぎるとお知らせします。遅れて届いた回答も表示されます。作業開始後の編集は届かないため、追加事項は返信してください。利用できる道具や実行できる作業は、接続先の設定に従います。

接続先を管理する

同時に使える接続先は1つです。外部エージェントを優先する担当は、すべて「使用する接続先」で選んだ接続先を使います。

  • 「＋ 接続先を追加」で名前を付けると、その接続先のキーが発行され、そのまま使用中になります。キーが表示されるのは発行した直後だけです。
  • 一覧で別の接続先を選ぶと切り替わります。ほかの接続先のキーは残りますが、使用中でないキーでは接続できません。切り替えたときに取りに来るのを待っていた依頼は、内蔵モデルが答えます。
  • キーの再発行と削除は、接続先ごとの行で行います。

Hermes とつなぐ

  1. 設定 → 外部連携 → 外部エージェント接続 で 追加してキーを発行 を押し、表示された設定をコピーします。

Obsidian（LLM Connect Hub）とつなぐ

LLM Connect Hub を使うと、担当の回答を Obsidian の LLM Hub が答えます。モデルは LLM Hub で選んだものを使い、Vault のノート・RAG・スキルを調べて回答します。回答の出典には、参照した Vault のファイルが [[ファイル名]] で示されます。

  1. Obsidian のコミュニティプラグインから LLM Hub と LLM Connect Hub を入れて有効にします（デスクトップ版のみ）。
  2. kakeratta の 設定 → 外部連携 → 外部エージェント接続 で接続名（例: Obsidian）を付けて 追加してキーを発行 を押します。
  3. LLM Connect Hub の設定の Kakeratta に、接続情報と待ち時間 に表示された MCPエンドポイントを入れます。Add header で名前 Authorization、値 Bearer 接続キー を追加します。
  4. 回答に使うモデル、読んでよい Vault のフォルダ、RAG、スキルを決めます。担当ごとに変えることもできます。
  5. Check periodically をONにして Enabled をONにし、Save and reconnect を押します。

LLM Connect Hub は Obsidian を開いている間、1分ごとに依頼を確認します。依頼がないときにモデルのトークンは使いません。確認の間隔が1分なので、取得を待つ時間（外部エージェントが依頼を受け取るまで kakeratta が待つ時間）は1分より長くしておいてください。Obsidian を閉じて取得を待つ時間が過ぎると不在とみなされ（下の「担当を任せる」を参照）、それ以降の依頼は待たずに内蔵モデルが答えます。閉じた直後に届いた依頼は、待ち時間が過ぎてから内蔵モデルが答えます。詳しい設定は LLM Connect Hub の説明 を見てください。

担当を任せる

  1. 担当 画面で、任せたい担当の 外部エージェントを優先する をONにします。このチェックは、接続先を設定し、設定の「外部エージェントを使う」がONのときだけ表示されます。
  2. いつもどおり投稿します。その担当に届いた投稿は、外部エージェントが調べて回答を書きます。記憶・予定は kakeratta が決めます。返事は担当の名前で「外部エージェント」の印付きで届きます。

外部エージェントが3分以内に依頼を取りに来ない、または取ってから15分以内に回答を返さないときは、内蔵モデルが代わりに答えます。

最後の接続から 取得を待つ時間（既定は3分）が過ぎても接続がなければ、外部エージェントは不在とみなされます。不在のあいだは、以後の依頼を待たずに内蔵モデルが答えます。再び接続されると、次の依頼から外部エージェントに戻ります。依頼に取り組んでいる最中は不在になりません。

待ち時間は 外部連携 の接続先ごとの 接続情報と待ち時間 で、エージェントごとに変えられます。同じ画面の 外部エージェントを使う をOFFにすると、外部エージェントからの接続を受け付けず、担当ごとの設定を残したまま内蔵モデルで考えます。返し方を直す ときの試し書きは、常に内蔵モデルで行います。

外部エージェントが読めるもの

外部エージェントは、あなたの投稿と すべての担当のメモ を読めます。担当への依頼では回答を提出し、記憶と予定は kakeratta が管理します。また、外部エージェントを優先する有効な担当として、自発的にタイムラインへ投稿できます（担当ごとに1日5件まで）。この投稿だけで担当の記憶が更新されたり、通知が送られたりすることはありません。モデル設定や他の利用者のデータには触れません。接続先を削除すると接続キーが無効になります。

外部エージェントが読んだ投稿やメモは、そのエージェントが使うモデルにも渡ります。Hermes や LLM Hub で外部の API のモデルを選んでいれば、その提供元に送られます。端末の外に出したくない場合は、ローカルのモデルを使ってください。ただし LLM Connect Hub で Vault・RAG・スキルを使って答えるには、API のモデルが必要です。

つながらないとき

  • 設定を変えたあと Hermes を再起動したか確認してください。
  • Hermes から接続URLに届くか確認してください。
  • キーを再発行したら、config.yaml も置き換えてください。NemoClaw の管理 MCP では、kakeratta-mcp.env を更新したうえで nemohermes <sandbox> mcp remove kakeratta で古い登録を削除し、setup-hermes.sh を再実行してください。
  • WSL2 でサンドボックス作成やポート確保が止まる場合は、.wslconfig で networkingMode=nat に設定して wsl --shutdown してからやり直してください。
  • LLM Connect Hub では、設定画面の接続状態（例: Kakeratta: connected; 1 ask failed）を見てください。回答が失敗した依頼は内蔵モデルが答えます。

Google Bridgeは、自分の端末・サーバーで動かす個人用Webアプリ兼MCPサーバーです。Googleの資格情報はBridgeへ暗号化保存し、HermesはMCPで読み取ります。Hermes側workerが候補を取得し、LLMで選別・要約した結果をコードでTimelineの取り込み待ちへ届け、本人が「取り込む」を選んだ内容だけを通常投稿・担当・記憶の処理へ渡します。

1. Google Bridgeを起動する

Go 1.26以降と、このリポジトリが必要です。Hermesは上の手順でkakerattaへ接続しておきます。リポジトリのルートで次を実行します。Bridgeの画面はGoに埋め込まれているのでnpmは不要です。

mise exec -- go run ./tools/google-bridge/cmd/google-bridge -init
mise exec -- go run ./tools/google-bridge/cmd/google-bridge

http://127.0.0.1:8094 を開き、初期化時に表示されたパスの設定ファイルを自分のエディターで開いて、adminTokenをログイン欄へ入力します。管理キーをHermesやチャットへ貼り付けないでください。

2. 自分のGoogleアカウントを接続する

  1. BridgeのGoogleを接続でセットアップ案内を開き、自分のGoogle Cloudプロジェクトを指定します。表示されたCLI手順またはConsoleリンクでGmail APIとGoogle Calendar APIを有効にします。案内はコマンドを自動実行しません。
  2. Google Auth Platformで同意画面を設定し、Testingなら自分をテストユーザーへ追加します。Web applicationのOAuthクライアントを作り、Bridgeに表示されたリダイレクトURIを完全一致で登録します。既定はhttp://127.0.0.1:8094/api/google/callbackです。
  3. Web用OAuth JSONをBridgeの専用フォームで読み込むか、project ID・client ID・client secretを入力します。読み取りだけなら送信・下書き・予定変更の追加権限を外します。
  4. GoogleデータがHermesと設定したモデルへ渡ることを確認し、同意してGoogleに接続を押します。同じタブで認可を完了し、Gmail・Calendarの接続状態と接続テストを確認します。

3. HermesとTimelineを接続する

BridgeのHermesとつなぐから設定例を~/.hermes/config.yamlのmcp_serversへ追加し、Hermesを再起動します。同じ端末のローカル接続モードではキーなしの設定例が使えます。個別MCPキーを発行した場合は表示されたAuthorization設定も追加します。管理キーとは別のキーです。

mcp_servers:
  google_bridge:
    url: http://127.0.0.1:8094/mcp
    tools:
      prompts: false
      resources: false

kakerattaの外部エージェント接続で発行した本人のMCP URL・キーは、上のHermes連携手順でmcp_servers.kakerattaへ設定します。取り込みworkerは下のgoogle_bridge.jsonと親Hermesのkakeratta接続を使います。上のgoogle_bridge設定は対話読み取り・直接依頼用です。Bridgeへkakerattaの接続先やキーを入力する手順はありません。以前のBridgeに保存していた投稿先の資格情報は更新後の起動時に削除します。Hermesが別端末・コンテナの場合、127.0.0.1はHermes自身を指すので、到達できる同一originの転送やHTTPS構成が必要です。

@agentの直接依頼workerでも使う場合は、同じ設定ファイルの既存のkakeratta_worker.mcp_serversへgoogle_bridgeを追加します。他の設定・接続先を残して追記してください。

kakeratta_worker:
  mcp_servers: [google_bridge]

4. 同期して取り込むものを選ぶ

  1. 重要メールの確認で取り込みが有効か確認します。停止中ならおすすめ設定で有効にするを押し、今すぐ差分を取得します。フィルターでは対象・優先ラベル、送信元、除外、任意のLLM判定を調整できます。
  2. 今日・明日の予定を取り込むも有効か確認し、詳細設定で対象カレンダーとタイムゾーンを確認して、今日・明日の予定を今すぐ確認を押します。既定はprimary・Asia/Tokyoです。
  3. LLM判定が有効な場合はHermesによる判定完了を待ちます。Timelineの待機カードで内容を確認（予定は予定を確認）を開いて取り込む／取り込まないを選ぶか、カードの取り込まないでその場で破棄します。確認画面での破棄時にはメールの種類・From、単発予定・定期予定全体の除外も選べ、Hermes側workerのコードが実際のレシートを取得しBridgeへ戻すと反映されます。

5. 定期実行と直接依頼

定期同期は既存のHermes cronを使います。リポジトリのtools/google-bridge/hermes/にあるcheck_google_bridge.py・check_calendar_bridge.py・google_bridge_worker.pyを自分のHermesのscriptsへ置きます。先にkakeratta連携を導入し、既存のdirect_request_worker.pyも配置されていることを確認します。BridgeのMCPキー発行時に表示されるJSONを同じ場所のgoogle_bridge.jsonへ保存して権限を0600にします。メールは30分ごと、予定は日次などで登録します。cronは--no-agent付きでgateを実行します。gateは必要なときだけworkerを起動します。配送・レシート返却はコードで行い、LLMは選別・要約が必要なときだけ隔離セッションで動きます。具体的な登録コマンドは設定・運用・復旧ガイドを参照してください。

送信・返信・下書き保存・予定の作成／変更／削除は、追加権限を付け、@agentで自分のHermesへ明示的に直接依頼する別の機能です。google_action_runはWebでの再確認なしに実行します。本人の依頼であることはサーバーで検証できないため、判定ジョブから書き込みツールを除外してください。結果が不明なら再送せずGoogle上で確認します。

Google側の予定変更は既存カード・投稿へ自動反映されません。再認証が必要なら同じGoogleアカウントで接続し直し、URI不一致ならGoogle側の登録値を確認してください。Google OAuthと実Hermes接続を含むGmail・Calendarの実環境連携は検証済みです。自分の環境でまずメール検索と予定読み取りを確認してください。

Blueskyに公開する

自分の投稿と担当との会話から、見せたい発言だけを選んで、自分の Bluesky アカウントから投稿できます。担当の発言には「🍚 tabeからの返信:」のような署名が付きます。

アカウントをつなぐ

  1. 設定 → 外部連携 → Bluesky連携、または投稿の Blueskyに投稿 を開きます。
  2. 自分のハンドル（例：alice.bsky.social）を入れて Blueskyと接続 を押します。
  3. Bluesky の画面で許可すると、同じタブで kakeratta に戻ります。パスワードは Bluesky 側にだけ入力します。

会話を選んで公開する

  1. 元の投稿の Blueskyに投稿 を押します。最初は元の投稿だけが選ばれています。
  2. 元の投稿のチェックを外して、回答だけ公開することもできます。1件以上選んでください。返信先を選ばなかった発言は、選択した最初の発言への返信として公開します。
  3. 発言ごとに テキスト か 画像 を選びます。公開内容が同じ画面に自動で表示されるので、確認して 投稿 を押します。切り替え中や画像の変換中は投稿できません。

公開されるもの・されないもの

  • 公開されるのは、選んだ発言の本文・リンク・出典URL・画像です。位置情報、画像の読み取り結果、担当のメモは公開されません。
  • 長い発言は、文の切れ目で300文字程度ずつに分け、2つ目以降に「つづき:」を付けます。画像は最初の1つにだけ付きます。
  • 担当の回答の見出し・箇条書き・表は、Blueskyで読みやすい文章に直して公開します（Blueskyには太字や見出しがないため）。[文字](URL) のリンクは文字がそのままリンクになり、本文中のURLもリンクになります。
  • 担当のHTML回答とインフォグラフィックの図解は、最初は画像が選ばれています。テキストに切り替えることも、通常の文章を画像にすることもできます。縦長の回答は複数枚に分けるので、プレビューですべて確認してください。変換できない場合は投稿を止めます。元の回答はそのまま残ります。
  • 2 MB を超える画像は送信用に縮小されます（元の画像はそのまま）。透明部分は白に、GIF は静止画になります。
  • 一度に選べるのは100発言までです。

あとから足す・やめる

  • 公開済みの発言は再送されません。あとで選んだ返信だけを追加で投稿できます。
  • 通信が切れて結果が分からないときは、二重投稿を防ぐために止まります。Bluesky 側で確かめてください。
  • 接続を解除 でつながりを外せます。解除しても、kakeratta で投稿を消しても、Bluesky の投稿は消えません。

10. モデルや料金を確認する

どの処理にどのモデルを使うか、接続先の切り替え、月ごとの利用金額の見方と、費用の目安を説明します。

AI のモデル

Nebius Token Factory では、用途ごとに次のモデルを使います。設定画面で選ぶ必要はありません。

用途モデル

深い回答が必要な依頼の最終回答Nemotron Ultra

画像の読み取りGLM-5.3-Flash

常に熟考する がオンの担当は、通常の依頼でも最終回答を Super VL で生成します。「詳しく」「ちゃんと調べて」などの言葉を含む依頼は、最終回答を Ultra で生成します。お礼やふつうの追加質問は、常に熟考がオフなら通常のモデルのままです。

調べものにはふだん Super、「詳しく」などの深い依頼と常に熟考する担当では Super VL、予定の計画には Super VL を使います。1 回の回答で調べられる回数（読む・Web検索する）には上限があり、深い回答が必要な依頼や「常に熟考する」の担当では上限が広がります。設定されていない道具や、記憶を持たない担当の記憶検索は使いません。

Embedding は、投稿や回答を検索の索引に加えるときと、意味で検索するたびに使います。単価が低く、金額のほとんどは Nemotron の呼び出しです。

@ai が使うモデル

@ai への質問は、ふだん Nemotron 3.5 Super VL で調べて答え、「詳しく」などの言葉があると Ultra で答えます。担当ごとの「常に熟考する」の設定には左右されません。金額は AI利用状況の「@ai」の行に入ります。

OpenRouter を使う

設定 → モデル → OpenRouterを使う で API キーを入れて接続確認します。

  • OpenRouterを使う にチェックすると、Router・High・Middle・Low・画像解析に OpenRouter を使います。チェックを外してもAPIキーとモデル選択は残るので、切り替えて比較できます。
  • 接続確認後、画像解析モデル で画像入力に対応したモデルを検索・選択できます。未設定時は従来どおり GLM-5.3-Flash を使います。選択は OpenRouter をオフにしても保持します。
  • 振り分けに Jev を使うには、Routerモデル で ~typesafe/jev-latest を選択します。Jev は判定理由を表示しません。
  • OpenRouter で選べるのは Router・High・Middle・Low・画像解析の枠で、各枠に任意のモデルを指定できます。意味検索の Embedding は切り替わらず、OpenRouter を使うときも Nebius の API キーで Qwen3-Embedding-8B を使います。

月ごとのAI利用状況

設定 → AI利用状況 を開くと、月の合計金額とWeb検索回数が見られます。集計月 で月を選び、最新の記録を見るときは 更新 を押します。内訳は 振り分け・担当合計・@ai・その他 です。「@ai」の行は、@ai に直接した質問の分です。担当が内蔵モデルで答えた分は「担当合計」に入ります。「その他」には意味検索のEmbeddingや日まとめ・月まとめなどの共通処理を含みます。

担当別に見るには、担当 を開き、各カードの AI利用状況 を開きます。返答・定期実行・その他 に分かれ、返答や定期実行に伴う調査・記憶更新・再試行も含みます。定期実行はチェックインとリマインダーです。振り分けなどの共通費用は担当別の金額には含めません。

金額は米ドルの概算です。OpenRouterはAPIが返した料金、Nebiusは記録時の公開単価を使い、Nebiusの割引・無料枠は反映しません。料金が分からない呼び出しは 未算出 と表示します。Web検索は失敗を含む実際のAPIリクエスト数で、検索料金や外部エージェント側のAI料金は含みません。記録開始後の利用だけが対象で、過去のログは取り込みません。記録がない月には、その旨を表示します。

費用が増える処理

  • 深い回答：「詳しく」「ちゃんと調べて」などの依頼は、Super VL で何度も調べて Ultra で答えます。常に熟考する 担当は、「詳しく」がなくても Super VL で調べて答えます。どちらも通常の数倍かかります。
  • 複数の担当：1つの投稿が複数の担当に届くと、担当ごとに回答と記録の処理が走ります。有効な担当が多いほど、振り分けの入力も長くなります。
  • Web検索：検索結果がモデルへの入力に加わります。Tavily の検索料金は別で、AI利用状況の金額には含みません（回数だけ表示します）。
  • 記憶と履歴の量：担当は毎回、今の事実と最近の記録を読むので、記憶が育つほど1回の入力が増えます。
  • 定期処理：毎日のチェックイン、今日のまとめ・今月のまとめ、予定による起床は、投稿とは別に動きます。

12. 困ったとき・もっと詳しく

反応が付きません。
担当が誰も有効でないか、どの担当の分野にも当たらなかったか、担当が「覚えるだけ」にしたのかもしれません。⚖ で誰に届いたかを確認できます。必ず答えてほしいときは @名前 で指名してください。
設定画面が閉じられません。
AI の接続が済むまでは閉じられません。API キーを入力してください。
検索で「語句の一致で探しました」と出ます。
意味で探す準備が終わっていないか、接続できない状態です。語句で見つかった結果は表示されています。少し待ってから検索し直してください。
画像の文字が読めていません。
読み取りには少し時間がかかります。しばらくして投稿の「読み取り結果」を開いてください。画像は1投稿あたり 20 MiB までです。
Push通知が届きません。
受け取りたい端末ごとに 設定 → この端末 → リマインダーのpush通知 で Push通知 のスイッチをONにします。iPhone・iPad はホーム画面に追加して、そこから開いてください。ブラウザの通知許可、ログイン状態、予定ごとの通知設定も確かめてください（リマインダーのPush通知）。
通知をOFFにしたのに、予定の投稿が届きます。
OFFで止まるのはPush通知だけで、予定は実行されタイムラインに投稿されます。予定そのものを止めるには × で取り消してください（予定・通知を管理する）。
入力欄の @ 候補に「外部エージェント」が出ません。
外部連携が有効で、接続先があるときだけ出ます。「内蔵AI」（@ai）はいつでも選べます（宛先の使い分け、外部AIやサービスとつなぐ）。
外部エージェントに任せた担当なのに、内蔵モデルが答えました。
外部エージェントが時間内に依頼を取りに来ない、または回答を返さないと、内蔵モデルが代わりに答えます。接続先の状態と待ち時間を確かめてください（つながらないとき）。
忘れさせたことを、担当がまた覚えています。

Using kakeratta

kakeratta is a notebook with a personal AI that remembers, and reminds you when it matters.

Toss text, photos, URLs and voice into one timeline. Getting no reply from the AI is normal: every post stays, and you can search it or read it back later.

Personas, one for each person or interest you choose, each keep a memory of their own and react when something concerns them. You can check and correct what they remember and how posts were routed.

This manual covers everything from daily use to tuning personas and connecting external agents.

1. Get started

  1. Open the app. Sign in with your Google account. After approval, “Completing sign-in…” stays visible until the app opens automatically. Your data is tied to your account and nobody else can see it.
  2. Open Settings at the top right and enter an API key from Nebius Token Factory. “Connected” means you are ready.
  3. New accounts start with two personas active: sona and the infographic persona.
  4. Write a line in the box and press Post. That is your first fragment.

The API key is stored only on the server and sent only to the configured endpoint.

Using it offline

On a device that has opened the app online once, you can write text, images, URLs and replies without a connection. They wait as “Saved on this device · waiting to send” and go out automatically when the connection returns while the app is open. Personas react once the server has them.

  • After an error, Reconnect and retry sends again. Nothing is posted twice.
  • Clearing browser data loses posts still waiting. Signing out asks first, then clears this device's saved data.
  • The latest 20 conversations are also kept on the device, so the app opens with them straight away.

A persona can also keep one person in mind - your mother, a friend. In Personas, select the People tab and choose Create a persona with AI.   • A person's persona remembers what happens with them (talks, gifts, promises, loans) and nudges you when meetings or birthdays approach (see notification schedule rules in the detailed explanation).
  • Supplied details like birthdays and preferences can be reviewed and edited anytime directly in the persona settings.

If a fragment did not reach them, add keywords from Should have been called in ⚖; if an unrelated one did, remove the matched word from Should not have been called (Fix a person's keywords). More keywords are not always better: vague words bring in unrelated fragments, so adjust while watching the actual routing.

Edit a persona

Use Edit with AI on a persona to say “Give shorter replies” or “Remember why I liked a wine, too.” Built-in personas can be edited the same way, and their notes carry over.

As you keep posting, a persona's memory may fill up with a different subject. The persona may then suggest at a daily check-in: “Shall we make a new persona for …?”

  • Press Create it under the post to create the persona, move the related memory over, and narrow the original persona's condition, all in one step. From then on that subject reaches the new persona alone.
  • Press Not now to pass. The persona and its memory stay as they are.
  • If something fails along the way, everything is put back and you can press Create it again.

Only subject personas with memory on make suggestions, at most once every 30 days each. A persona created this way can be edited like any other. For details, see Details: Memory upkeep and persona suggestions.

5. Inspect and correct memory

Open What I remember on a persona to read its memory anytime, and edit or forget notes by hand. Nothing is learned or hidden behind your back.

What you can do

  • Read: Each persona keeps one memory, shown as current facts and fragment records under “Facts and records”.
  • Trace: Tap Original post on any note to open the conversation or image that produced it. Tap a #tag to filter by topic.
  • Edit: If a fact has a typo or misinterprets something, tap ✎ to correct it directly.
  • Forget: Remove unwanted notes with × or Forget this note. You are asked to confirm deletion. There is no separate button to clear all memory. Deleting an original fragment also removes notes that rested solely on it.
  • Lifespan and review: Ephemeral notes expire automatically (Gone on), and older notes are surfaced at check-in with “Can I forget this now?” (Review on). Choose Yes to delete the record, Keep it a while longer to postpone review, or Don't forget it to stop future reviews. Your choice is shown after answering. You can also reply in words.

Details Memory upkeep and persona suggestions

A persona's memory grows a little with each conversation and is reorganized at check-ins. How to check and correct it on screen is in What a persona remembers; this section explains how memory is tidied and how a new persona is suggested from it.

Fragment records and current facts

  • Fragment records: for each fragment received, one line with the date and time, original post, summary and tags. Greetings and general questions alone are not recorded. That is all a conversation adds.
  • Current facts: one line per fact known, including grounded tendencies, conditions, exceptions and changes over time. At check-in (daily, or monthly for people set to monthly), new records are folded into facts (added, rewritten, deleted or merged) and the folded records go. Facts that no longer hold, and bookings whose date has passed, are deleted.

A fact is up to 200 characters, and all facts together up to 4,000. Each turn a persona reads its current facts and recent records first, and searches older records by tag, words and meaning (records).

Lifespan and review

  • Gone on …: set on records that served their moment, such as “today's lunch”; they are deleted on that day.
  • Review on …: set from the content on records of what you said. Once the day passes, the persona asks at a daily check-in: “Can I forget this now?”
  • When asked, choose Yes to delete the record, Keep it a while longer to postpone, or Don't forget it to stop future reviews. A reply in words is handled the same way.
  • When a persona reads a record again to answer you, its dates move forward from that day.
  • When a record goes, facts that rested on it alone go too.

New persona suggestions

What happens: memory is not split by subject. When a subject outside a persona's domain, or one plainly of its own, builds up, the persona suggests at a daily check-in: “Shall we make a new persona for …?” If the persona stays silent, the app posts the same suggestion.

How to use it: choose Create it or Not now under the post.

  • Create it: a persona with a name, icon, condition and tone drafted for the subject is added right away, with memory on and enabled. The related facts and records move to its memory word for word, and it reads the moved records as new at its next check-in.
  • The original persona's condition gains a sentence leaving the subject out. From then on posts on the subject reach the new persona alone.
  • Not now: recorded as passed; the persona and its memory stay as they are.

Notes:

  • Only subject personas with memory on make suggestions, at most once every 30 days each. Person personas do not.
  • Adding the persona, narrowing the condition, moving memory and enabling it are committed only when all succeed. If a step fails, the steps already done are undone and the post keeps its Create it button. A failure while moving memory never leaves it in neither persona.
  • Pressing twice never creates two personas.

The new persona and the original's condition can be adjusted like any other, with Edit or Fix a persona's condition.

6. Fix routing and replies

The app decides which personas get each fragment. Tap ⚖ on one of your posts or replies to see who was called and, for each one that was not, a one-line reason. A persona you mentioned with @name is not listed: that was your call.

7. Manage schedules and notifications

Personas keep birthdays, meetings and checks before you head out as schedules, and post to the timeline when the time comes. You can view, edit and cancel schedules in one list.

Turning notifications off does not stop a schedule. Off stops only the Push notification; the persona still wakes on time and posts to the timeline. To stop a schedule, cancel it with ×.

Where schedules come from

  • Person personas register birthdays, anniversaries and meetings with a known date from their basic information and from fragments.
  • Personas with the schedule tool (such as sona) pick their own wake time when a post or habit makes the time clear.
  • Each persona holds up to 20 schedules. Pausing or deleting a persona removes its schedules.

Hearing from your personas

Personas with Remember enabled keep memories and speak now and then when they have something useful or timely to share, such as sona's doorstep reminder before heading out. How much they say and their tone follow their character. Turning off Remember stops periodic check-ins; explicit schedules still run. Check-in timings and monthly summary mechanics are in the detailed explanation.

View and edit all schedules

Open Schedules in the header (the calendar icon on phones) to see all personas' schedules ordered by next run. Search by persona name or schedule text. Use the pencil button to open the Edit time and notifications dialog, change the next run and/or Push notifications, then save. The date/time input uses the device timezone shown below it.

The same controls are available on each persona card and at the top of its Remarks list. Turning Push off keeps the task and its timeline post. You can also ask a persona to turn notifications off for a schedule. Use × to cancel the schedule itself.

Daily repeats keep the edited time in the schedule's timezone. Annual reminders keep the time too, but date changes apply only to the next occurrence. Edits may be too late for an occurrence already running. A failed save retains your input for retry.

Push reminders

  1. On iPhone/iPad, add kakeratta to the Home Screen and open it there. If you dismissed the top banner on a phone with Later, you can also review the steps anytime under Settings → This device.
  2. Open Settings → This device → Push reminders, turn on the Push notifications switch, and allow browser notifications. Enable them on each device where you want reminders.
  3. Birthday and scheduled reminders, as well as replies to direct @agent requests when 🔔 is on, can arrive while the browser is closed. Open a notification to view its post. Turn off the Push notifications switch in the same place to stop delivery to that device.

Notifications show up to 300 characters of text, with an ellipsis when shortened. Lock-screen visibility follows your device settings. Ordinary replies, check-ins and monthly summaries do not trigger Push. HTTPS and a supported browser are required. The timeline post remains available if delivery fails.

If notifications do not arrive, check device enablement, browser permission, login status, and the schedule's notification setting. A message saying Push is not configured on the server requires operator setup.

Mark done

Scheduled reminders offer Mark done. Tap it to show ✓ Done, or tap again to remove the mark. Personas can see the mark when reading the conversation. This requires an online connection.

For a persona that prefers the external agent, the external agent writes what to say at check-in (what to ask or tell you). How the memory is tidied is still decided by kakeratta, as always. If the agent does not respond in time, the built-in model writes it instead.

This month's summary, and people looked back on monthly

Once a month, the app reads that month's timeline and posts This month's summary to the timeline. It groups your statements, actions, decisions, and changes by topic. A persona’s suggestion alone is not treated as something you did or planned. Each bullet's → opens the original fragment. The app picks the date per account (somewhere between the 1st and the 28th of each month). The summary is yours to edit with ✎.

On a person's card you can choose Look back frequently or Look back occasionally. A person set to monthly wakes on the day the summary is posted, reading the summary and the fragments where their name or keywords appeared. Even as you add more people, the timeline is read only once a month. When you create personas with the AI, the frequency is chosen from the relationship: daily for family and close friends, monthly for people you meet once in a while. An interest persona is always daily.

Person persona notification rules

From saved or edited basic info and from fragments that reach that person, birthdays, anniversaries, and meetings with clear dates are registered automatically.

  • Birthdays and anniversaries: Reminded every year, 1 week before and on the day at 9:00 AM.
  • Meetings: Any specified reminder time takes precedence; otherwise reminded on the day at 9:00 AM (or 1 hour before if the meeting is earlier than 9:00 AM).
  • Reminders arrive as remarks posted by the persona. There is no day limit on future schedules, and unclear dates are never guessed. Schedule edits and cancellations are reflected too.

A persona's own schedule (schedule)

A persona can wake shortly before an outing whose timing is grounded in your posts or habits, checking belongings and past omissions. When the region and date are known, it reads a fresh forecast: sunshine now can still mean taking an umbrella for rain on the way home. Unknown locations, times and unavailable forecasts are not invented. Chore follow-ups happen shortly afterwards; completed or already-mentioned items stay quiet. It does not nag or recite a generic checklist every day.

A person's persona sets one for the morning of a meeting you mention, such as “drinks with Sato next Saturday.” On waking it brings up what happened last time and anything still open, like a loan or a promise.

  • Up to 20 per persona, at any future date. Tool-created schedules run once or daily; birthdays and anniversaries recur annually.
  • Schedules are listed on the persona's card. Remove one you do not want with ×.
  • A wake is used up even if the persona stays silent or fails. One more than 10 minutes late is skipped.
  • Deleting a fragment makes the persona revisit the schedules it set for it. Pausing or deleting the persona removes its schedules.

Connect Obsidian (LLM Connect Hub)

With LLM Connect Hub, a persona's answer comes from LLM Hub in your Obsidian. It uses the model you choose in LLM Hub and researches your Vault notes, RAG and skills; the vault files it read are cited as [[file name]].

  1. Install and enable LLM Hub and LLM Connect Hub from Obsidian's community plugins (desktop only).

LLM Connect Hub checks for asks once a minute while Obsidian is open, and uses no model tokens when there are none. Because it checks once a minute, keep Wait for a claim (how long kakeratta waits for the agent to pick up an ask) longer than a minute. Hand a persona over

  1. In Personas, turn on Prefer the external agent for the persona. The checkbox appears only while a connection is configured and Use the external agent is enabled in settings.
  2. Post as usual. For posts that reach that persona, the external agent researches and writes the answer; kakeratta decides memory and schedules. The reply arrives under the persona's name, marked External agent.

If the external agent does not pick an ask up within 3 minutes, or does not return an answer within 15 minutes of picking it up, the built-in model answers instead.

If the agent has not connected for longer than Wait for a claim (3 minutes by default), it is taken to be away. While it is away, later asks go straight to the built-in model instead of waiting. As soon as it connects again, the next ask goes to it. An agent is never away while it is working on an ask.

An external agent can read your posts and the notes of every persona. For persona asks it submits an answer, while kakeratta manages memory and schedules. Profile (display name and icon)

Profile at the top of Settings changes the Display name and Icon shown for you on the timeline and elsewhere. Pick an emoji from the groups or choose a photo, the same way as for persona icons. It is saved with your account, so other devices show the same. An empty name shows as “You” and an empty icon as 🙂. Your sign-in account name does not change.

Backup

Export as zip puts your posts, personas and their notes, persona order, and images into one zip. The download starts when it is ready, and a Download link also appears. The link is valid for an hour. The zip holds personal content, so keep it to yourself.

API keys and the Bluesky and external agent connections are not included.

Close account

Press Delete everything and close the account and type “delete” to confirm. This removes the account's posts, personas and notes, images, settings, connections, backups, and the login account itself. It cannot be undone, so export a backup first.

12. Troubleshooting and further reading

Nothing reacts to my post.
Perhaps no persona is enabled, the post matched no persona's subject, or a persona chose to remember without speaking. ⚖ shows who got the post. Mention @name when you need an answer.
I cannot close Settings.
Settings stays open until the AI connection works. Enter an API key.
Search says it only matched words.
Meaning search is still preparing or cannot connect. Word matches are still shown. Try again in a moment.
The text in my image has not been read.
Reading takes a moment. Open “Reading result” under the post a little later. Images are limited to 20 MiB per post.
Push notifications do not arrive.
Turn on the Push notifications switch on each device under Settings → This device → Push reminders. On iPhone and iPad, add kakeratta to the Home Screen and open it from there. Also check browser permission, that you are signed in, and the schedule's notification setting (Push reminders).
I turned notifications off, but scheduled posts still arrive.
Off stops only the Push notification; the schedule still runs and posts to the timeline. To stop the schedule itself, cancel it with × (Manage schedules and notifications).
The @ suggestions do not offer External agent.
It appears only when external integration is enabled and a connection exists. Built-in AI (@ai) is always offered (Choosing who you address, Connect other AI and services).
A persona set to prefer the external agent was answered by the built-in model.
When the external agent does not pick up the request or return an answer in time, the built-in model answers instead. Check the connection and its wait times (If it cannot connect).
A persona remembers something I made it forget.
It may learn it again by searching posts that remain. Delete the original post too, or tell it how to remember with Edit with AI (Check or fix memory, Fix what a persona remembers).
A persona asks whether to make a new persona.
It suggests this when another subject has built up in its memory. Choose Create it or Not now under the post (New personas from memory).
AI costs are higher than I expected.
Settings → AI usage and each persona's AI usage show the breakdown. “In detail” requests, Always think deeply, Web search and many active personas raise it (Monthly AI usage, What raises the cost).
Where is my data stored?
On the server, separated per account; nobody else can see it. To keep a copy yourself, see Settings and data.
